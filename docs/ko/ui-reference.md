# HAM 메일함과 팝업 UI 참고서

한국어 · [English](../ui-reference.md) · [README](../../README.ko.md)

## 메일함 열기

명령 팔레트에서 다음 세 동작을 사용할 수 있습니다.

- **HAM: Mailbox (Right Split)** (`herdr.agent-messenger.mailbox-split`)은
  현재 pane 오른쪽에 플러그인 소유 pane을 엽니다.
- **HAM: Mailbox (Tab)** (`herdr.agent-messenger.mailbox-tab`)은 같은 화면을 탭으로 엽니다.
- **HAM: Mailbox (quick send)** (`herdr.agent-messenger.mailbox-popup`)는
  전송 성공 결과가 오면 닫히는 팝업을 엽니다. 전송이 실패하면 입력창을 유지합니다.

일반 셸에서도 열 수 있으며, 연 pane에 에이전트가 없어도 됩니다. 이 동작은
키 바인딩을 바꾸거나 runtime을 설치하지 않습니다. 오른쪽 분할 동작을
`prefix+m`에 연결하면, workspace에 등록된 메일함이 현재 탭에 있을 때만
그 메일함으로 이동합니다. 다른 탭에 있으면 현재 pane 오른쪽에 새 메일함을
열고 등록을 교체합니다. 이전 메일함은 화면 첫 줄에 `NAV ·`가 있을 때만
닫습니다. 초안 작성, 확인, 선택 중이거나 화면을 읽을 수 없으면 그대로 둡니다.
탭 동작은 기존처럼 어느 탭에 있든 workspace에 등록된 메일함으로 이동합니다.
기존 메일함은 표시 이름이 아니라 pane/terminal ID로 확인합니다.
`q`는 플러그인이 소유한 메일함 pane이나 팝업만 닫습니다. 내용이 있는 초안은
폐기 확인을 거치며 기본 선택은 Cancel입니다. 최상위에서 `Esc`는 팝업만 닫고,
분할·탭에서는 아무 동작도 하지 않습니다. 입력창이나 겹쳐 열린 화면에서는 빠져나옵니다.

### 화면 크기에 따른 영역 배치와 탐색

본문은 **Agents**, **Threads**, **Detail**로 구성됩니다. 공간이 충분하면
Detail은 항상 목록 아래에 표시하며, 오른쪽의 세 번째 열로 배치하지 않습니다.

- **Stacked, 좌우 배치:** 너비가 80열 이상이고 사용 가능한 본문이 18행 이상일 때,
  각 절반에 Agents의 모든 열을 표시할 수 있어야 두 목록을 나란히 배치합니다.
  TURN, ALIAS, MAIL, RX, ROLE, PHN, EMU, SRV와 최소 16칸의 PHASE · SUMMARY,
  열 사이 간격과 테두리를 기준으로 필요한 너비를 계산합니다.
  별칭과 역할의 현재 너비에 따라 기준이 달라집니다. 예를 들어 별칭이 15칸이고
  ROLE이 최소 너비인 4칸이면 터미널 너비가 158열 이상이어야 합니다.
- **Tabbed:** 좌우 배치에 필요한 너비보다 좁으면 위쪽 목록을 전체 너비로 표시합니다.
  위쪽 테두리의 `Agents │ Threads`에서 활성 탭은 강조색과 굵은 글씨로,
  비활성 탭은 흐리게 표시합니다. 탭 이름을 클릭하면 해당 목록으로 전환합니다.
  Detail은 아래에 전체 너비로 유지합니다. 별칭이나 역할이 길면 여유 너비부터
  줄여서 전체 너비의 Agents 목록에 기기·서버 열을 유지합니다.
- Detail의 테두리를 포함한 높이는 `round(사용 가능한 본문 높이 * 0.4)`입니다.
  최소 9행으로 맞춰 내용 6행과 안내 1행, 테두리를 확보하고, 목록에도
  테두리와 탭 표시줄을 포함해 최소 8행을 남깁니다. 전체 내용은 스크롤할 수 있습니다.
- 사용 가능한 본문 높이는 전역 헤더, 하단 키 안내, 상태 표시줄과 INPUT을
  제외한 높이입니다. INPUT은 Detail 아래에 전체 너비로 표시합니다.
  입력창을 열거나 높이가 늘어나면 단일 영역 모드로 바뀔 수 있습니다.
- **Single:** 너비가 80열 미만이거나 사용 가능한 본문이 18행 미만이면
  포커스가 있는 영역만 본문에 표시합니다. 위쪽 테두리에는 목록 탭을 유지합니다.
  기존 순서인 `Agents → Threads → Detail → Agents`로 포커스를 옮기면
  Detail이 목록을 대신하며, 테두리에는 탭과 Detail 이름을 함께 표시합니다.
  탭을 클릭하면 해당 목록으로 돌아갑니다. INPUT은 아래에 별도 패널로 유지합니다.
- 모든 배치에서 `Tab`·`Shift+Tab`, `←`·`→`, `h`·`l`로 같은 순서대로
  포커스를 옮깁니다. 목록 포커스에 맞춰 활성 탭도 바뀝니다. Detail에서는
  마지막으로 선택한 목록의 탭을 유지하며, 각 목록의 선택과 스크롤은 따로 보존합니다.
- **Tiny:** 너비가 32열 미만이거나 터미널 높이가 10행 미만이면 본문 대신
  크기 변경 안내를 표시합니다. 초안, 선택 항목, 커서와 모드는 유지합니다.

```text
Tabbed (두 목록을 나란히 표시할 너비가 부족할 때)
+-- Agents | Threads -------------------------------+
| 활성 목록                                         | 나머지 공간, 최소 8행
+---------------------------------------------------+
| Detail                                            | 약 40%, 최소 9행
+---------------------------------------------------+
| INPUT (열려 있을 때 표시, 본문 높이에서 제외)      |
+---------------------------------------------------+
```

INPUT과 상태 표시줄이 없으면 200×50 터미널의 사용 가능한 본문은 48행입니다.
좌우 목록은 29행, Detail은 19행을 사용합니다. 110×35에서는 활성 탭이 20행,
Detail이 13행을 사용합니다. 이 높이에는 테두리가 포함됩니다.

에이전트 Detail은 한 열 안에서 **Work**(턴 상태, 단계, 굵은 요약),
**Identity & role**, **Devices & servers**, **Mail**, 흐린 **Receiver/technical**
순서로 묶어서 표시합니다. 기기는 기술 ID보다 아이콘과 사람이 읽는 이름
(예: `📱 SM-A245N`)을 먼저 표시합니다. Mail에는 메시지 본문 대신 개수와
Threads·Space 읽기 안내를 표시합니다. 스레드 Detail의 메시지 이력과
선택적으로 펼치는 기술 정보는 유지합니다.

헤더는 현재 모드(`NAV`, `INPUT`, `CONFIRM`, `SETTINGS`, `HELP`, `EVIDENCE`)를,
**NAV**에서 Agents 또는 Threads 항목(DIRECT·OUTBOX 포함)을 선택하고 `Space`를
누르면 화면 중앙에 읽기 전용 Detail 뷰어가 열립니다. 화면의 약 90% 크기이며
최대 100×40칸입니다. `↑`·`↓`, `PgUp`·`PgDn`, `Home`·`End`와 휠로 스크롤하고
`t`로 Detail과 같은 기술 정보를 토글합니다. 최신 메시지 위치를 기준으로 열리며,
그 위치에 있을 때만 새 도착 메시지를 따라갑니다. 새로고침 중 항목이 사라지면
상태 메시지와 함께 닫힙니다. `Esc`, `q`, `Space` 또는 바깥 클릭으로 닫습니다.
안쪽 클릭과 `Enter`는 동작하지 않으며, 보기만 해서는 ACK하지 않습니다.
INPUT에서 Space는 문자로 입력되고, CONFIRM·Settings 선택 목록의 기존 Space
동작은 유지됩니다.
| --- | --- |
| `Space` | 선택한 Agents 또는 Threads 항목을 읽기 전용 뷰어로 엽니다. |
| `↑` / `↓`, `j` / `k` | 목록의 선택 항목을 옮깁니다. Detail에 포커스가 있으면 방향키로 스크롤합니다. |
| `PgUp` / `PgDn`, `Home` / `End` | 포커스가 있는 영역에서 페이지를 넘기거나 처음·끝으로 이동합니다. Detail은 실제로 보이는 본문 행 수를 기준으로 한 행씩 겹치게 페이지를 넘기며, Home/End는 첫 페이지와 마지막 페이지로 이동합니다. |
| `Enter` | Agents에서는 입력창을, Threads에서는 답장 입력창을 엽니다. Detail에서는 동작하지 않습니다. |
| `t` | Detail에서는 native 스레드·DIRECT·OUTBOX의 기술 정보를 펼치거나 접고 최신 native 메시지로 돌아갑니다. 단일 항목은 맨 위로 이동합니다. Threads에서는 기존 OUTBOX 재시도 확인창을 엽니다. 에이전트 상세·진단 화면에서는 토글하지 않으며 INPUT에서는 문자로 입력합니다. |
| `s` | Settings를 엽니다. |
| `?` | 문맥별 키와 전체 키 목록을 차례로 보여 주는 도움말을 엽니다. |
| `e` | 연결 오류와 대기 중인 작업 등 진단 정보를 Detail에 표시합니다. |
| `r` | 새로고침합니다. |
| `q` | 종료합니다. 내용이 있는 초안은 폐기 여부를 확인합니다. |
| `Esc` | 도움말·진단·겹쳐 열린 화면을 닫습니다. 최상위에서는 팝업일 때만 종료합니다. |

### 마우스

- 영역을 클릭하면 포커스를 옮기고, Agents나 Threads의 행을 클릭하면 해당 행을
  선택합니다. 이미 선택한 행을 클릭하면 `Enter`처럼 동작하여 Agents에서는
  입력창을, Threads에서는 답장 입력창을 엽니다.
- 휠은 포커스를 옮기지 않고 포인터 아래의 영역을 스크롤합니다.
- 입력창의 본문을 클릭하면 커서를 해당 위치로 옮깁니다.
- 대화상자의 버튼은 클릭할 수 있으며, 대화상자 바깥을 클릭하면 무시합니다.
  Settings에서는 행을 클릭하면 선택하고, 선택한 행을 클릭하면 `Enter`처럼
  동작합니다. 도움말은 아무 곳이나 클릭하면 닫힙니다.
- 마우스 처리는 기본으로 켜져 있습니다. 켜져 있을 때는 보통 `Shift`를 누른 채
  드래그하면 터미널 텍스트를 선택할 수 있습니다. `HAM_MAILBOX_NO_MOUSE=1`로
  마우스 처리를 끌 수 있습니다.

숫자는 탐색 키가 아닙니다. Agents는 에이전트마다 메타데이터를 둘째 줄에 표시하지
않고 **테두리 없이 열을 정렬한 한 줄 행**을 사용합니다. 열 사이는 **공백 두 칸**으로
띄우며, 패널 안에는 세로 경계나 가로 구분선을 그리지 않습니다. 열 이름은
**밑줄 없이 청록색 굵은 글씨**로 표시하고, 색상을 사용하지 않으면 굵게만 표시합니다.
각 호스트 구역은 `▾ winmini · 1 agent`, `▾ winmini · 2 agents`처럼 **굵은 호스트
이름과 에이전트 수**로 시작하며, 그 아래에 열 이름과 에이전트 행을 표시합니다.
에이전트가 없는 호스트에는 열 이름을 표시하지 않습니다. 작은 화면의 공간을
보존하기 위해 구역 사이에 빈 줄을 넣지 않습니다. 호스트와 열 이름은 마우스로
선택할 수 없으며 키보드 선택에서도 건너뜁니다. 스크롤할 때 선택한 에이전트를
계속 보여 주고, 공간이 허용되면 해당 호스트와 열 이름도 함께 유지합니다.
발견 사항은 0이 아니거나 알 수 없을 때만 뒤에 표시하며, 필요한 경우 stale·오류
정보도 표시합니다. 공간이 부족하면 개수를 유지하고 발견 사항부터 줄입니다.

TURN은 선택 표시와 상태 기호로 시작하며, 제목은 상태 단어 위에 맞춥니다.
ALIAS, ROLE, SUMMARY는 왼쪽에, MAIL, RX, PHN, EMU, SRV는 가운데에 정렬합니다.
개수를 알 수 없으면 `?`, 확인된 개수가 0이면 `·`를 표시합니다. 0은 선택하지 않은
행에서만 흐리게 표시하고, 0이 아닌 MAIL 개수는 굵게 표시합니다. 선택한 행은
**행 전체에 공통의 밝은 배경색과 대비가 높은 글자색**을 사용합니다. 열 사이 여백에도
같은 색을 적용하며 상태 기호와 단어는 굵게 표시합니다. 선택하지 않은 행의 상태에는
의미에 따른 색을 유지하고, 색상을 사용하지 않을 때는 선택한 행 전체를 반전합니다.

열에는 **상태 기호와 단어**, **별칭**, **MAIL**(읽지 않은 메일 수),
**RX**(native 수신기 표시: 준비됨 `✓`, 없음 `⚠`, 알 수 없음 `?`), **ROLE**,
리소스 개수와 남은 너비를 사용하는 **phase · summary**를 표시합니다. TURN,
ALIAS, MAIL은 항상 표시합니다. RX를 먼저 추가하고, 내용 너비를 16칸 이상
확보할 수 있으면 SUMMARY를 추가한 뒤 ROLE, PHN/EMU/SRV 순으로 추가합니다.
열을 추가할 때 SUMMARY는 최소 16칸, SUMMARY가 없으면 ALIAS는 최소 8칸을
유지합니다. ALIAS의 기본 너비는 가장 긴 별칭에 맞추되 8~18칸으로, ROLE은 가장
긴 역할에 맞추되 4~8칸으로 제한합니다. SUMMARY가 없으면 ALIAS가 남은 너비를
사용합니다. 내부 너비 30칸에서는 TURN에 선택 표시와 상태 기호만 표시하고 제목은
비워 둡니다. 38칸에서는 상태 단어까지 표시합니다. 76칸에서는 SUMMARY를 유지하고,
100칸 이상에서는 모든 열을 표시합니다. 제목을 단어 중간에서 자르지 않습니다.
ALIAS에 필요한 너비를 확보한 뒤 SUMMARY를 늘리고, 요약은 끝에서만 줄입니다.
전체 요약은 Detail에서 볼 수 있습니다. 전송 결과는 ALIAS나 SUMMARY 안에 표시하며
길면 줄입니다. 연결이 끊긴 호스트는 마지막 조회 결과에 stale 표시를 붙이고
MAIL을 `?`로 표시하며, 종료됐다고 판단하지 않습니다.

Threads는 기존의 **전체 너비를 굵게 표시하고 단어에만 밑줄을 긋는 열 헤더**와
**선택 행 전체의 배경색**을 사용합니다. 색상을 사용하지 않을 때는 행 전체를 반전합니다.
선택하지 않은 행에서는 상태·종류·전송 작업 라벨에 의미에 따른 글자색을 적용하고,
제목과 참여자는 기본 글자색을 유지합니다. 선택한 행에서는 밝은 배경과 대비를
확보하도록 라벨을 기본 선택 글자색과 굵은 글씨로 표시하며, 기호와 단어는 모두
유지합니다. 각 항목은 두 줄로 표시하며, 마우스로 선택할 수 있는 범위도 기존과
같이 행 전체입니다.

Threads는 **하나의 목록과 스크롤 영역** 안에서 `Active (개수)`와 `Handled (개수)`로
나뉩니다. 진행 중이거나 확인이 필요한 Active 항목을 위에 표시하고, 빈 행과 구분선을
둔 뒤 처리 완료된 Handled 항목을 아래에 표시합니다. 빈 그룹에는 제목이나 여백을
만들지 않으며, 각 그룹 안에서는 기존의 갱신·최근 순서를 유지합니다. 처리 완료된
행은 흐리게 표시하되 선택하면 원래의 높은 대비를 유지합니다. 제목과 빈 행은 선택하거나
실행할 수 없습니다. 방향키, 페이지 키와 휠은 구분선을 넘어 항목 사이를 이동하며,
새로고침으로 순서가 바뀌어도 클릭한 항목의 ID를 기준으로 동작합니다.

보관된 메시지가 하나 이상이고 **모든 메시지의 상태가 `handled`인 native 스레드만**
처리 완료 그룹으로 옮깁니다. 최신 메시지가 처리됐더라도 이전 메시지가 대기 중이거나,
전달 후 미처리 상태이거나, claim이 불확실하거나, 실패·전달 불가 상태라면 Active에
남습니다. 새 답장이 오면 같은 ID와 선택을 유지한 채 Active로 돌아옵니다. 철회는
전송 취소이지 사람이 처리했다는 뜻이 아니므로 `withdrawn`도 보수적으로 Active에
유지합니다. 직접 입력과 표시 중인 대기·실패 OUTBOX 작업은 항상 Active에 남습니다.
직접 입력 접수, 전송 성공이나 운영자 증거만으로 처리 완료를 추정하지 않습니다.
미확정 claim은 기록된 `delivering` 상태로 판단합니다. claim ID나 증거는 명시적으로
처리한 뒤에도 이력으로 남으므로, 해당 필드가 있다는 이유만으로 미처리로 보지는 않습니다.

| Threads 표시 | 의미와 색상 |
| --- | --- |
| `. pending`, `. queued` | 전송 대기이며 노란색으로 표시합니다. |
| `> submitting` | 직접 입력을 제출 중이며 노란색으로 표시합니다. |
| `? UNCERTAIN delivering` | 아직 확정하지 못한 native claim이며 노란색으로 표시합니다. 전달 완료를 뜻하지 않습니다. |
| `+ delivered`, `+ DIRECT accepted` | 기록된 native 전달과 별개의 직접 입력 접수이며 초록색으로 표시합니다. |
| `= handled` | 기록된 처리 완료 상태이며 청록색으로 표시합니다. |
| `! failed`, `! undeliverable` | 실패이며 빨간색으로 표시합니다. |
| `- withdrawn` | 철회됐으며 흐리게 표시합니다. |
| `? DIRECT unknown` | 직접 입력 접수 여부가 불확실하며 노란색으로 표시합니다. |
| `i fyi`, `! action` | 메일 종류이며 각각 청록색과 노란색으로 표시합니다. |
| `> direct` | 사용자의 터미널 직접 입력 증거이며 청록색으로 표시합니다. **native 메일이 아닙니다.** |
| `> message`, `< receipt`, `# setting`, `- withdraw` | OUTBOX의 전송 작업 종류이며 청록색으로 표시합니다. FYI/action 메일 종류를 뜻하지 않습니다. |

기호는 모두 한 셀을 차지하는 ASCII 문자이며 항상 상태·종류 이름을 함께 표시합니다.
기록된 행 데이터만 반영하므로 보기나 선택으로 상태를 만들지 않습니다. 스레드 안에
미확정 `delivering` claim이 하나라도 있으면 이후 메시지의 상태와 무관하게 불확실성
경고를 유지합니다. OUTBOX 접두사, 대상과 오류도 유지하며 전송 작업 라벨로 본문의
메일 종류를 추측하지 않습니다. Detail에서도 같은 상태·종류·전송 작업 표시와
운영자 증거·native 증거의 구분을 볼 수 있습니다. 직접 입력의
접수는 native 전달·처리 완료를 뜻하지 않습니다. `?` 도움말에도 이 범례를 표시합니다.

상태 색상은 보조 표현입니다. **working은 노란색**, **idle은 초록색**,
**done은 청록색**, **blocked는 빨간색**으로 표시하며, **unknown·stale은 흐리게**
표시합니다. `● working`, `○ idle`, `✓ done`, `! blocked`, `? unknown`,
`~ stale`처럼 기호와 단어를 함께 유지합니다. `NO_COLOR`가 있으면 값이 비어 있어도
색상을 끄지만 기호, 단어, 굵기, 밑줄, 흐림과 선택 행의 반전 표시는 유지합니다.

Detail과 다른 일반 텍스트 패널에는 왼쪽 안쪽 여백을 한 칸 둡니다.

Detail은 마지막으로 포커스를 둔 목록의 선택 항목을 자동으로
미리 보여 줍니다. 전체 요약과 상태 갱신·관찰 시각을 구분하여 현지 시간과 경과
시간으로 표시합니다. **Detail은 읽기 전용이며, 보기만 해서는 ACK·전달·처리·복구가
일어나지 않습니다.** Threads에는 메시지 이력, 직접 입력 결과와 대기·실패한
OUTBOX가 포함됩니다. `delivering`은 **UNCERTAIN**으로 표시합니다.

보내거나 받은 메일을 읽으려면 `Tab`으로 **Threads**에 포커스를 옮겨 스레드를
선택한 뒤 `Space`를 눌러 뷰어를 엽니다. 기존 **Detail**에서도 메시지를 읽을 수 있습니다.
에이전트를 선택하면 메시지 본문 대신 상태와 리소스를 보여 줍니다. 에이전트 Detail의
Unread 다음에는 **Mail** 구역이 있으며, 현재 불러온 스레드 중 해당 에이전트가 참여한
Active·Handled 개수와 `Read: Tab → Threads, select a thread, Space opens it` 안내를
흐리게 표시합니다. 해당 스레드가 없으면 `No threads with this agent yet`를 표시합니다.
Devices와 Servers는 그 아래에서 계속 확인할 수 있습니다.

메시지 Detail은 **메시지 i/N, 현지 시각·경과 시간, 기록된 발신자 → 수신자**를
짧은 헤더로 보여 준 뒤 종류·상태 요약과 일반 밝기의 본문을 표시합니다.
native 이력과 번호는 오래된 메시지부터 최신 메시지 순서를 유지하지만, 새 스레드를
선택하면 **최신 메시지 헤더**에서 읽기 시작합니다. 최신 메시지가 짧으면 스크롤 범위에
맞춰 마지막 페이지를 표시합니다. 이전 메시지는 Detail에서 PgUp이나 Home으로 읽습니다.
Threads의 제목은 최신 메시지의 제목이나 본문 첫 줄을 미리 보여 줍니다.
긴 대상 라벨은 읽기용 헤더에서만 줄입니다.
좁은 패널에서는 메시지 번호·시각 때문에 발신자와 수신자 방향이 사라지지 않도록
대상을 별도 헤더 행에 표시하며, 번호·시각 행은 짧게 표시할 수 있습니다.
정확한 전체 값은 기술 정보에 남습니다. 종류·상태, 접수와 전송 경고는 잘라내지 않고
줄바꿈하여 의미를 보존합니다. 제목과 UUID로 첫 본문 앞의 공간을 채우지 않습니다.
native와 DIRECT 본문은
원래 문단과 실제 개행, 문자 그대로의 `\n`을 보존하고 패널 너비에 맞춰 줄바꿈합니다.
OUTBOX는 대화 답신이나 native ACK가 아니라 전송 작업으로 유지합니다.
message 작업의 중첩된 message payload에 실제 문자열 본문이 있을 때만 본문을 표시합니다.

기술 정보는 기본으로 접혀 있습니다. NAV에서 Detail에 포커스를 두고 `t`를 누르면
전체 기록 원본, 식별자와 정확한 대상, claim과 이전 에이전트·세대, 경로, 확인 출처,
증거와 오류를 흐리게 표시합니다. 기술 정보를 접어도 미확정 `delivering`의
UNCERTAIN 경고, 운영자 확인의 **NOT native ACK**, DIRECT 접수가
**native 전달·처리 완료와 다르다**는 안내는 상태 요약에 남습니다.
펼치거나 접으면 최신 native 메시지 헤더로 돌아갑니다. 다른 항목을 선택하면 기술 정보를
접고 최신 헤더에서 시작합니다. 메시지가 하나인 스레드와 DIRECT·OUTBOX는 기존처럼 맨
위에서 시작합니다. 같은 항목을 새로고침하면 펼침 상태와 읽던 위치를 유지하며, 본문이나
줄바꿈이 바뀌면 유효한 범위 안으로 위치를 조정합니다. 새 메시지가 도착했을 때 이전
최신 헤더 위치나 그 헤더가 있는 마지막 페이지에 그대로 있었다면 새 최신 헤더로
이동합니다. 다른 곳으로 스크롤했다면 읽던 위치를 유지합니다.

기존 읽기 전용 안내행에 현재 보이는 행 범위·전체 행 수, 위·아래에 내용이 남았을 때의
`↑more`·`↓more`, 기술 정보 토글 상태를 함께 표시합니다. 좁은 패널에서는 문구를
줄이되 ACK하지 않는다는 안내, 읽기 위치와 토글 키를 유지하며 별도 본문 행을 쓰지
않습니다. 행 수에는 줄바꿈한 헤더·본문 문단과 펼친 기술 정보가 포함됩니다.
PgUp/PgDn은 실제 본문 표시 행 수에서 한 행을 뺀 만큼 이동합니다. 최소 이동량은
한 행이며, 일반적인 페이지 사이에는 한 행이 겹칩니다. 방향키·Home/End·휠·화면 크기
변경·기술 정보 토글에도 같은 스크롤 범위를 적용합니다.

### 인라인 입력과 답장

Agents에서 행을 선택하고 `Enter`를 누르면 Detail 아래에 전체 너비의 입력창을
열고 `To host/alias · FYI`를 표시합니다. 단일 영역 모드에서는 포커스가 있는
영역 아래에 표시합니다. 본문 배치를 정하기 전에 입력창 공간을 확보하므로,
입력창을 열거나 높이가 늘어나면 stacked에서 single 모드로 바뀔 수 있습니다.
UI에서 보내는 메일은 항상 발신자가 `sender=user`, 종류가 `fyi`이며 제목은
없습니다. native 수신기가 없으면 경고하지만 메일함으로 전송할 수 있습니다.
stale 수신자에게는 입력창을 열 수 없습니다.
Threads에서 `Enter`를 누르면 같은 입력창으로 최신 메시지에 답장합니다.
수신자를 현재의 stale이 아닌 에이전트로 찾지 못하면 오류를 표시합니다.

- `Enter`는 검토나 확인 단계 없이 메일을 즉시 전송합니다. 빈 본문은 전송하지
  않고 오류를 표시합니다.
- `Shift+Enter`는 줄을 바꿉니다. 메일함이 **kitty 키보드 프로토콜**을 요청하므로
  kitty 호환 터미널에서는 herdr를 통해서도 동작합니다. 이 프로토콜을 협상하지
  못하는 Moshi/mosh에서는 **`Alt+Enter`를 대안으로 사용하세요.** `Ctrl+J`는
  줄바꿈 키가 **아닙니다**. `HAM_MAILBOX_NO_KITTY=1`로 프로토콜 요청을 끌 수 있습니다.
- 숫자, `q`, `?`, `:`, `/` 등 인쇄 가능한 문자는 본문에 입력됩니다.
  방향키, `Home`·`End`, `Backspace`, `Delete`로 편집하고 `↑`·`↓`로 줄을 옮깁니다.
- `Ctrl+D`는 **터미널 직접 입력**으로 전환하거나 되돌립니다. 직접 입력에서
  `Enter`를 누르면 기본 선택이 Cancel인 확인창이 열립니다. `Tab` 또는 `←`·`→`로
  버튼을 고르고 `Enter`로 선택한 동작을 실행합니다.
- `Esc`는 입력창을 닫되 수신자와 답장별로 본문과 커서를 보존합니다.
  `Ctrl+R`은 입력창을 유지한 채 새로고침합니다. 입력 중 `F1`은 도움말을 열며,
  도움말을 닫으면 같은 입력창으로 돌아옵니다.

성공하면 입력창을 닫고 에이전트 행에 결과를 표시하며, 팝업도 닫습니다.
제출한 뒤 바뀌지 않은 초안만 지우므로 결과를 기다리며 새로 편집한 내용은
보존합니다. 실패하면 본문을 입력창에 남기고 오류를 표시합니다.

### Settings

NAV에서 `s`를 누릅니다. `↑`·`↓` 또는 `j`·`k`로 행을 고릅니다.
행을 클릭하면 선택하고, 선택한 행을 다시 클릭하면 `Enter`처럼 동작합니다.
`Esc`로 설정창을 닫으면 아직 저장하지 않은 변경을 버립니다.

Mode와 Thresholds는 저장소 전체에 적용합니다. Main·Members에는
`HERDR_HAM_OPENER_PANE_ID`로 찾은 Mailbox 시작 pane의 workspace를 표시합니다
(`Main (workspace …)` / `Members (workspace …)`). 범위는
`(repo_id, 정규 로컬 호스트, workspace_id)`이며 선택한 에이전트의 workspace를
따라 바뀌지 않습니다. 모든 저장소 보기에서도 기존 저장소 선택 방식을 유지하며,
저장소를 하나로 정할 수 없으면 설명과 함께 설정을 비활성화합니다.
workspace 역할 설정은 해당 호스트에만 저장하며 복제하지 않습니다.

- **Mode (repo-wide):** `Enter`로 각 선택지의 의미가 표시된 **PICK** 목록을 엽니다.
  `↑`·`↓`로 고른 뒤 `Enter`를 누르거나 항목을 클릭하면 바로 저장합니다.
  mode 행에서 `←`·`→` 또는 `h`·`l`로 값을 바꾼 뒤 `Enter`로 저장할 수도 있습니다.
- **Main (workspace …):** `Enter`로 저장소·정규 호스트·workspace가 모두 같은
  활성 에이전트와 `(none)`을 담은 **PICK** 목록을 엽니다. 현재 값은 `●`로
  표시하며 `Enter`나 클릭으로 저장합니다.
- **Members (workspace …):** `Enter`로 해당 범위의 **CHECK** 목록을 엽니다.
  `Space`나 항목 클릭으로 체크를 바꾸고 `Enter`로 체크된 구성원을 저장합니다.
  비활성 에이전트나 범위 밖의 대상을 새로 지정할 수 없으며 서비스도 이를
  거절합니다. 기존 구성원이 범위 밖으로 이동하면 그 범위의 역할을 받지 않습니다.
- **임곗값(repo-wide):** `←`·`→`, `-`·`+` 또는 `◀`·`▶` 클릭으로 값을 조정합니다.
  `idle_minutes`는 1, `coalesce_seconds`는 5, `wakes_per_hour`와 `max_hop`은
  각각 1씩 바뀌며 범위는 0~10000입니다. 저장 전에는 `unsaved`로 표시하고
  `Enter`로 저장합니다. 대기 중인 변경이 없을 때 `Enter`를 누르면 숫자만
  입력할 수 있는 선택적 입력창을 엽니다. 목록이나 숫자 입력창에서 `Esc`를
  누르면 해당 편집을 취소합니다.

마우스 휠로 목록이나 설정 메타데이터를 스크롤합니다.
선택한 Agents 행은 `Target: host/alias`로 표시됩니다. 대상이 활성 상태이며
Mailbox 시작 pane의 설정 범위 안에 있을 때만 `m`으로 main을 지정하고
`Space`로 수동 구성원에 넣거나 뺄 수 있습니다. 이 두 단축키는 기본 선택이
Cancel인 확인창을 그대로 거칩니다. Home, computed main, 버전·origin, 전파
대기와 충돌 정보는 읽기 전용이며 저장소 단위 설정만 전파합니다. 요청·snapshot·저장
결과를 저장소·호스트·workspace 전체 범위에 연결하므로 다른 범위의 결과가
현재 설정을 덮어쓰지 못합니다. 설정은 내부 서비스를 사용하며 에이전트의
`repo show`는 호출자의 범위를 보여 주는 읽기 전용 명령입니다.

설정은 한 번에 하나만 저장합니다. 해당 행에 **Saving settings**를 표시하고
저장이 끝나면 결과나 오류를 같은 행에 표시합니다. 추가 저장은 대기열에 넣지
않고 거절하며, 거절된 편집 내용은 보존합니다. 화면 이동은 계속 동작합니다.
확정 결과를 즉시 표시하고 오래된 조회 결과로 덮어쓰지 않습니다.
`PgUp`·`PgDn`으로 긴 메타데이터와 생략 없이 줄바꿈한 충돌 기록을 스크롤하며,
NAV의 `e`로 전체 진단 정보를 봅니다.

### 접수 결과와 불확실한 전달

메일은 일반적인 native 수신 규칙을 따릅니다. 직접 입력은 정확히
`Message from user (HAM):` 헤더를 붙여 검증된 터미널 전송 경로로 제출합니다.
수신자의 작업에 끼어들 수 있으므로 경로를 명시적으로 선택하고 확인해야 합니다.
HAM은 `via=direct`, `submitting`을 기록한 뒤 `accepted`·`unknown`·`failed`를
기록합니다. 이는 native의 `delivered`·`handled` 수신 확인이 아닙니다.
Threads에서 결과를 확인하세요. 중단된 `submitting`이나 `unknown`은 다시 전송하기
전에 직접 확인해야 하며, HAM은 자동 재전송하지 않습니다.

Threads의 `w`는 로컬에서 보낸 철회 가능한 메일을 철회하고, `t`는 선택한 OUTBOX를
같은 ID로 재시도합니다. 두 동작 모두 정확한 대상을 확인해야 합니다.
불확실한 native claim은 세션이 바뀌어도 보류합니다. `a`는 적용, `n`은 미적용을
확인합니다. 두 동작 모두 먼저 비어 있지 않은 운영자 증거를 입력한 뒤, 정확한
메시지·claim ID, 이전 에이전트, generation과 현재 상태가 표시된 확인창을 거칩니다.
기본 선택은 Cancel이며 `Tab` 또는 `←`·`→`로 버튼을 고르고 `Enter`로 실행합니다.
`Esc`는 취소합니다. 적용 확인은 이전 claim에 대한 **사용자의 수동 확인**이지
native runtime journal의 증거, 모델의 이해나 작업 처리 완료가 아닙니다.
미적용 확인은 해당 claim만 해제하며 그 자체가 재전송하지는 않습니다.

로컬 board bell은 1초마다 확인하고, 원격 상태는 키 입력 루프 밖에서 실행 시간을
제한한 별도 프로세스로 30초마다 조회합니다. 닫을 때는 자기가 시작한 프로세스만
정리하며, 이 조회는 모델 턴을 만들지 않습니다. 표시 셀 너비를 고려하는 텍스트
도구로 한글 입력, 자르기와 크기 변경을 처리합니다. `NO_COLOR`가 있으면 값이 비어
있어도 색상을 끄지만 라벨 등 색상 이외의 상태 표시는 유지합니다.

### 기기와 서버 표시

Agents 영역은 RX, SUMMARY, ROLE을 배치한 뒤 공간이 허용되면 **PHN**, **EMU**,
**SRV** 열에 각각 휴대전화, 에뮬레이터, 서버 개수를 표시합니다. 각 열은 내용 너비가
세 칸이며, 열 사이는 공백 두 칸으로 띄웁니다. 색상 설정과 관계없이 ASCII 제목을
사용하고 제목과 값을 가운데에 정렬합니다. 리소스 이모지는 사용하지 않습니다.
개수가 0이면 `·`를 표시하되 선택하지 않은 행에서만 흐리게 표시하고, 0이 아니면
일반 밝기의 숫자를 표시합니다. 기기 정보가 없으면 PHN과 EMU에 `?`를,
서버 정보가 없으면 SRV에 별도로 `?`를 표시합니다.
호스트 그룹 라벨에는 대상 리스너가 없는 Serve 경로, 소유자가 없는 Serve 대상,
stale 기기를 `dead 1 · unowned 1 · stale-dev 1`처럼 표시하며 개수가 0인 항목은
생략합니다. 호스트 자원 필드가 없으면 `?`, 탐색 오류가 있으면 `!`를 표시합니다.
공간이 부족하면 에이전트 수를 유지하고 발견 사항부터 줄입니다.

Agent Detail에는 **Devices**와 **Servers** 구역이 있습니다. Devices는 현재 소유한
유효한 점유를, Servers는 포트·프로세스·PID, 바인드 주소, cwd, inherited 여부,
시작 시각·경과 시간과 URL을 표시합니다. `inherited`는 리스너가 현재 에이전트 세션보다
먼저 시작됐다는 뜻입니다. 정보가 없으면 `Devices: ?` 또는 `Servers: ?`, 비어 있음이
확인되면 `: none`으로 표시합니다. 이전 peer는 `devices`, `servers`, 호스트 `resources`
중 일부를 생략할 수 있으며, 없는 정보만 알 수 없음으로 처리하고 0으로 해석하지 않습니다.

표시는 에이전트 JSON의 `devices`, `servers`와 호스트의
`resources:{servers_unowned:[],dead_serve:[],stale_devices:[],error:null}`를 읽습니다.
서버는 현재 사용자의 리스너와 Tailscale Serve에서 탐색하며 플러그인, adb와 에이전트
런타임 리스너는 제외합니다. 조회는 레지스트리 갱신, 점유 정리, 토큰 변경이나 메일
확인 처리를 하지 않습니다.

기기 점유를 바꾸려면 표의 동작이 아니라 번들 CLI를 사용합니다.

```text
device claim phone|emu DEVICE [--label TEXT] [--force]
device release [phone|emu|all] [DEVICE]
device list
```

`release`는 기본적으로 호출자 자신의 점유를 모두 해제하며 종류·기기로 범위를 좁힙니다.
점유는 검증된 호스트·terminal·generation에 귀속됩니다. 비활성 또는 이전 generation의
소유자는 adb 연결 여부와 관계없이 stale이므로 교체할 수 있습니다. 다른 활성 소유자가
있으면 점유를 거부하며, `--force`는 사용자가 명시적으로 지시한 경우에만 사용합니다.
Herdr 갱신 실패를 stale의 근거로 해석하지 않습니다. `device list`는 읽기 전용입니다.
명령 결과와 기기 세부 사항은 [스킬 가이드](skill-guide.md#기기-점유와-자원-표시)를
참고하세요. 제품은 기존 기기 JSON을 가져오지 않습니다. `heavy_slot.py`는 별도로
그대로 유지하며 슬롯을 표시하지 않습니다.

### 역할, phase와 테두리 소유권

main과 worker는 `(저장소, 정규 호스트, Herdr workspace)`별로 정하므로
worktree workspace도 자체 main을 가집니다. 모드와 임곗값은 저장소 전체에
적용합니다. auto에서는 해당 범위의 활성 에이전트로 지정한 명시적 main이
우선합니다. 없으면 활성 에이전트가 하나일 때 그 에이전트가 main이 되며,
여럿이면 메인 체크아웃의 활성 에이전트가 정확히 하나일 때만 main이 됩니다.
그 외에는 main이 없고 나머지 auto 에이전트는 worker로 남습니다. manual에서는
활성 명시적 main과 해당 범위의 지정 구성원만 역할을 받습니다. 모든 화면은
각 에이전트의 호스트가 계산한 역할을 표시합니다.

역할은 `🟧 [메인] orange-rabbit`처럼 alias 앞에 붙여 주소 해석을 유지합니다.
공유 표시 모듈이 alias, color, 표시 이름, phase(`recap`)와 원장 기반 기기 토큰을
메타데이터 source `herdr.agent-messenger`로 보고합니다. 값은 정확히
`phone=📱 <공백으로 연결한 라벨>`과 `emu=🤖 <공백으로 연결한 라벨>`이며, 점유가
없으면 해당 키를 지웁니다. 상태 표시도 점유를 유지하며 강제 교체하면 이전 활성
소유자의 표시도 갱신합니다. Herdr 토큰은 source별로 격리되지 않은 pane 단위의
평면 맵입니다. HAM은 관련 없는 토큰 키를 바꾸지 않습니다.

상태·역할 기능을 사용하면 summary는 `[메인] summary` 또는 `[워커] summary`
형태로 테두리에 표시합니다. off 모드의 상태에는 역할 접두사가 없습니다.
HAM은 비어 있는 테두리, 출처가 확인된 legacy 테두리, 또는 자기가 마지막으로
기록한 값과 같은 테두리만 바꿉니다. 사용자가 다른 이름으로 바꿨으면 보존합니다.
옛 `user:pane-recap` 토큰은 새 상태·역할 기능을 사용할 때만 지웁니다.
이 UI는 전역 recap 규칙을 설치하거나 삭제하지 않습니다.

## 기존 직접 프롬프트 팝업

**Send Prompt to Agents**와 **Held Messages** 동작은 그대로 유지합니다.
아래 내용은 메일함 전달이 아니라 기존 팝업을 설명합니다.

## 메신저 열기

에이전트가 실행 중인 pane에서 **Send Prompt to Agents**를 실행합니다. 현재
에이전트가 고정 발신자가 됩니다. 선택한 pane에 에이전트가 없으면 팝업 대신 오류
알림을 표시합니다.

로컬 에이전트는 Herdr workspace 라벨 순으로 즉시 표시됩니다. 유니코드 라벨을
보존하고 worktree 기반 workspace에는 `WT:` 접두사가 붙습니다. 원격 에이전트는
SSH 호스트 별칭 아래에 묶고, 각 호스트 안에서 workspace별로 다시 묶어 표시합니다.
그룹 식별에는 정규 호스트와 Herdr의 `workspace_id`를 함께 사용하며, 호스트가
다른 ID를 같은 workspace로 보지 않습니다. 표시 이름이 같은 서로 다른
workspace도 합쳐지지 않으며, 이 경우 ID를 함께 표시해 구분합니다.

## 수신자 행

조작 상태와 에이전트 수명 주기 표시는 서로 분리돼 있습니다.

- `›`: 키보드 커서
- `[x]`: 선택된 수신자
- `●`: 작업 중
- `○`: 대기
- `✓`: 완료
- `!`: 차단
- `~`: 오래된 상태

색상은 보조 표현이므로 단색 화면에서도 상태를 구분할 수 있습니다. workspace
이름은 각 그룹 제목에 한 번만 표시하고 에이전트 행에서는 반복하지 않습니다.
각 행은 Agent Labels 이름, Herdr pane ID, 수명 주기 상태를 우선 표시합니다.
전체 session ID와 workspace 정보는 주 화면 너비를 차지하지 않으면서 검색할 수
있습니다. 호스트 제목은 에이전트 수를 항상 `(n)`으로 표시하고, workspace 제목은
에이전트가 여러 개일 때만 같은 형식의 개수를 표시합니다.

긴 그룹은 스크롤 중에도 호스트와 workspace 제목을 유지합니다. 작은 화면에서
sticky 제목을 하나만 표시할 수 있으면 더 구체적인 workspace 제목을 우선합니다.
필요한 경우 수신자 제목에 현재 보이는 범위를 표시합니다. 접속할 수 없는 원격
호스트는 요약해서 보여주며 상세 화면에서 각 별칭과 최근 오류를 확인할 수 있습니다.

## 메시지 편집기와 레이아웃

팝업은 큰 터미널에서 최대 120열×32행까지 확장되고 작은 터미널에 맞춰 축소됩니다.
탐색된 수신자 목록에 대부분의 공간을 할당하면서 가능하면 soft-wrap된 메시지
4행 이상을 유지합니다. 긴 메시지는 텍스트 커서를 따라가며 viewport scrollbar를
표시합니다.

좁은 터미널에서는 단축키 도움말을 자르지 않고 다음 줄로 넘깁니다. 팝업은 Herdr
터미널 팔레트를 상속하며 수명 주기 색상은 작업 중, 완료, 차단, 경고 상태에만
사용합니다.

UI 언어는 `LC_ALL`, `LC_MESSAGES`, `LANG` 순으로 결정하며 영어, 일본어,
한국어를 지원합니다. 지원하지 않는 locale은 영어를 사용합니다.

위·아래 방향키는 화면에 표시된 메시지의 줄바꿈에 맞춰 커서를 이동합니다.
긴 라벨과 상태 문구는 터미널 셀 너비에 맞춰 잘라서 한국어와 일본어가 다음 행을
덮어쓰지 않도록 합니다.

전송을 취소해도 이미 확인된 전송 결과는 유지합니다. 이미 전달됐거나 연결 중단으로
수신 여부가 불확실한 대상은 선택에서 해제합니다. 수신 여부가 불확실하면 팝업에
안내하므로 다시 보내기 전에 대상의 상태를 확인할 수 있습니다. 직접 전송에서는
아직 보내지 않은 대상과 실패가 확인된 대상의 선택을 유지합니다.

## 키보드 조작

- `Up` / `Down`: 선택지, 수신자 또는 메시지 행 이동
- `Enter`: 강조된 탐색 방식 확정
- `D` / `L`: 원격 탐색 또는 로컬 전용 선택
- `C` / `D`: 코디네이터 위임 또는 직접 전송 선택
- `Space`: 수신자 선택 전환
- `Ctrl+A`: 필터된 수신자 모두 선택
- `Ctrl+D`: 선택 해제
- `Tab`: 수신자 목록과 메시지 편집기 전환
- `Ctrl+O`: 전송 방식 화면 다시 열기
- `Ctrl+R`: 로컬 및 허용된 원격 에이전트 새로고침
- `Ctrl+U`: 접속 불가 원격 호스트와 최근 오류 표시
- `Ctrl+G`: HAM 스킬 설치기와 가이드 열기
- `Ctrl+S`: 프롬프트 전송
- `Esc`: 이전 화면으로 이동하고 탐색·전송을 취소한 뒤 팝업 닫기
