# HAM 메일함과 오버레이 UI 참고서

한국어 · [English](../ui-reference.md) · [README](../../README.ko.md)

## 메일함 열기

명령 팔레트에서 다음 세 동작을 사용할 수 있습니다.

- **HAM: Mailbox (Right Split)** (`herdr.agent-messenger.mailbox-split`)은
  현재 pane 오른쪽에 플러그인 소유 pane을 엽니다.
- **HAM: Mailbox (Tab)** (`herdr.agent-messenger.mailbox-tab`)은 같은 화면을 탭으로 엽니다.
- **HAM: Mailbox (quick send)** (`herdr.agent-messenger.mailbox-popup`)는
  전송 성공 결과가 오면 닫히는 오버레이를 엽니다. 전송이 실패하면 입력창을 유지합니다.

일반 셸에서도 열 수 있으며, 연 pane에 에이전트가 없어도 됩니다. 이 동작은
키 바인딩을 바꾸거나 runtime을 설치하지 않습니다. 오른쪽 분할 동작을
`prefix+m`에 연결하면, workspace에 등록된 메일함이 현재 탭에 있을 때만
그 메일함으로 이동합니다. 다른 탭에 있으면 현재 pane 오른쪽에 새 메일함을
열고 등록을 교체합니다. 이전 메일함은 화면 첫 줄에 `NAV ·`가 있을 때만
닫습니다. 초안 작성, 확인, 선택 중이거나 화면을 읽을 수 없으면 그대로 둡니다.
탭 동작은 기존처럼 어느 탭에 있든 workspace에 등록된 메일함으로 이동합니다.
기존 메일함은 표시 이름이 아니라 pane/terminal ID로 확인합니다.
`q`는 플러그인이 소유한 메일함 pane이나 오버레이만 닫습니다. 내용이 있는 초안은
폐기 확인을 거치며 기본 선택은 Cancel입니다. 최상위에서 `Esc`는 빠른 전송 오버레이만
닫고 분할·탭에서는 아무 동작도 하지 않습니다. 입력창이나 대화상자에서는 빠져나옵니다.

별도의 pane 동작인 **HAM: Deliver queued FYI now**(`herdr.agent-messenger.fyi-now`)는
메일함을 열지 않습니다. [FYI 즉시 전달](#fyi-즉시-전달)을 참고하세요.

### Herdr 오버레이 배치

빠른 전송, **Send Prompt to Agents**, **Held Messages**, **HAM Skill**은 공식
`overlay` 배치를 사용합니다. Herdr가 오버레이 pane을 임시로 확대하고, 닫으면 이전
포커스와 확대 상태를 복원합니다. 상시 메일함의 오른쪽 분할·탭 배치와 재사용 규칙은
바뀌지 않습니다. 기존 키 바인딩을 위해 공개 action과 pane entrypoint의
`mailbox-popup` ID도 유지합니다.
중앙에 제한된 크기로 뜨던 팝업과 달리, 오버레이는 분할된 pane들을 포함한 현재 탭의
전체 콘텐츠 영역을 채우며 사이드바와 탭 표시줄은 그대로 보입니다.

HAM은 `pane layout --current` 조회나 `--width`·`--height` 없이
`plugin pane open --placement overlay --focus`를 한 번 실행합니다. manifest에도
pane 크기를 지정하지 않습니다. 오버레이는 HAM이 정한 크기의 떠 있는 사각형이
아니라 Herdr가 제공하는 pane 영역을 사용합니다. 공개 CLI에 맞추고 지원되지 않는
크기 설정을 피하기 위한 선택입니다. 공식 [Panes 문서](https://herdr.dev/docs/plugins/#panes),
[v0.9.5 오버레이 구현](https://github.com/herdrdev/herdr/blob/v0.9.5/src/app/api/plugins/panes.rs),
너비·높이를 `popup`에서만 허용하는 [manifest 검증](https://github.com/herdrdev/herdr/blob/v0.9.5/src/app/api/plugins/manifest.rs)을
참고하세요. [v0.8.0 플러그인 스키마](https://github.com/herdrdev/herdr/blob/v0.8.0/src/api/schema/plugins.rs)에
이미 `Overlay`가 있으므로 최소 버전은 **Herdr 0.8.0**으로 유지합니다.

HAM은 오버레이를 열기 전에 메신저 발신자, 설치 대상 프로젝트, 메일함 저장소와
원래 pane·terminal ID를 필요한 화면에 맞춰 보존합니다. 오버레이 자체의 pane ID로
이 정보를 바꾸지 않습니다. Held Messages는 호스트 전체의 보류 목록을 보여 주며
원래 pane에 에이전트가 없어도 열립니다.

HAM은 오버레이 안에서 본문 영역을 가로 중앙에 두고 위쪽에 맞춥니다. 외곽 테두리는
추가하지 않습니다. 본문 너비의 상한은 빠른 전송 120열, Send Prompt 104열,
Held 96열, Skill 80열입니다. 80열보다 좁으면 좌우 여백을 한 칸으로 줄입니다.
이는 본문의 너비 제한이지 Herdr pane의 크기 요청이 아닙니다. 분할·탭 메일함의
기존 배치는 유지합니다.

각 오버레이의 첫 줄에는 `HAM · <Surface>`와 흐리게 표시한 작업 맥락을 놓고,
다음 줄은 비웁니다. 빠른 전송은 INPUT/NAV를, Held는 현재 목록 위치를 오른쪽
끝에 표시합니다. 맥락은 한글처럼 두 칸을 차지하는 문자도 고려해 자릅니다.
분할·탭 메일함의 제목은 바꾸지 않습니다.

네 화면은 의미에 따른 색상과 `[Key] Action` 형식의 키 안내를 공유합니다.
각 안내를 나누지 않고 최대 두 줄로 배치합니다. 이동·주요 동작·닫기 순서를 유지하며,
우선순위는 공간이 부족할 때 생략할 안내를 정하는 데만 사용합니다. 닫기·도움말·필수
편집 동작은 부가 단축키보다 먼저 남깁니다. 선택한 행에는 항상 `›`와 굵은 글씨를
사용합니다. 256색 터미널에서는 기본 글자색에 짙은 회색 배경을 행 전체에 적용하고,
다른 터미널에서는 반전합니다. `NO_COLOR`가 있으면 값이 비어 있어도 색상 쌍을
초기화하지 않으며 선택 기호, 굵기, 반전은 유지합니다.

빠른 전송의 INPUT은 공간이 허용하면 내용 8행 이상을 확보하고 Detail은 바깥
영역을 최대 9행으로 제한합니다. INPUT에서는 작성창 테두리와 제목을 강조하며,
NAV에서는 `›`로 활성 영역 제목을 표시합니다. 기존 영역 테두리와 Send Prompt
편집기의 왼쪽 세로선은 유지합니다. 선택 기호는 상태 기호나 수신자 체크박스 바로
앞에 한 칸을 띄워 표시합니다. Recipients 영역 제목은 선택하지 않고 굵은 강조색으로
표시합니다. Held는 목록 바로 아래에 선택한 항목의 미리보기, 시각, push 경고를
붙입니다. 빈 목록에는 제목 아래로 `No held messages.`와 `[Esc] Close`만 표시합니다.
Skill은 가장 긴 클라이언트 이름에서 두 칸 뒤에 상태를 정렬하고 선택한 이름·상태
행만 강조합니다. 긴 경로는 별도의 상세 줄에 표시합니다.

### 화면 크기에 따른 영역 배치와 탐색

본문은 **Agents**, **Threads**, **Detail**로 구성됩니다. 공간이 충분하면
Detail은 항상 목록 아래에 표시하며, 오른쪽의 세 번째 열로 배치하지 않습니다.

- **Stacked, 좌우 배치:** 너비가 80열 이상이고 사용 가능한 본문이 18행 이상일 때,
  각 절반에 Agents의 모든 열을 표시할 수 있어야 두 목록을 나란히 배치합니다.
  TURN, ALIAS, MAIL, RX, ROLE, PHN, EMU, SRV와 최소 16칸의 PHASE · SUMMARY,
  열 사이 간격과 테두리를 기준으로 필요한 너비를 계산합니다.
  별칭과 역할의 현재 너비에 따라 기준이 달라집니다. 예를 들어 별칭이 15칸이고
  ROLE이 최소 너비인 4칸이면 터미널 너비가 158열 이상이어야 합니다.
- **Tabbed:** 좌우 배치에 필요한 너비보다 좁으면 위쪽 목록을 전체 너비로 표시합니다.
  위쪽 테두리의 `Agents │ Threads`에서 활성 탭은 강조색과 굵은 글씨로,
  비활성 탭은 흐리게 표시합니다. 탭 이름을 클릭하면 해당 목록으로 전환합니다.
  Detail은 아래에 전체 너비로 유지합니다. 별칭이나 역할이 길면 여유 너비부터
  줄여서 전체 너비의 Agents 목록에 기기·서버 열을 유지합니다.
- Detail의 테두리를 포함한 높이는 `round(사용 가능한 본문 높이 * 0.4)`입니다.
  최소 9행으로 맞춰 내용 6행과 안내 1행, 테두리를 확보하고, 목록에도
  테두리와 탭 표시줄을 포함해 최소 8행을 남깁니다. 전체 내용은 스크롤할 수 있습니다.
- 사용 가능한 본문 높이는 전역 헤더, 하단 키 안내, 상태 표시줄과 INPUT을
  제외한 높이입니다. INPUT은 Detail 아래에 전체 너비로 표시합니다.
  입력창을 열거나 높이가 늘어나면 단일 영역 모드로 바뀔 수 있습니다.
- **Single:** 너비가 80열 미만이거나 사용 가능한 본문이 18행 미만이면
  포커스가 있는 영역만 본문에 표시합니다. 위쪽 테두리에는 목록 탭을 유지합니다.
  기존 순서인 `Agents → Threads → Detail → Agents`로 포커스를 옮기면
  Detail이 목록을 대신하며, 테두리에는 탭과 Detail 이름을 함께 표시합니다.
  탭을 클릭하면 해당 목록으로 돌아갑니다. INPUT은 아래에 별도 패널로 유지합니다.
- 모든 배치에서 `Tab`·`Shift+Tab`, `←`·`→`, `h`·`l`로 같은 순서대로
  포커스를 옮깁니다. 목록 포커스에 맞춰 활성 탭도 바뀝니다. Detail에서는
  마지막으로 선택한 목록의 탭을 유지하며, 각 목록의 선택과 스크롤은 따로 보존합니다.
- **Tiny:** 너비가 32열 미만이거나 터미널 높이가 10행 미만이면 본문 대신
  크기 변경 안내를 표시합니다. 초안, 선택 항목, 커서와 모드는 유지합니다.

```text
Tabbed (두 목록을 나란히 표시할 너비가 부족할 때)
+-- Agents | Threads -------------------------------+
| 활성 목록                                         | 나머지 공간, 최소 8행
+---------------------------------------------------+
| Detail                                            | 약 40%, 최소 9행
+---------------------------------------------------+
| INPUT (열려 있을 때 표시, 본문 높이에서 제외)      |
+---------------------------------------------------+
```

INPUT과 상태 표시줄이 없으면 200×50 터미널의 사용 가능한 본문은 48행입니다.
좌우 목록은 29행, Detail은 19행을 사용합니다. 110×35에서는 활성 탭이 20행,
Detail이 13행을 사용합니다. 이 높이에는 테두리가 포함됩니다.

에이전트 Detail은 한 열 안에서 **Work**(턴 상태, 단계, 굵은 요약),
**Identity & role**, **Devices & servers**, **Mail**, 흐린 **Receiver/technical**
순서로 묶어서 표시합니다. 기기는 기술 ID보다 아이콘과 사람이 읽는 이름
(예: `📱 SM-A245N`)을 먼저 표시합니다. Mail에는 메시지 본문 대신 개수와
Threads·Space 읽기 안내를 표시합니다. 스레드 Detail의 메시지 이력과
선택적으로 펼치는 기술 정보는 유지합니다.

헤더는 현재 모드(`NAV`, `INPUT`, `CONFIRM`, `SETTINGS`, `HELP`, `EVIDENCE`)를,
**NAV**에서 Agents 또는 Threads 항목(DIRECT·OUTBOX 포함)을 선택하고 `Space`를
누르면 화면 중앙에 읽기 전용 Detail 뷰어가 열립니다. 화면의 약 90% 크기이며
최대 100×40칸입니다. `↑`·`↓`, `PgUp`·`PgDn`, `Home`·`End`와 휠로 스크롤하고
`t`로 Detail과 같은 기술 정보를 토글합니다. 최신 메시지 위치를 기준으로 열리며,
그 위치에 있을 때만 새 도착 메시지를 따라갑니다. 새로고침 중 항목이 사라지면
상태 메시지와 함께 닫힙니다. `Esc`, `q`, `Space` 또는 바깥 클릭으로 닫습니다.
안쪽 클릭과 `Enter`는 동작하지 않으며, 보기만 해서는 ACK하지 않습니다.
INPUT에서 Space는 문자로 입력되고, CONFIRM·Settings 선택 목록의 기존 Space
동작은 유지됩니다.
| --- | --- |
| `Space` | 선택한 Agents 또는 Threads 항목을 읽기 전용 뷰어로 엽니다. |
| `↑` / `↓`, `j` / `k` | 목록의 선택 항목을 옮깁니다. Detail에 포커스가 있으면 방향키로 스크롤합니다. |
| `PgUp` / `PgDn`, `Home` / `End` | 포커스가 있는 영역에서 페이지를 넘기거나 처음·끝으로 이동합니다. Detail은 실제로 보이는 본문 행 수를 기준으로 한 행씩 겹치게 페이지를 넘기며, Home/End는 첫 페이지와 마지막 페이지로 이동합니다. |
| `Enter` | Agents에서는 입력창을, Threads에서는 답장 입력창을 엽니다. Detail에서는 동작하지 않습니다. |
| `f` | Agents에서 선택한 로컬 에이전트에게 FYI 지연과 입력 유휴 대기 시간을 생략하고 대기 중인 FYI를 전달하도록 요청합니다. 프롬프트 입력이나 확인 없이 실행하며 자세한 내용은 [FYI 즉시 전달](#fyi-즉시-전달)을 참고하세요. 원격·비활성 행에서는 아무것도 바꾸지 않고 이유를 표시합니다. |
| `m` | Agents에서 같은 호스트·저장소·역할 그룹의 활성 에이전트를 main으로 고정합니다. 이미 명시적으로 고정된 행에서는 고정을 해제합니다. 확인을 거치며, 원격·비활성·다른 그룹의 행에서는 설정을 바꾸지 않고 이유를 표시합니다. |
| `t` | Detail에서는 native 스레드·DIRECT·OUTBOX의 기술 정보를 펼치거나 접고 최신 native 메시지로 돌아갑니다. 단일 항목은 맨 위로 이동합니다. Threads에서는 기존 OUTBOX 재시도 확인창을 엽니다. 에이전트 상세·진단 화면에서는 토글하지 않으며 INPUT에서는 문자로 입력합니다. |
| `s` | Settings를 엽니다. |
| `?` | 문맥별 키와 전체 키 목록을 차례로 보여 주는 도움말을 엽니다. |
| `e` | 연결 오류와 대기 중인 작업 등 진단 정보를 Detail에 표시합니다. |
| `r` | 새로고침합니다. |
| `q` | 종료합니다. 내용이 있는 초안은 폐기 여부를 확인합니다. |
| `Esc` | 도움말·진단·대화상자를 닫습니다. 최상위에서는 빠른 전송 오버레이만 종료합니다. |

### 마우스

- 영역을 클릭하면 포커스를 옮기고, Agents나 Threads의 행을 클릭하면 해당 행을
  선택합니다. 이미 선택한 행을 클릭하면 `Enter`처럼 동작하여 Agents에서는
  입력창을, Threads에서는 답장 입력창을 엽니다.
- 휠은 포커스를 옮기지 않고 포인터 아래의 영역을 스크롤합니다.
- 입력창의 본문을 클릭하면 커서를 해당 위치로 옮깁니다.
- 대화상자의 버튼은 클릭할 수 있으며, 대화상자 바깥을 클릭하면 무시합니다.
  Settings에서는 행을 클릭하면 선택하고, 선택한 행을 클릭하면 `Enter`처럼
  동작합니다. 도움말은 아무 곳이나 클릭하면 닫힙니다.
- 마우스 처리는 기본으로 켜져 있습니다. 켜져 있을 때는 보통 `Shift`를 누른 채
  드래그하면 터미널 텍스트를 선택할 수 있습니다. `HAM_MAILBOX_NO_MOUSE=1`로
  마우스 처리를 끌 수 있습니다.

숫자는 탐색 키가 아닙니다. Agents는 에이전트마다 메타데이터를 둘째 줄에 표시하지
않고 **테두리 없이 열을 정렬한 한 줄 행**을 사용합니다. 열 사이는 **공백 두 칸**으로
띄우며, 패널 안에는 세로 경계나 가로 구분선을 그리지 않습니다. 열 이름은
**밑줄 없이 청록색 굵은 글씨**로 표시하고, 색상을 사용하지 않으면 굵게만 표시합니다.
각 호스트 구역은 `▾ winmini · 1 agent`, `▾ winmini · 2 agents`처럼 **굵은 호스트
이름과 에이전트 수**로 시작하며, 그 아래에 열 이름과 에이전트 행을 표시합니다.
에이전트가 없는 호스트에는 열 이름을 표시하지 않습니다. 작은 화면의 공간을
보존하기 위해 구역 사이에 빈 줄을 넣지 않습니다. 호스트와 열 이름은 마우스로
선택할 수 없으며 키보드 선택에서도 건너뜁니다. 스크롤할 때 선택한 에이전트를
계속 보여 주고, 공간이 허용되면 해당 호스트와 열 이름도 함께 유지합니다.
발견 사항은 0이 아니거나 알 수 없을 때만 뒤에 표시하며, 필요한 경우 stale·오류
정보도 표시합니다. 공간이 부족하면 개수를 유지하고 발견 사항부터 줄입니다.

먼저 창을 연 저장소의 에이전트를 표시합니다. 로컬 호스트에서는 시작 workspace가 속한
기준 workspace(anchor) 그룹을 맨 위에 두고, 다른 역할 그룹은 기준 workspace ID 순으로
표시합니다. 원격 호스트는 이름순으로 표시합니다. 각 그룹은 `기준 workspace 라벨 · N`으로
그룹 전체의 에이전트 수를 표시하며, 연결된 workspace는 들여쓴
`workspace 라벨 (worktree) · N` 하위 행으로 표시합니다. 실제 시작 workspace에만
`· current`를 붙이므로 연결된 workspace에서 열었다면 해당 하위 행에 붙습니다.
그룹 안의 에이전트는 별칭·terminal ID 순으로 정렬합니다. 로컬 라벨은 Herdr 스냅샷에서
가져오고 없으면 ID를 사용합니다. 역할 범위 메타데이터가 없는 이전 peer는 workspace별
표시를 유지합니다. ID가 없으면 `No workspace`로 표시하고 마지막에 배치합니다.
그 아래 **Other repositories** 구역에는 로컬 호스트와 등록된 피어의 다른 저장소를
호스트 → 저장소의 짧은 이름 → 에이전트 순서로 표시합니다. 짧은 이름은 저장소 경로의
마지막 부분이며, 길면 화면 너비에 맞게 줄입니다. 들여쓴 저장소 행에는 에이전트 수도
표시하며, 작업 공간 행처럼 선택할 수 없습니다. 스크롤할 때 공간이 허용되면 호스트와
열 이름, 작업 공간 또는 저장소 이름을 유지합니다. 피어마다 저장소 전체를 한 번
조회하여 두 구역을 채웁니다. 다른 저장소의 에이전트를 선택해도 창을 연 저장소는
바뀌지 않으며, 사용자 메일도 창을 연 저장소를 발신 문맥으로 사용합니다.
DIRECT 전송 이력도 창을 연 저장소에 남기며, 대상 스냅샷에는 실제 수신 저장소를
유지합니다. 창을 연 저장소가 없는 전체 저장소 화면에서는 수신 대상의 저장소를
발신 문맥으로 사용하되, 화면 범위는 바꾸지 않습니다.

TURN은 선택 표시와 상태 기호로 시작하며, 제목은 상태 단어 위에 맞춥니다.
ALIAS, ROLE, SUMMARY는 왼쪽에, MAIL, RX, PHN, EMU, SRV는 가운데에 정렬합니다.
개수를 알 수 없으면 `?`, 확인된 개수가 0이면 `·`를 표시합니다. 0은 선택하지 않은
행에서만 흐리게 표시하고, 0이 아닌 MAIL 개수는 굵게 표시합니다. 선택한 행은
**행 전체에 공통의 밝은 배경색과 대비가 높은 글자색**을 사용합니다. 열 사이 여백에도
같은 색을 적용하며 상태 기호와 단어는 굵게 표시합니다. 선택하지 않은 행의 상태에는
의미에 따른 색을 유지하고, 색상을 사용하지 않을 때는 선택한 행 전체를 반전합니다.

열에는 **상태 기호와 단어**, **별칭**, **MAIL**(읽지 않은 메일 수),
**RX**(native 수신기 표시: 준비됨 `✓`, 없음 `⚠`, 알 수 없음 `?`), **ROLE**,
리소스 개수와 남은 너비를 사용하는 **phase · summary**를 표시합니다. TURN,
ALIAS, MAIL은 항상 표시합니다. RX를 먼저 추가하고, 내용 너비를 16칸 이상
확보할 수 있으면 SUMMARY를 추가한 뒤 ROLE, PHN/EMU/SRV 순으로 추가합니다.
열을 추가할 때 SUMMARY는 최소 16칸, SUMMARY가 없으면 ALIAS는 최소 8칸을
유지합니다. ALIAS의 기본 너비는 가장 긴 별칭에 맞추되 8~18칸으로, ROLE은 가장
긴 역할에 맞추되 4~8칸으로 제한합니다. SUMMARY가 없으면 ALIAS가 남은 너비를
사용합니다. 내부 너비 30칸에서는 TURN에 선택 표시와 상태 기호만 표시하고 제목은
비워 둡니다. 38칸에서는 상태 단어까지 표시합니다. 76칸에서는 SUMMARY를 유지하고,
100칸 이상에서는 모든 열을 표시합니다. 제목을 단어 중간에서 자르지 않습니다.
ALIAS에 필요한 너비를 확보한 뒤 SUMMARY를 늘리고, 요약은 끝에서만 줄입니다.
전체 요약은 Detail에서 볼 수 있습니다. 전송 결과는 ALIAS나 SUMMARY 안에 표시하며
길면 줄입니다. 연결이 끊긴 호스트는 마지막 조회 결과에 stale 표시를 붙이고
MAIL을 `?`로 표시하며, 종료됐다고 판단하지 않습니다.

Threads는 기존의 **전체 너비를 굵게 표시하고 단어에만 밑줄을 긋는 열 헤더**와
**선택 행 전체의 배경색**을 사용합니다. 색상을 사용하지 않을 때는 행 전체를 반전합니다.
선택하지 않은 행에서는 상태·종류·전송 작업 라벨에 의미에 따른 글자색을 적용하고,
제목과 참여자는 기본 글자색을 유지합니다. 선택한 행에서는 밝은 배경과 대비를
확보하도록 라벨을 기본 선택 글자색과 굵은 글씨로 표시하며, 기호와 단어는 모두
유지합니다. 각 항목은 두 줄로 표시하며, 마우스로 선택할 수 있는 범위도 기존과
같이 행 전체입니다.

Threads에는 창을 연 저장소가 대화의 시작 저장소이거나 발신·수신에 참여한 대화가
표시됩니다. 다른 저장소에서 보낸 메시지는 목록과 메시지 이력의 발신자 뒤에
`(repo NAME)`을 붙입니다. NAME은 저장소의 짧은 이름이며 최대 24칸으로 줄입니다.

Threads는 **하나의 목록과 스크롤 영역** 안에서 `Active (개수)`와 `Handled (개수)`로
나뉩니다. 진행 중이거나 확인이 필요한 Active 항목을 위에 표시하고, 빈 행과 구분선을
둔 뒤 처리 완료된 Handled 항목을 아래에 표시합니다. 빈 그룹에는 제목이나 여백을
만들지 않으며, 각 그룹 안에서는 기존의 갱신·최근 순서를 유지합니다. 처리 완료된
행은 흐리게 표시하되 선택하면 원래의 높은 대비를 유지합니다. 제목과 빈 행은 선택하거나
실행할 수 없습니다. 방향키, 페이지 키와 휠은 구분선을 넘어 항목 사이를 이동하며,
새로고침으로 순서가 바뀌어도 클릭한 항목의 ID를 기준으로 동작합니다.

보관된 메시지가 하나 이상이고 **모든 메시지가 `handled` 상태이거나 발신 측 정리
기록(dismissal)이 있는 native 스레드만** Handled로 옮깁니다. 정리는 발신 측의
확인 필요 상태를 끝낼 뿐, 전달이나 수신자의 작업 완료를 뜻하지 않습니다.
원래 상태인 `undeliverable`은 그대로 유지됩니다. 최신 메시지가 처리·정리됐어도
이전 메시지가 대기, 전달 후 미처리, 불확실한 claim, 미정리 실패 상태라면 Active에
남습니다. 새 답장은 같은 ID와 선택을 유지한 채 Active로 돌아옵니다. 철회는
전송 취소이므로 `withdrawn`도 Active에 유지합니다. 직접 입력과 표시 중인 대기·실패
OUTBOX 작업도 항상 Active에 남습니다. 접수, 전송 성공, claim ID나 운영자 증거만으로
완료를 추정하지 않으며, `delivering`은 미확정 상태입니다. Agent Detail의 개수에도
같은 기준을 적용하고, 정리 기록이 있으면 완료 합계를 `handled/dismissed`로 표시합니다.

| Threads 표시 | 의미와 색상 |
| --- | --- |
| `. pending`, `. queued` | 전송 대기이며 노란색으로 표시합니다. |
| `> submitting` | 직접 입력을 제출 중이며 노란색으로 표시합니다. |
| `? UNCERTAIN delivering` | 아직 확정하지 못한 native claim이며 노란색으로 표시합니다. 전달 완료를 뜻하지 않습니다. |
| `+ delivered`, `+ DIRECT accepted` | 기록된 native 전달과 별개의 직접 입력 접수이며 초록색으로 표시합니다. |
| `= handled` | 기록된 처리 완료 상태이며 청록색으로 표시합니다. |
| `x dismissed` | 발신 측에서 사유와 함께 정리했으며 흐리게 표시합니다. **전달·수신자 처리 완료가 아닙니다.** |
| `! failed`, `! undeliverable` | 실패이며 빨간색으로 표시합니다. |
| `- withdrawn` | 철회됐으며 흐리게 표시합니다. |
| `? DIRECT unknown` | 직접 입력 접수 여부가 불확실하며 노란색으로 표시합니다. |
| `i fyi`, `! action` | 메일 종류이며 각각 청록색과 노란색으로 표시합니다. |
| `> direct` | 사용자의 터미널 직접 입력 증거이며 청록색으로 표시합니다. **native 메일이 아닙니다.** |
| `> message`, `< receipt`, `# setting`, `- withdraw` | OUTBOX의 전송 작업 종류이며 청록색으로 표시합니다. FYI/action 메일 종류를 뜻하지 않습니다. |

기호는 모두 한 셀을 차지하는 ASCII 문자이며 항상 상태·종류 이름을 함께 표시합니다.
기록된 행 데이터만 반영하므로 보기나 선택으로 상태를 만들지 않습니다. 스레드 안에
미확정 `delivering` claim이 하나라도 있으면 이후 메시지의 상태와 무관하게 불확실성
경고를 유지합니다. OUTBOX 접두사, 대상과 오류도 유지하며 전송 작업 라벨로 본문의
메일 종류를 추측하지 않습니다. Detail에서도 같은 상태·종류·전송 작업 표시와
운영자 증거·native 증거의 구분을 볼 수 있습니다. 직접 입력의
접수는 native 전달·처리 완료를 뜻하지 않습니다. `?` 도움말에도 이 범례를 표시합니다.

정리된 메시지의 Detail에는 기술 정보 모드를 켜지 않아도 정리한 에이전트와
터미널, 시각, 사유, 보존된 전달 상태와 이전 실패 사유가 표시됩니다.
이전 실패 사유는 이력으로 보존하며, 현재 보류 중이라는 HOLD 표시는 붙이지 않습니다.
정리하지 않은 메시지가 실제로 보류 중이라면 기존 HOLD 표시를 유지합니다.
처리 완료와 정리가 섞인 스레드도 목록에 dismissed로 표시합니다. 정리는 원본 호스트의
로컬 장부에만 기록되며 수신 확인이나 원격 처리 완료로 전파되지 않습니다.
권한이 있는 발신자 또는 같은 역할 그룹의 main이 CLI에서
`mail dismiss --message UUID --reason TEXT`로 실행합니다. TUI에는 정리 단축키나
새 변경 동작을 추가하지 않습니다.

상태 색상은 보조 표현입니다. **working은 노란색**, **idle은 기본색**,
**done은 초록색**, **blocked는 빨간색**으로 표시하며, **unknown·stale은 흐리게**
표시합니다. `● working`, `○ idle`, `✓ done`, `! blocked`, `? unknown`,
`~ stale`처럼 기호와 단어를 함께 유지합니다. `NO_COLOR`가 있으면 값이 비어 있어도
색상을 끄지만 기호, 단어, 굵기, 흐림과 선택 행의 반전 표시는 유지합니다.

Detail과 다른 일반 텍스트 패널에는 왼쪽 안쪽 여백을 한 칸 둡니다.

Detail은 마지막으로 포커스를 둔 목록의 선택 항목을 자동으로
미리 보여 줍니다. 전체 요약과 상태 갱신·관찰 시각을 구분하여 현지 시간과 경과
시간으로 표시합니다. **Detail은 읽기 전용이며, 보기만 해서는 ACK·전달·처리·복구가
일어나지 않습니다.** Threads에는 메시지 이력, 직접 입력 결과와 대기·실패한
OUTBOX가 포함됩니다. `delivering`은 **UNCERTAIN**으로 표시합니다.

보내거나 받은 메일을 읽으려면 `Tab`으로 **Threads**에 포커스를 옮겨 스레드를
선택한 뒤 `Space`를 눌러 뷰어를 엽니다. 기존 **Detail**에서도 메시지를 읽을 수 있습니다.
에이전트를 선택하면 메시지 본문 대신 상태와 리소스를 보여 줍니다. 에이전트 Detail의
Unread 다음에는 **Mail** 구역이 있으며, 현재 불러온 스레드 중 해당 에이전트가 참여한
Active·Handled 개수와 `Read: Tab → Threads, select a thread, Space opens it` 안내를
흐리게 표시합니다. 해당 스레드가 없으면 `No threads with this agent yet`를 표시합니다.
Devices와 Servers는 그 아래에서 계속 확인할 수 있습니다.

메시지 Detail은 **메시지 i/N, 현지 시각·경과 시간, 기록된 발신자 → 수신자**를
짧은 헤더로 보여 준 뒤 종류·상태 요약과 일반 밝기의 본문을 표시합니다.
native 이력과 번호는 오래된 메시지부터 최신 메시지 순서를 유지하지만, 새 스레드를
선택하면 **최신 메시지 헤더**에서 읽기 시작합니다. 최신 메시지가 짧으면 스크롤 범위에
맞춰 마지막 페이지를 표시합니다. 이전 메시지는 Detail에서 PgUp이나 Home으로 읽습니다.
Threads의 제목은 최신 메시지의 제목이나 본문 첫 줄을 미리 보여 줍니다.
긴 대상 라벨은 읽기용 헤더에서만 줄입니다.
좁은 패널에서는 메시지 번호·시각 때문에 발신자와 수신자 방향이 사라지지 않도록
대상을 별도 헤더 행에 표시하며, 번호·시각 행은 짧게 표시할 수 있습니다.
정확한 전체 값은 기술 정보에 남습니다. 종류·상태, 접수와 전송 경고는 잘라내지 않고
줄바꿈하여 의미를 보존합니다. 제목과 UUID로 첫 본문 앞의 공간을 채우지 않습니다.
native와 DIRECT 본문은
원래 문단과 실제 개행, 문자 그대로의 `\n`을 보존하고 패널 너비에 맞춰 줄바꿈합니다.
OUTBOX는 대화 답신이나 native ACK가 아니라 전송 작업으로 유지합니다.
message 작업의 중첩된 message payload에 실제 문자열 본문이 있을 때만 본문을 표시합니다.

기술 정보는 기본으로 접혀 있습니다. NAV에서 Detail에 포커스를 두고 `t`를 누르면
전체 기록 원본, 식별자와 정확한 대상, claim과 이전 에이전트·세대, 경로, 확인 출처,
증거와 오류를 흐리게 표시합니다. 기술 정보를 접어도 미확정 `delivering`의
UNCERTAIN 경고, 운영자 확인의 **NOT native ACK**, DIRECT 접수가
**native 전달·처리 완료와 다르다**는 안내는 상태 요약에 남습니다.
펼치거나 접으면 최신 native 메시지 헤더로 돌아갑니다. 다른 항목을 선택하면 기술 정보를
접고 최신 헤더에서 시작합니다. 메시지가 하나인 스레드와 DIRECT·OUTBOX는 기존처럼 맨
위에서 시작합니다. 같은 항목을 새로고침하면 펼침 상태와 읽던 위치를 유지하며, 본문이나
줄바꿈이 바뀌면 유효한 범위 안으로 위치를 조정합니다. 새 메시지가 도착했을 때 이전
최신 헤더 위치나 그 헤더가 있는 마지막 페이지에 그대로 있었다면 새 최신 헤더로
이동합니다. 다른 곳으로 스크롤했다면 읽던 위치를 유지합니다.

기존 읽기 전용 안내행에 현재 보이는 행 범위·전체 행 수, 위·아래에 내용이 남았을 때의
`↑more`·`↓more`, 기술 정보 토글 상태를 함께 표시합니다. 좁은 패널에서는 문구를
줄이되 ACK하지 않는다는 안내, 읽기 위치와 토글 키를 유지하며 별도 본문 행을 쓰지
않습니다. 행 수에는 줄바꿈한 헤더·본문 문단과 펼친 기술 정보가 포함됩니다.
PgUp/PgDn은 실제 본문 표시 행 수에서 한 행을 뺀 만큼 이동합니다. 최소 이동량은
한 행이며, 일반적인 페이지 사이에는 한 행이 겹칩니다. 방향키·Home/End·휠·화면 크기
변경·기술 정보 토글에도 같은 스크롤 범위를 적용합니다.

### 인라인 입력과 답장

Agents에서 행을 선택하고 `Enter`를 누르면 Detail 아래에 전체 너비의 입력창을
열고 수신자와 선택한 종류를 표시합니다. 처음에는 `ACTION`입니다. 단일 영역 모드에서는 포커스가 있는
영역 아래에 표시합니다. 본문 배치를 정하기 전에 입력창 공간을 확보하므로,
입력창을 열거나 높이가 늘어나면 stacked에서 single 모드로 바뀔 수 있습니다.
UI에서 보내는 메일은 항상 발신자가 `sender=user`이며 제목은 없습니다.
native 수신기가 없으면 경고하지만 메일함으로 전송할 수 있습니다.
stale 수신자에게는 입력창을 열 수 없습니다.
Threads에서 `Enter`를 누르면 같은 입력창으로 최신 메시지에 답장합니다.
수신자를 현재의 stale이 아닌 에이전트로 찾지 못하면 오류를 표시합니다.
답장이나 보존한 초안을 다시 여는 경우를 포함해 새 입력창은 매번 `action`으로
초기화합니다. `Ctrl+G`로 해당 입력창의 `action` / `fyi`를 전환하고 선택한 종류를
명시해 전송합니다. CLI 기본값은 계속 `fyi`입니다. 수신자가 행동하거나 답하거나
작업을 이어가야 하면 action을 선택하세요. 조건을 충족하는 action은 신속히
깨웁니다. FYI는 약 10~15분 뒤 묶어서 참여 중인 유휴 OMP를 깨웁니다. 수신자 호스트의
로컬 enqueue 시각으로부터 최소 600초를 기다리며, 실제 깨우기는 이후 일반 이벤트나
5분 간격 안전 확인에서 기존 조건에 따라 이루어집니다. 기존 queued 메일도
마이그레이션 없이 적용합니다. 턴 진행 중 도착한 FYI는 로컬 enqueue 시점에 최신 `working`
상태가 확인된 경우 그 턴 직후 전달합니다. 두 경로 모두 기존 깨우기 안전 조건을
적용합니다. action의 깨우기에는 아직 600초가 지나지 않은 FYI도 포함할 수 있으며,
FYI만 있을 때는 작업에 영향을 주는 경우에만 답하면 됩니다.

- `Enter`는 검토나 확인 단계 없이 메일을 즉시 전송합니다. 빈 본문은 전송하지
  않고 오류를 표시합니다.
- `Shift+Enter`는 줄을 바꿉니다. 메일함이 **kitty 키보드 프로토콜**을 요청하므로
  kitty 호환 터미널에서는 herdr를 통해서도 동작합니다. 이 프로토콜을 협상하지
  못하는 Moshi/mosh에서는 **`Alt+Enter`를 대안으로 사용하세요.** `Ctrl+J`는
  줄바꿈 키가 **아닙니다**. `HAM_MAILBOX_NO_KITTY=1`로 프로토콜 요청을 끌 수 있습니다.
- 숫자, `q`, `?`, `:`, `/` 등 인쇄 가능한 문자는 본문에 입력됩니다.
  방향키, `Home`·`End`, `Backspace`, `Delete`로 편집하고 `↑`·`↓`로 줄을 옮깁니다.
- `Ctrl+D`는 **터미널 직접 입력**으로 전환하거나 되돌립니다. 직접 입력에서
  `Enter`를 누르면 기본 선택이 Cancel인 확인창이 열립니다. `Tab` 또는 `←`·`→`로
  버튼을 고르고 `Enter`로 선택한 동작을 실행합니다.
- `Esc`는 입력창을 닫되 수신자와 답장별로 본문과 커서를 보존합니다.
  `Ctrl+R`은 입력창을 유지한 채 새로고침합니다. 입력 중 `F1`은 도움말을 열며,
  도움말을 닫으면 같은 입력창으로 돌아옵니다.

성공하면 입력창을 닫고 에이전트 행에 결과를 표시하며, 빠른 전송 오버레이도 닫습니다.
메일함 대기열에 넣은 뒤에는 `Queued · recipient · ACTION|FYI` 형식으로 Herdr 알림을
비동기로 요청합니다. 전달 완료를 뜻하지 않으며, 알림이 실패해도 대기열에 넣은 결과는
성공으로 유지합니다. 제출한 뒤 바뀌지 않은 초안만 지우므로 결과를 기다리며
새로 편집한 내용은 보존합니다. 실패하면 본문을 입력창에 남기고 오류를 표시합니다.

### Agents의 Main 단축키

NAV에서 메일함을 연 pane과 같은 저장소·workspace 역할 그룹에 속한 로컬 활성
에이전트를 선택하고 `m`을 누릅니다. 확인창에는 대상과 역할 그룹이 표시되며 처음에는
Cancel이 선택됩니다. Confirm을 선택하면 Settings와 같은 서비스로 terminal을
main으로 고정하고 저장 직전에 현재 범위와 대상을 다시 검사합니다.
명시적으로 고정된 행에서 `m`을 누르면 고정 해제를 확인합니다. 해제 요청은 고정된
terminal을 함께 보내며, 저장 전에 다른 Mailbox가 고정을 바꿨다면 `main_pin_changed`
오류로 실패하고 새 고정은 그대로 둡니다. 해제하더라도 역할
모드는 꺼지지 않습니다. `auto`에서는 기존 자동 main이나 유일한 후보가 main이 될 수
있습니다. 자동으로 선출된 main은 명시적인 고정이 아니므로 `m`을 누르면 고정합니다.
Settings의 선택 목록과 `m` 단축키 동작은 그대로 유지됩니다. 설정 변경 CLI는 없습니다.

### FYI 즉시 전달

대기 중인 일반 FYI는 보통 FYI 지연(약 10~15분)을 기다립니다. 다음 두 방법은 사용자의
명시적 요청에 따라 **FYI 지연과 입력 유휴 대기 시간**을 생략합니다. 메일을 쓰거나
에이전트에 입력하지 않으므로 요청 자체는 모델 토큰을 쓰지 않습니다. 모델이 하는 일은
전달된 묶음을 읽는 에이전트 자신의 턴뿐입니다.

- **메일함:** NAV의 Agents에서 로컬 에이전트를 선택하고 `f`를 누릅니다. 결과는 상태 줄과
  행의 짧은 태그로 표시합니다.
- **Pane 동작:** **HAM: Deliver queued FYI now**(`herdr.agent-messenger.fyi-now`, context
  `pane`)는 포커스된 pane을 대상으로 하며 Herdr 알림으로 결과를 알립니다.
  `~/.config/herdr/config.toml`에 연결하세요. `prefix+f`는 Herdr 0.9.5 기본 키와 겹치지 않습니다.
  두 번째 항목은 다른 HAM 바인딩처럼 한글 자판용입니다.

  ```toml
  [[keys.command]]
  key = "prefix+f"
  type = "plugin_action"
  command = "herdr.agent-messenger.fyi-now"
  description = "HAM: deliver queued FYI now"

  [[keys.command]]
  key = "prefix+ㄹ"
  type = "plugin_action"
  command = "herdr.agent-messenger.fyi-now"
  description = "HAM: deliver queued FYI now (hangul)"
  ```

  추가하기 전에 사용 중인 설정에 `prefix+f`가 이미 있는지 확인하세요. 두 방법 모두 로컬
  전용이므로 다른 호스트의 에이전트에는 그 호스트의 메일함을 사용하세요.

요청은 해당 에이전트의 대기 중이고 보류되지 않았으며 hop 한도 이내인 FYI에 로컬
`deliveries.fyi_turn_end` 플래그를 설정합니다. 이미 플래그가 설정되어 있어도 유효한
요청을 할 때마다 상태 로그에 `fyi_now` 행을 추가하고 입력 유휴 대기 생략 권한을
**600초**로 갱신한 뒤 로컬 벨을 울립니다. 이 권한은 요청 당시의 메시지 ID와 수신자의
세대·세션에 한정됩니다. action 메일, 보류·처리된 메일, 다른 에이전트는 건드리지 않습니다.
턴 진행 중 enqueue되어 자동으로 설정된 플래그는 FYI 지연만 생략하며 입력 유휴 대기는
생략하지 않습니다.

이 권한은 요청에 포함된 메시지의 전달이 확인되거나 600초가 지나면 소멸합니다.
자연스러운 OMP 턴이나 hook을 통한 수신도 전달에 포함됩니다. 적용되지 않은 것이 확실한
claim을 해제하면 권한은 전달 또는 만료 때까지 유지되지만, 적용 여부가 불확실한 claim이
있으면 다른 깨우기는 계속 차단됩니다. 이후 도착한 무관한 메일이나 교체된 세션은
이 권한을 사용할 수 없습니다. 다시 요청하면 권한을 갱신합니다. 권한이 만료되거나
소멸해도 메시지의 FYI 지연 생략 플래그는 유지됩니다.

생략하는 것은 OMP의 입력 유휴 타이머 또는 Claude·Codex의 연속 유휴 시간 조건뿐입니다.
참여 여부, `idle`/`done` 턴, 빈 OMP 편집기, 유휴 런타임, pending 메시지·continuation·retry
hold 없음, 다른 claim 없음, 보류되지 않은 메일, 시간당 한도와 hop 한도, 기본 **60초**의
메시지 모으기 대기 시간은 유지됩니다. claim 시점과 OMP enqueue 직전에 권한과 조건을
다시 확인합니다. 작업 중인 에이전트에는 `after_turn`을 반환하며 턴을 중단하거나 즉시
전달을 약속하지 않습니다. Claude·Codex 워커는 입력 중인 초안을 볼 수 없으며 연속 유휴
시간 조건을 생략해도 편집기 내용을 볼 수 있게 되는 것은 아닙니다.

Claude·Codex에서는 먼저 세션을 깨울 수 있는지 확인하고 필요하면 워커를 시작합니다
(자동 시작이 꺼져 있지 않은 경우). `worker_start_failed`는 워커를 시작하지 못했다는
뜻입니다. 한 번의 깨우기에는 최대 8개 메시지와 8 KiB까지 담습니다. 남은 메시지는
사용자가 다시 요청하지 않으면 일반 입력 유휴 조건에 따라 다음 깨우기에서 전달합니다.
스키마나 프로토콜 버전은 바뀌지 않습니다. OMP에서 입력 유휴 대기를 생략하려면
갱신된 확장이 활성화되어 있어야 합니다. 상태 줄은 긴 에이전트 이름보다 요청과 남은
필수 조건을 먼저 보여 주므로 80열에서도 핵심 내용을 읽을 수 있습니다.

| 결과 | 메시지(형태) |
| --- | --- |
| `requested` | OMP: `N FYI requested; quiet skipped; empty prompt + idle required.` Claude/Codex: `N FYI requested; quiet skipped; idle turn required.` |
| `after_turn` | `N FYI after turn; quiet skipped; ... required.` 뒤에 에이전트 이름과 턴 상태를 표시 |
| `hourly_limit` | `N FYI marked, wake limit reached (4/4 this hour); next wake possible HH:MM` |
| `nothing_queued` / `only_held` | 전달할 FYI가 없으며 대기 중인 action 수나 보류 수를 함께 표시 |
| `not_participating` | 모드가 off이거나 manual 비구성원이면 HAM이 깨우지 않고 FYI는 다음 턴까지 대기 |
| `no_receiver` | OMP 확장 미등록, 등록된 hook이 없는 Claude, 지금 깨울 수 없는 Claude/Codex(`Claude cannot be woken right now (REASON: detail)`, 아무것도 표시하지 않음), 그 밖의 클라이언트(`inbox read`만 가능) |
| `not_agent` | 포커스된 pane이 HAM 에이전트가 아님(pane 동작에서만) |
| 원격 에이전트 | 로컬 전용이므로 그 에이전트 호스트의 메일함 사용 |

### Settings

NAV에서 `s`를 누릅니다. `↑`·`↓` 또는 `j`·`k`로 행을 고릅니다.
행을 클릭하면 선택하고, 선택한 행을 다시 클릭하면 `Enter`처럼 동작합니다.
`Esc`로 설정창을 닫으면 아직 저장하지 않은 변경을 버립니다.

Mode와 Thresholds는 저장소 전체에 적용합니다. Main·Members에는 Mailbox 시작 pane의
역할 그룹을 해석한 기준 workspace를 표시합니다
(`Main (workspace ANCHOR @ HOST) · role group` /
`Members (workspace ANCHOR @ HOST) · role group`). 원래 workspace는
`HERDR_HAM_OPENER_PANE_ID`로 찾으며, 범위는
`(repo_id, 정규 로컬 호스트, anchor_workspace_id)`입니다. 선택한 에이전트를 따라 바뀌지
않습니다. 모든 저장소 보기에서도 기존 저장소 선택 방식을 유지하며, 저장소를 하나로
정할 수 없으면 설명과 함께 설정을 비활성화합니다. 역할 설정은 해당 호스트에만 저장하고
변경은 기준 workspace에 저장합니다. 연결된 workspace의 기존 설정은 그룹에 속한 동안
무시하지만 변경 없이 보존하며, 분리되면 다시 적용합니다. `repo show`의 `workspace_id`는
기준 workspace, `requested_workspace_id`는 원래 workspace입니다.
시작 pane이 아직 원장에 없으면 새로고침에서 가져온 Herdr pane 스냅샷으로
workspace를 찾습니다. 시작 pane이 닫혔다면 Mailbox 자체의 workspace를 사용합니다.
workspace를 찾을 수 없어도 Main·Members만 비활성화하며, 선택한 저장소의
Mode·Thresholds는 계속 조회하고 저장할 수 있습니다.

- **Mode (repo-wide):** `Enter`로 각 선택지의 의미가 표시된 **PICK** 목록을 엽니다.
  `↑`·`↓`로 고른 뒤 `Enter`를 누르거나 항목을 클릭하면 바로 저장합니다.
  mode 행에서 `←`·`→` 또는 `h`·`l`로 값을 바꾼 뒤 `Enter`로 저장할 수도 있습니다.
- **Main (workspace ANCHOR @ HOST) · role group:** `Enter`로 같은 저장소·정규 호스트의
  역할 그룹 전체에서 활성 에이전트와 `(none)`을 담은 **PICK** 목록을 엽니다.
  연결된 workspace의 에이전트도 포함합니다. 현재 값은 `●`로 표시하며 `Enter`나 클릭으로 저장합니다.
- **Members (workspace ANCHOR @ HOST) · role group:** `Enter`로 그룹 전체의 **CHECK**
  목록을 엽니다. `Space`나 항목 클릭으로 체크를 바꾸고 `Enter`로 저장합니다.
  비활성 에이전트나 그룹 밖의 대상을 새로 지정할 수 없으며 서비스도 이를 거절합니다.
  기존 구성원이 그룹 밖으로 이동하면 그 그룹의 역할을 받지 않습니다.
- **임곗값(repo-wide):** `←`·`→`, `-`·`+` 또는 `◀`·`▶` 클릭으로 값을 조정합니다.
  `idle_minutes`는 1, `coalesce_seconds`는 5, `wakes_per_hour`와 `max_hop`은
  각각 1씩 바뀌며 범위는 0~10000입니다. 저장 전에는 `unsaved`로 표시하고
  `Enter`로 저장합니다. 대기 중인 변경이 없을 때 `Enter`를 누르면 숫자만
  입력할 수 있는 선택적 입력창을 엽니다. 목록이나 숫자 입력창에서 `Esc`를
  누르면 해당 편집을 취소합니다.

마우스 휠로 목록이나 설정 메타데이터를 스크롤합니다.
설정 범위는 `Target: repository REPO_ID · workspace ANCHOR @ HOST`로 표시하며,
시작 workspace는 별도로 표시합니다. main·members 변경은 기준 workspace에 저장합니다.
선택한 Agents 행의 대상이 활성 상태이며 시작 pane의 역할 그룹 안에 있을 때만 `m`으로 main을 지정하고
`Space`로 수동 구성원에 넣거나 뺄 수 있습니다. 이 두 단축키는 기본 선택이
Cancel인 확인창을 그대로 거칩니다. Home, main source(`pinned`·`auto`·`none`), effective main(고정이든 자동이든 실제로 결정된 main), fallback candidate(`computed main`: 고정이나 기존 자동 main이 없을 때만 쓰는 유일한 후보), 버전·origin, 전파
대기와 충돌 정보는 읽기 전용이며 저장소 단위 설정만 전파합니다. 요청·snapshot·저장
결과를 저장소·호스트·workspace 전체 범위에 연결하므로 다른 범위의 결과가
현재 설정을 덮어쓰지 못합니다. 설정은 내부 서비스를 사용하며 에이전트의
`repo show`는 호출자의 범위를 보여 주는 읽기 전용 명령입니다.

설정은 한 번에 하나만 저장합니다. 해당 행에 **Saving settings**를 표시하고
저장이 끝나면 결과나 오류를 같은 행에 표시합니다. 추가 저장은 대기열에 넣지
않고 거절하며, 거절된 편집 내용은 보존합니다. 화면 이동은 계속 동작합니다.
확정 결과를 즉시 표시하고 오래된 조회 결과로 덮어쓰지 않습니다.
`PgUp`·`PgDn`으로 긴 메타데이터와 생략 없이 줄바꿈한 충돌 기록을 스크롤하며,
NAV의 `e`로 전체 진단 정보를 봅니다.

### 접수 결과와 불확실한 전달

메일은 일반적인 native 수신 규칙을 따릅니다. 직접 입력은 정확히
`Message from user (HAM):` 헤더를 붙여 검증된 터미널 전송 경로로 제출합니다.
수신자의 작업에 끼어들 수 있으므로 경로를 명시적으로 선택하고 확인해야 합니다.
HAM은 `via=direct`, `submitting`을 기록한 뒤 `accepted`·`unknown`·`failed`를
기록합니다. 이는 native의 `delivered`·`handled` 수신 확인이 아닙니다.
Threads에서 결과를 확인하세요. 중단된 `submitting`이나 `unknown`은 다시 전송하기
전에 직접 확인해야 하며, HAM은 자동 재전송하지 않습니다.

Threads의 `w`는 로컬에서 보낸 철회 가능한 메일을 철회하고, `t`는 선택한 OUTBOX를
같은 ID로 재시도합니다. 두 동작 모두 정확한 대상을 확인해야 합니다.
불확실한 native claim은 세션이 바뀌어도 보류합니다. `a`는 적용, `n`은 미적용을
확인합니다. 두 동작 모두 먼저 비어 있지 않은 운영자 증거를 입력한 뒤, 정확한
메시지·claim ID, 이전 에이전트, generation과 현재 상태가 표시된 확인창을 거칩니다.
기본 선택은 Cancel이며 `Tab` 또는 `←`·`→`로 버튼을 고르고 `Enter`로 실행합니다.
`Esc`는 취소합니다. 적용 확인은 이전 claim에 대한 **사용자의 수동 확인**이지
native runtime journal의 증거, 모델의 이해나 작업 처리 완료가 아닙니다.
미적용 확인은 해당 claim만 해제하며 그 자체가 재전송하지는 않습니다.

키 입력 루프의 입력 대기 시간은 기존처럼 100ms로 유지하지만, 화면은 이벤트가
발생할 때만 다시 그립니다. 키 입력과 터미널 크기 변경, 작업 시작과 완료, 전송 결과
태그의 만료가 다시 그리기를 요청합니다. 화면에 변화가 없으면 입력 대기 시간이
지날 때마다 다시 그리지 않습니다. 화면에 표시된 상대 시간은 표시 단위가 바뀔 때
갱신합니다. 1분 미만은 초마다, 1시간 미만은 분마다, 1일 미만은 시간마다,
그 이후에는 일마다 갱신합니다. 상대 시간만 갱신할 때는 실제 시계의 정수 초
경계에 맞춰 한 번에 처리하므로, 소수점이 있는 타임스탬프가 여러 개 있어도
초당 여러 번 다시 그리지 않습니다. 상대 시간 표시는 경계보다 최대 1초 늦게
바뀔 수 있습니다. 타임스탬프가 없거나 상대 시간이 현재 보이는 Detail 영역 밖에
있으면 시간 갱신을 예약하지 않습니다. 키 입력과 새 메일 처리는 이 시간 갱신을
기다리지 않습니다.

로컬 board bell은 기존처럼 1초마다 확인하며, bell이 바뀌지 않으면 로컬 스냅샷을
다시 요청하지 않습니다. 로컬 스냅샷은 계속 실행되는 자식 프로세스를 재사용하므로,
bell이 바뀔 때마다 새 프로세스를 시작하지 않습니다. 각 스냅샷은 원장, 메일,
에이전트 상태, 설정, 기기 점유 행을 새로 읽습니다. 호스트 자원 탐색 원본과
Herdr pane 메타데이터만 해당 Mailbox 인스턴스 안에서 30초 동안 캐시하며, 사용자가
직접 새로 고치면 이 캐시를 건너뜁니다. 원장에서 에이전트의 마지막 HAM 라벨이
바뀌면 호스트 자원을 다시 탐색하지 않고 Herdr 메타데이터만 일찍 갱신합니다.
따라서 캐시된 이전 HAM 라벨을 사용자가 수정한 라벨로 잘못 판단하지 않습니다.
스냅샷을 이미 읽고 있다면 취소하거나 프로세스를 재시작하지 않고, 캐시를 건너뛰는
후속 조회를 한 번 예약합니다.

원격 상태도 기존처럼 키 입력 루프 밖에서 실행 시간을 제한한 별도 프로세스로
30초마다 조회합니다. Mailbox를 닫으면 로컬 스냅샷 프로세스를 포함해 자신이 시작한
작업 프로세스만 정리하며, 이 조회는 모델 턴을 만들지 않습니다. 표시 셀 너비를
고려하는 텍스트 도구로 한글 입력, 자르기와 크기 변경을 처리합니다. `NO_COLOR`가
있으면 값이 비어 있어도 색상을 끄지만, 라벨 등 색상 이외의 상태 표시는 유지합니다.

### 기기와 서버 표시

Agents 영역은 RX, SUMMARY, ROLE을 배치한 뒤 공간이 허용되면 **PHN**, **EMU**,
**SRV** 열에 각각 휴대전화, 에뮬레이터, 서버 개수를 표시합니다. 각 열은 내용 너비가
세 칸이며, 열 사이는 공백 두 칸으로 띄웁니다. 색상 설정과 관계없이 ASCII 제목을
사용하고 제목과 값을 가운데에 정렬합니다. 리소스 이모지는 사용하지 않습니다.
개수가 0이면 `·`를 표시하되 선택하지 않은 행에서만 흐리게 표시하고, 0이 아니면
일반 밝기의 숫자를 표시합니다. 기기 정보가 없으면 PHN과 EMU에 `?`를,
서버 정보가 없으면 SRV에 별도로 `?`를 표시합니다.
호스트 그룹 라벨에는 대상 리스너가 없는 Serve 경로, 소유자가 없는 Serve 대상,
stale 기기를 `dead 1 · unowned 1 · stale-dev 1`처럼 표시하며 개수가 0인 항목은
생략합니다. 호스트 자원 필드가 없으면 `?`, 탐색 오류가 있으면 `!`를 표시합니다.
공간이 부족하면 에이전트 수를 유지하고 발견 사항부터 줄입니다.

Agent Detail에는 **Devices**와 **Servers** 구역이 있습니다. Devices는 현재 소유한
유효한 점유를, Servers는 포트·프로세스·PID, 바인드 주소, cwd, inherited 여부,
시작 시각·경과 시간과 URL을 표시합니다. `inherited`는 리스너가 현재 에이전트 세션보다
먼저 시작됐다는 뜻입니다. 정보가 없으면 `Devices: ?` 또는 `Servers: ?`, 비어 있음이
확인되면 `: none`으로 표시합니다. 이전 peer는 `devices`, `servers`, 호스트 `resources`
중 일부를 생략할 수 있으며, 없는 정보만 알 수 없음으로 처리하고 0으로 해석하지 않습니다.

표시는 에이전트 JSON의 `devices`, `servers`와 호스트의
`resources:{servers_unowned:[],dead_serve:[],stale_devices:[],error:null}`를 읽습니다.
서버는 현재 사용자의 리스너와 Tailscale Serve에서 탐색하며 플러그인, adb와 에이전트
런타임 리스너는 제외합니다. 조회는 레지스트리 갱신, 점유 정리, 토큰 변경이나 메일
확인 처리를 하지 않습니다.

기기 점유를 바꾸려면 표의 동작이 아니라 번들 CLI를 사용합니다.

```text
device claim phone|emu DEVICE [--label TEXT] [--force]
device release [phone|emu|all] [DEVICE]
device list
```

`release`는 기본적으로 호출자 자신의 점유를 모두 해제하며 종류·기기로 범위를 좁힙니다.
점유는 검증된 호스트·terminal·generation에 귀속됩니다. 비활성 또는 이전 generation의
소유자는 adb 연결 여부와 관계없이 stale이므로 교체할 수 있습니다. 다른 활성 소유자가
있으면 점유를 거부하며, `--force`는 사용자가 명시적으로 지시한 경우에만 사용합니다.
Herdr 갱신 실패를 stale의 근거로 해석하지 않습니다. `device list`는 읽기 전용입니다.
명령 결과와 기기 세부 사항은 [스킬 가이드](skill-guide.md#기기-점유와-자원-표시)를
참고하세요. 제품은 기존 기기 JSON을 가져오지 않습니다. `heavy_slot.py`는 별도로
그대로 유지하며 슬롯을 표시하지 않습니다.

### 역할, phase와 테두리 소유권

main과 worker는 `(저장소, 정규 호스트, anchor_workspace_id)`를 기준으로 정합니다.
연결된 workspace는 같은 호스트에서 Herdr `worktree.repo_key`가 같고 열려 있는 비연결
workspace를 결정적인 순서로 선택해 기준 workspace로 삼습니다. 메타데이터나 기준
workspace가 없으면 자체 범위를 유지하며 git common directory로 대체하지 않습니다.
모드·home·임곗값은 저장소 전체에 적용합니다. 기준 workspace의 유효한 main·members
설정이 그룹 전체에 적용되며, 연결된 workspace의 설정은 변경 없이 보존했다가 분리되면
다시 사용합니다. auto에서는 활성 명시적 main이 우선합니다. 없으면 기준 workspace에
활성 에이전트가 있을 때만 그룹의 유일한 활성 에이전트, 또는 여럿 중 메인 체크아웃의
유일한 활성 에이전트가 main이 됩니다. 열린 기준 workspace에 에이전트가 없으면
연결된 에이전트가 하나뿐이어도 자동 main이 없습니다. 나머지 auto 에이전트는 worker입니다.
manual에서는 활성 명시적 main과 선택한 그룹 구성원만 역할을 받습니다. 모든 화면은
각 에이전트의 호스트가 계산한 역할을 표시합니다.
이전 프로세스는 v9 원장을 열 수 없으므로 배포 전에
[스키마 v9 저장소·배포 안내](migration.md#worktree-역할-그룹스키마-v9)를 참고하세요.

사용자 지정 별칭에도 색상 표시와 color 토큰을 부여합니다. 하이픈으로 구분한
첫 부분이 팔레트 색상 이름이면 그 색을 사용하고, 그 외에는 SHA-256으로 모든
호스트에서 같은 팔레트 색을 정합니다. 이 식별 표시는 Mailbox·상태 보드의
작업 상태 색상이나 라우팅 주소를 바꾸지 않습니다.

역할은 `🟧 [메인] orange-rabbit`처럼 alias 앞에 붙여 주소 해석을 유지합니다.
공유 표시 모듈이 alias, color, 표시 이름, phase(`recap`)와 원장 기반 기기 토큰을
메타데이터 source `herdr.agent-messenger`로 보고합니다. 값은 정확히
`phone=📱 <공백으로 연결한 라벨>`과 `emu=🤖 <공백으로 연결한 라벨>`이며, 점유가
없으면 해당 키를 지웁니다. 상태 표시도 점유를 유지하며 강제 교체하면 이전 활성
소유자의 표시도 갱신합니다. Herdr 토큰은 source별로 격리되지 않은 pane 단위의
평면 맵입니다. HAM은 관련 없는 토큰 키를 바꾸지 않습니다.

HAM 소유 테두리는 `[메인] alias · summary` 또는 `[워커] alias · summary`로
표시하며 없는 부분은 생략합니다. off 모드에서는 역할 접두사가 없습니다.
HAM은 비어 있는 테두리, 출처가 확인된 legacy 테두리, 또는 자기가 마지막으로
기록한 값과 정확히 같은 테두리만 바꿉니다. 에이전트 세대가 바뀌어도 같은 호스트의
동일한 terminal·pane 연결에서만 소유권을 이어받습니다. 복구할 때도 현재 이름이
기록된 이전 세대의 라벨과 정확히 같아야 하며, 역할 접두사만으로는 소유권을
인정하지 않습니다. 사용자가 다른 이름으로 바꿨으면 보존합니다. 현재 테두리가
원하는 라벨과 이미 같으면 이름을 다시 쓰지 않고 소유권만 다시 기록합니다.
옛 `user:pane-recap` 토큰은 새 상태·역할 기능을 사용할 때만 지웁니다.
이 UI는 전역 recap 규칙을 설치하거나 삭제하지 않습니다.

레지스트리를 갱신할 때 이미 가져온 Herdr 스냅샷을 HAM이 표시하려는
`display_agent`, alias/color/recap/phone/emu 토큰과 HAM 소유 테두리에 비교합니다.
표시 불일치는 모델 토큰을 쓰거나 모델을 깨우거나 메일을 보내지 않고 복구하며,
별도 프로세스나 타이머도 시작하지 않습니다. 표시가 일치하면 표시 쓰기나 추가
하위 프로세스 실행이 없습니다. 기록된 phase·summary를 복원할 뿐이므로 작업의
의미 있는 변화는 여전히 `status set`으로 명시해야 합니다. 대체 표시를 쓰는 쪽과
경합하면 다음 워커 스냅샷에서 다시 확인하며, 쓰기 성공만으로 복구를 확정하지 않습니다.

각 표시 쓰기는 성공 여부와 관계없이 이후 스냅샷에서 원하는 표시를 확인할 때까지
대기합니다. 불일치가 남으면 5초부터 시작하는 지수 백오프로 재시도하며, 최초 쓰기를
포함해 최대 다섯 번 시도합니다. 큐는 최대 256개 pane을 보관하며, 용량을 넘은
pane에는 쓰지 않고 진단을 남깁니다. `pending` 항목은 재시도 시각 전에도 기존
유지보수 워커를 유지하지만, `exhausted` 항목만 있으면 워커를 유지하지 않습니다.
재시도 상태는 이벤트나 워커 인스턴스가 바뀌어도 유지되며, 원하는 표시나
terminal·pane 연결이 바뀌거나 스냅샷의 표시가 일치하면 해제됩니다.

불일치가 계속되면 `python3 -m ham cli ledger doctor`의 pane별 `display_repair`
맵에서 `state`(`pending` 또는 `exhausted`), `attempts`, `next_try_at`,
`fingerprint`, `last_error`를 확인하세요. `exhausted`이면 같은 대상을 자동으로
다시 쓰지 않습니다. 실제 pane 표시와 경합하는 쓰기 주체를 먼저 확인하세요.
워커를 다시 시작하거나 같은 상태를 반복해서 지정해도 시도 횟수는 초기화되지 않습니다.
사용자가 붙인 테두리 이름은 보존하며, 역할처럼 보이는 접두사를 덮어쓰기 권한으로
해석하지 마세요.

## 기존 직접 프롬프트 오버레이

**Send Prompt to Agents**와 **Held Messages** 동작은 그대로 유지합니다.
아래 내용은 메일함 전달이 아니라 기존 프롬프트 UI를 설명합니다.

## 메신저 열기

에이전트가 실행 중인 pane에서 **Send Prompt to Agents**를 실행합니다. 현재
에이전트가 고정 발신자가 됩니다. 선택한 pane에 에이전트가 없으면 오버레이 대신 오류
알림을 표시합니다.

로컬 에이전트는 Herdr workspace 라벨 순으로 즉시 표시됩니다. 유니코드 라벨을
보존하고 worktree 기반 workspace에는 `WT:` 접두사가 붙습니다. 원격 에이전트는
SSH 호스트 별칭 아래에 묶고, 각 호스트 안에서 workspace별로 다시 묶어 표시합니다.
그룹 식별에는 정규 호스트와 Herdr의 `workspace_id`를 함께 사용하며, 호스트가
다른 ID를 같은 workspace로 보지 않습니다. 표시 이름이 같은 서로 다른
workspace도 합쳐지지 않으며, 이 경우 ID를 함께 표시해 구분합니다.

## 수신자 행

조작 상태와 에이전트 수명 주기 표시는 서로 분리돼 있습니다.

- `›`: 키보드 커서
- `[x]`: 선택된 수신자
- `●`: 작업 중
- `○`: 대기
- `✓`: 완료
- `!`: 차단
- `~`: 오래된 상태

색상은 보조 표현이므로 단색 화면에서도 상태를 구분할 수 있습니다. workspace
이름은 각 그룹 제목에 한 번만 표시하고 에이전트 행에서는 반복하지 않습니다.
각 행은 Agent Labels 이름, Herdr pane ID, 수명 주기 상태를 우선 표시합니다.
전체 session ID와 workspace 정보는 주 화면 너비를 차지하지 않으면서 검색할 수
있습니다. 호스트 제목은 에이전트 수를 항상 `(n)`으로 표시하고, workspace 제목은
에이전트가 여러 개일 때만 같은 형식의 개수를 표시합니다.

긴 그룹은 스크롤 중에도 호스트와 workspace 제목을 유지합니다. 작은 화면에서
sticky 제목을 하나만 표시할 수 있으면 더 구체적인 workspace 제목을 우선합니다.
필요한 경우 수신자 제목에 현재 보이는 범위를 표시합니다. 접속할 수 없는 원격
호스트는 요약해서 보여주며 상세 화면에서 각 별칭과 최근 오류를 확인할 수 있습니다.

## 메시지 편집기와 레이아웃

오버레이는 Herdr가 제공하는 pane 영역을 사용하며 HAM은 고정 크기를 요청하지 않습니다.
가로 중앙의 본문 영역은 최대 104열이며 수신자의 pane·상태도 이 영역 안에 정렬합니다.
편집기는 최대 88셀에서 줄바꿈합니다. 탐색된 수신자 목록에 대부분의 높이를 할당하면서
가능하면 줄바꿈된 메시지 4행 이상을 유지합니다. 긴 메시지는 텍스트 커서를 따라가며
스크롤바를 표시합니다.

탐색·전송 경로 선택의 키 안내는 화면 맨 아래 대신 짧은 선택 영역 바로 다음에
표시합니다. 작성 중 전송 경로를 다시 열면 선택한 수신자 수와 초안이 유지된다는 안내를
보여 줍니다. coordinator·추천 경로는 기본색으로, 탐색 완료는 경고가 아닌 성공으로
표시합니다. 공통 키 안내는 동작 단위로 묶어 최대 두 줄로 배치합니다.

UI 언어는 `LC_ALL`, `LC_MESSAGES`, `LANG` 순으로 결정하며 영어, 일본어,
한국어를 지원합니다. 지원하지 않는 locale은 영어를 사용합니다.

위·아래 방향키는 화면에 표시된 메시지의 줄바꿈에 맞춰 커서를 이동합니다.
긴 라벨과 상태 문구는 터미널 셀 너비에 맞춰 잘라서 한국어와 일본어가 다음 행을
덮어쓰지 않도록 합니다.

전송을 취소해도 이미 확인된 전송 결과는 유지합니다. 이미 전달됐거나 연결 중단으로
수신 여부가 불확실한 대상은 선택에서 해제합니다. 수신 여부가 불확실하면 오버레이에
안내하므로 다시 보내기 전에 대상의 상태를 확인할 수 있습니다. 직접 전송에서는
아직 보내지 않은 대상과 실패가 확인된 대상의 선택을 유지합니다.

## 키보드 조작

- `Up` / `Down`: 선택지, 수신자 또는 메시지 행 이동
- `Enter`: 강조된 탐색 방식 확정
- `D` / `L`: 원격 탐색 또는 로컬 전용 선택
- `C` / `D`: 코디네이터 위임 또는 직접 전송 선택
- `Space`: 수신자 선택 전환
- `Ctrl+A`: 필터된 수신자 모두 선택
- `Ctrl+D`: 선택 해제
- `Tab`: 수신자 목록과 메시지 편집기 전환
- `Ctrl+O`: 전송 방식 화면 다시 열기
- `Ctrl+R`: 로컬 및 허용된 원격 에이전트 새로고침
- `Ctrl+U`: 접속 불가 원격 호스트와 최근 오류 표시
- `Ctrl+G`: HAM 스킬 설치기와 가이드 열기
- `Ctrl+S`: 프롬프트 전송
- `Esc`: 이전 화면으로 이동하고 탐색·전송을 취소한 뒤 오버레이 닫기
