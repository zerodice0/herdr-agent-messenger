# HAM 메일함과 팝업 UI 참고서

한국어 · [English](../ui-reference.md) · [README](../../README.ko.md)

## 메일함 열기

**HAM: Mailbox (Right Split)** (`herdr.agent-messenger.mailbox-split`)은
현재 pane 오른쪽에 plugin 소유 메일함을 엽니다. **HAM: Mailbox (Tab)**
(`herdr.agent-messenger.mailbox-tab`)은 같은 화면을 새 탭으로 엽니다.
일반 셸에서도 열 수 있으며, 연 pane에 에이전트가 없어도 됩니다. 이 동작은
키 바인딩을 바꾸거나 runtime을 설치하지 않습니다.

HAM은 workspace마다 실제 메일함 pane ID와 terminal ID를 기억합니다.
다시 열면 해당 plugin pane으로 이동하며, 라벨이 바뀌었거나 다른 pane의
이름이 `HAM`이어도 혼동하지 않습니다. 연 pane과 terminal의 ID는 별도로
전달합니다. 편집기 밖에서 `q`를 누르면 메일함 plugin pane만 닫습니다.
`Esc`는 편집기나 상세 화면에서 먼저 빠져나옵니다.

### 네 화면

- **1 Status:** 로컬과 등록된 원격 호스트의 에이전트, canonical 호스트 이름,
  역할, 턴 상태, phase, 읽지 않은 수(`queued` 또는 내부 claim 상태), 확장
  유무를 표시합니다. 확장이 없다는 사실을 전달 실패로 표시하지 않습니다.
  연결이 끊긴 호스트는 마지막 조회 결과에 오래된 상태라는 표시를 붙이고,
  읽지 않은 수는 `?`로 표시합니다. 연결 실패만으로 에이전트가 종료됐다고
  판단하지 않습니다. `Enter`로 상세 정보를 보고, 에이전트를 선택한 뒤
  `c`를 누르면 해당 저장소에서 작성합니다.
- **2 Threads:** 보관 중인 메시지 본문, 전달 상태, 보류 사유, 철회 요청,
  직접 입력 결과와 전송 대기·실패한 OUTBOX를 표시합니다. `Enter`로 항목을
  열고 방향키로 상세 내용을 스크롤합니다. 조회만으로 전달·처리 상태가 바뀌지
  않습니다. `w`는 로컬에서 보낸 철회 가능한 메시지를 철회하고, `t`는 선택한
  OUTBOX를 같은 ID로 명시적으로 재시도합니다.
- **3 Compose:** 발신자는 항상 `user`입니다. `Tab`으로 제목·본문을 전환하고
  본문에서 `Enter`로 줄을 바꿉니다. `Ctrl+K`는 `fyi`·`action`을, `Ctrl+D`는
  메일함·명시적인 **사용자 바로 입력**을 전환합니다. `Ctrl+S`로 경로를 확인한
  뒤 다시 `Ctrl+S`를 눌러 전송합니다. 편집 중에는 `q`와 숫자도 글자로
  입력되며, `Esc`로 상태판으로 돌아갑니다.
- **4 Settings:** `Enter`로 편집할 수 있는 행은 정확히 일곱 개입니다.
  `mode`(`off`·`manual`·`auto`), `main`, `members`, `idle_minutes`,
  `coalesce_seconds`, `wakes_per_hour`, `max_hop`입니다. main은 canonical
  호스트와 terminal을 담은 JSON 객체이며 `null`은 지정을 해제합니다.
  구성원은 같은 객체의 배열입니다. 상태판에서 `c`로 에이전트를 고른 뒤
  설정 화면의 `m`으로 main을 지정하거나 `Space`로 manual 구성원에 넣고
  뺄 수 있습니다. Home(모드를 처음 켠 canonical 호스트), `computed_main`,
  버전·origin, 전파 대기와 충돌 정보는 의도적으로 읽기 전용입니다.
  설정은 내부 서비스를 통해 바꾸며, 에이전트의 `repo show`도 읽기 전용입니다.

설정은 한 번에 하나만 저장할 수 있습니다. **Saving settings** 표시가 있는 동안
추가 저장 요청이나 토글은 거절하며 대기열에 넣지 않습니다. 결과를 기다린 뒤
원하는 변경을 다시 시도하세요. 저장 요청이 거절돼도 편집 중인 내용은 유지합니다.
저장 중에도 화면 이동은 동작하며, 텍스트 편집기 밖에서는 `q`로 닫을 수 있습니다.
저장 서비스가 확정한 결과를 즉시 표시하며, 오래된 조회 결과로 덮어쓰지 않습니다.

`Page Up`·`Page Down`으로 긴 상세 내용과 설정 정보를 스크롤합니다. 편집
항목 아래에 이어지는 충돌 기록도 끝까지 볼 수 있습니다. 충돌 정보는 값,
승자, 버전과 origin을 생략하지 않고 줄바꿈하므로 전체 기록을 확인할 수 있습니다.
작성 화면 밖에서 `?`를 누르면 짧은 하단 줄에 잘린 오류·상태와 호스트 연결
정보를 자세히 봅니다.
전송을 기다리는 동안 새로 편집한 초안은 전송 결과가 돌아와도 지우지 않습니다.

### 접수 결과와 불확실한 전달

메일함에 넣은 메시지는 일반적인 native 수신 규칙을 따릅니다. 바로 입력은
기존의 수신 대상 검증과 터미널 전송을 이용하여 정확히
`Message from user (HAM):` 헤더를 붙여 제출합니다. 대상의 작업에 끼어들 수
있으므로 경로를 명시적으로 선택하고 확인해야 합니다. HAM은 전송 전에
`via=direct`, `submitting`을 저장한 뒤 `accepted`·`unknown`·`failed`를
기록합니다. 이 결과는 native의 `delivered`·`handled`와 다릅니다.
Threads에서 결과를 확인할 수 있습니다. 중단된 `submitting`이나 `unknown`은
다시 전송하기 전에 직접 확인해야 하며, HAM이 자동 재전송하지 않습니다.

접수 여부가 불확실한 native claim은 세션이 바뀌어도 보류합니다. 해당 thread에서
`a`로 적용됐음을, `n`으로 적용되지 않았음을 확인합니다. 두 동작 모두 경고를
표시하며, 근거를 입력한 뒤 `Enter`를 눌러야 바뀝니다. 적용 확인은 과거 claim의
에이전트와 generation을 가리킵니다. **사용자가 수동으로 확인한 기록**이며
runtime journal의 증거나 모델의 이해·처리 완료를 뜻하지 않습니다. 미적용
확인은 정확히 해당 claim만 해제하며, 그 동작 자체가 재전송하지는 않습니다.
`Esc`를 누르면 claim을 바꾸지 않고 취소합니다.

메일함이 열려 있는 동안 로컬 board bell을 1초마다 stat으로 확인합니다.
원격 상태는 로컬 변경과 무관하게 30초마다, 실행 시간을 제한한 별도 프로세스에서
조회합니다. 따라서 SSH가 끊겨도 키 입력과 닫기가 멈추지 않습니다. 닫을 때는
자기가 시작한 프로세스만 정리합니다. 이 조회는 모델 턴을 만들지 않는 코드
동작입니다. 한글 입력, 터미널 셀 너비에 맞춘 자르기, 크기 변경과 작은 화면
안내는 기존 메신저와 같은 텍스트 도구를 사용합니다.

### 역할, phase와 테두리 소유권

역할은 `🟧 [메인] orange-rabbit`처럼 alias 앞에 붙여 주소 해석을 유지합니다.
공유 표시 모듈이 alias, color, 표시 이름과 phase(`recap`)를 같은 HAM source로
보고합니다. `phone`·`emu` 등 기기 토큰이나 다른 source는 덮어쓰지 않습니다.

상태·역할 기능을 사용하면 summary는 `[메인] summary` 또는 `[워커] summary`
형태로 테두리에 표시합니다. off 모드의 상태에는 역할 접두사가 없습니다.
HAM은 비어 있는 테두리, 출처가 확인된 legacy 테두리, 또는 자기가 마지막으로
기록한 값과 같은 테두리만 바꿉니다. 사용자가 다른 이름으로 바꿨으면 보존합니다.
옛 `user:pane-recap` 토큰은 새 상태·역할 기능을 사용할 때만 지웁니다.
이 UI는 전역 recap 규칙을 설치하거나 삭제하지 않습니다.

## 기존 직접 프롬프트 팝업

**Send Prompt to Agents**와 **Held Messages** 동작은 그대로 유지합니다.
아래 내용은 메일함 전달이 아니라 기존 팝업을 설명합니다.

## 메신저 열기

에이전트가 실행 중인 pane에서 **Send Prompt to Agents**를 실행합니다. 현재
에이전트가 고정 발신자가 됩니다. 선택한 pane에 에이전트가 없으면 팝업 대신 오류
알림을 표시합니다.

로컬 에이전트는 Herdr workspace 라벨 순으로 즉시 표시됩니다. 유니코드 라벨을
보존하고 worktree 기반 workspace에는 `WT:` 접두사가 붙습니다. 원격 에이전트는
SSH 호스트 별칭 아래에 묶고, 각 호스트 안에서 workspace별로 다시 묶어 표시합니다.
그룹 식별에는 Herdr의 `workspace_id`를 사용하므로 표시 이름이 같은 서로 다른
workspace도 합쳐지지 않으며, 이 경우 ID를 함께 표시해 구분합니다.

## 수신자 행

조작 상태와 에이전트 수명 주기 표시는 서로 분리돼 있습니다.

- `›`: 키보드 커서
- `[x]`: 선택된 수신자
- `●`: 작업 중
- `○`: 대기
- `✓`: 완료
- `!`: 차단
- `~`: 오래된 상태

색상은 보조 표현이므로 단색 화면에서도 상태를 구분할 수 있습니다. workspace
이름은 각 그룹 제목에 한 번만 표시하고 에이전트 행에서는 반복하지 않습니다.
각 행은 Agent Labels 이름, Herdr pane ID, 수명 주기 상태를 우선 표시합니다.
전체 session ID와 workspace 정보는 주 화면 너비를 차지하지 않으면서 검색할 수
있습니다. 호스트 제목은 에이전트 수를 항상 `(n)`으로 표시하고, workspace 제목은
에이전트가 여러 개일 때만 같은 형식의 개수를 표시합니다.

긴 그룹은 스크롤 중에도 호스트와 workspace 제목을 유지합니다. 작은 화면에서
sticky 제목을 하나만 표시할 수 있으면 더 구체적인 workspace 제목을 우선합니다.
필요한 경우 수신자 제목에 현재 보이는 범위를 표시합니다. 접속할 수 없는 원격
호스트는 요약해서 보여주며 상세 화면에서 각 별칭과 최근 오류를 확인할 수 있습니다.

## 메시지 편집기와 레이아웃

팝업은 큰 터미널에서 최대 120열×32행까지 확장되고 작은 터미널에 맞춰 축소됩니다.
탐색된 수신자 목록에 대부분의 공간을 할당하면서 가능하면 soft-wrap된 메시지
4행 이상을 유지합니다. 긴 메시지는 텍스트 커서를 따라가며 viewport scrollbar를
표시합니다.

좁은 터미널에서는 단축키 도움말을 자르지 않고 다음 줄로 넘깁니다. 팝업은 Herdr
터미널 팔레트를 상속하며 수명 주기 색상은 작업 중, 완료, 차단, 경고 상태에만
사용합니다.

UI 언어는 `LC_ALL`, `LC_MESSAGES`, `LANG` 순으로 결정하며 영어, 일본어,
한국어를 지원합니다. 지원하지 않는 locale은 영어를 사용합니다.

위·아래 방향키는 화면에 표시된 메시지의 줄바꿈에 맞춰 커서를 이동합니다.
긴 라벨과 상태 문구는 터미널 셀 너비에 맞춰 잘라서 한국어와 일본어가 다음 행을
덮어쓰지 않도록 합니다.

전송을 취소해도 이미 확인된 전송 결과는 유지합니다. 이미 전달됐거나 연결 중단으로
수신 여부가 불확실한 대상은 선택에서 해제합니다. 수신 여부가 불확실하면 팝업에
안내하므로 다시 보내기 전에 대상의 상태를 확인할 수 있습니다. 직접 전송에서는
아직 보내지 않은 대상과 실패가 확인된 대상의 선택을 유지합니다.

## 키보드 조작

- `Up` / `Down`: 선택지, 수신자 또는 메시지 행 이동
- `Enter`: 강조된 탐색 방식 확정
- `D` / `L`: 원격 탐색 또는 로컬 전용 선택
- `C` / `D`: 코디네이터 위임 또는 직접 전송 선택
- `Space`: 수신자 선택 전환
- `Ctrl+A`: 필터된 수신자 모두 선택
- `Ctrl+D`: 선택 해제
- `Tab`: 수신자 목록과 메시지 편집기 전환
- `Ctrl+O`: 전송 방식 화면 다시 열기
- `Ctrl+R`: 로컬 및 허용된 원격 에이전트 새로고침
- `Ctrl+U`: 접속 불가 원격 호스트와 최근 오류 표시
- `Ctrl+G`: HAM 스킬 설치기와 가이드 열기
- `Ctrl+S`: 프롬프트 전송
- `Esc`: 이전 화면으로 이동하고 탐색·전송을 취소한 뒤 팝업 닫기
