# HAM agent skill

[한국어](ko/skill-guide.md) · English · [README](../README.md)

HAM lets Codex, Claude Code, and omp exchange durable mail across repositories, inspect coordination status, and **start new labeled interactive Herdr sessions**. Existing-agent prompt routing remains available where legacy policy permits. The canonical skill name is `herdr-agent-messenger`; **HAM** is its shorter user-facing name.

For caller-relative `spawn`, `--message-file`, `--body-file`, and `--destination`,
invoke the absolute copied/bundled `scripts/herdr_agent_messenger.py` from your
project cwd. It loads the pinned package from plugin-root cwd, then restores caller
cwd through `python3 -m ham --cwd <CALLER_DIRECTORY> cli ...`. For direct use:
`cd /ABS/PLUGIN_ROOT && python3 -m ham --cwd /ABS/CALLER cli ...`.
Module examples below deliberately run from the plugin root; relative arguments
then refer to that root. See [package layout and cwd](migration.md#python-package-layout).

## Install with the plugin

Open **HAM Skill** from Herdr's command palette, or press `Ctrl+G` in Agent Messenger. Select Codex, Claude, or omp at **System** (user-wide) or **Project** (active Herdr workspace) scope. Press `?` for the invocation guide.

| Client | System/user destination | Project destination |
| --- | --- | --- |
| Codex | `~/.agents/skills/herdr-agent-messenger` | `<project>/.agents/skills/herdr-agent-messenger` |
| Claude Code | `~/.claude/skills/herdr-agent-messenger` | `<project>/.claude/skills/herdr-agent-messenger` |
| omp | `~/.omp/agent/skills/herdr-agent-messenger` | `<project>/.omp/skills/herdr-agent-messenger` |

A checkout already supplies the canonical Codex skill and Claude bridge. Install the omp target to make the skill available through omp's skill search. Installer badges mean `✓` current, `↑` update available, `○` not installed, and `!` conflicting files. If a newly installed skill does not appear, start a new client session.

The installer does not overwrite an unrelated skill directory with the same name or follow internal symlinks when replacing managed files. Updates are copied to a temporary directory before replacing the installed skill. A failed copy leaves the previous installation intact; a failed replacement attempts restoration. If restoration also fails, the error identifies the retained backup. Local extra files are preserved; generated bytecode and `.DS_Store` files are omitted.

Open the installer from a shell:

```bash
herdr plugin action invoke agent-skill-guide --plugin herdr.agent-messenger
```

From the plugin/checkout root, the noninteractive installer accepts `codex`, `claude`, `omp`, or `all` and installs the selected user-scope targets:

```bash
python3 -m ham skill-installer install omp
python3 -m ham skill-installer install all
python3 -m ham messenger skill-path
```

The last command prints the packaged canonical skill path. Project installs are selected in the interactive installer and use the active Herdr workspace root.

### Receiving dependency

- **Plugin:** ledger, mailbox, UI, and transport.
- **Skill:** agent instructions and CLI launcher, not a receiver.
- **OMP adapter:** native receiving and eligible action/FYI wake.
- **Claude hooks:** native receiving at turn boundaries, with no idle wake.
- **Codex:** skill-guided inbox pull; no adapter is needed.

On **every selected host**, run the read-only health summary after installing or
updating the plugin and skill, with cwd set to the plugin root:

```bash
python3 -m ham cli runtime status
# Only after user consent, for each client actually used (omp or claude):
python3 -m ham cli runtime install omp
```

The summary reports runtime ownership/conflicts in `clients`, active local
receiver counts in `sessions`, ledger availability/errors in `ledger`, and
suggested `next_steps`. Missing or old ledgers are reported, never created or
upgraded by this read. `runtime status omp|claude` retains its client-specific
output. Codex's pull workflow is intentional, not a missing-receiver failure.

After a successful skill install, the interactive installer shows both runtime
states and offers missing runtimes with **Not now** selected by default. Review
the destination and files before consenting. Noninteractive installs report a
final runtime summary to **stderr**, including missing runtimes and the exact
install command, without contaminating stdout. The optional flag is explicit
consent to install the selected runtime(s), independently of the skill target:

```bash
python3 -m ham skill-installer install omp --runtime omp
python3 -m ham skill-installer install all --runtime all
```

`--runtime` accepts `omp`, `claude`, or `all`; omitting it never installs a
runtime implicitly. Conflicts are reported without replacing foreign or modified
files. Explain which sessions must restart and restart only those the user
selects. Then confirm receiver registration (`extension_present=1`); otherwise
report **installed, activation pending**. Plugin and skill installation alone
never prove receiving readiness, and owned files do not prove activation or
context admission. Plugin loading never writes client configuration. The new
repository `auto` default is unchanged; runtime consent does not change mode.

## Invoke HAM

- **Codex CLI/IDE:** type `$ham`, then select **HAM — Herdr Agent Messenger** from the skill picker. `$ham` is a search term, not a different canonical skill name.
- **Claude Code:** use `/herdr-agent-messenger`, or ask naturally to use HAM. `$ham` is not a Claude command.
- **omp:** ask naturally to use HAM or read `skill://herdr-agent-messenger` after installing the user/project target above.

For an existing recipient, include its exact host-qualified Agent Labels value:

```text
$ham Ask local/yellow-falcon to review the current change. Wait for the reply
and summarize any required follow-up.
```

For a new session, state creation explicitly:

```text
Use HAM to start a new omp agent in a new tab for this project, send it a
focused code-review assignment, and wait for its response.
```

These are different operations: a missing requested label is reported, never guessed or automatically created. When asked to start/open a session with an assignment, use one HAM `spawn --message TEXT` or `spawn --message-file PATH` operation. HAM persists the initial submission and sends it once after readiness; do not follow it with a separate legacy `request`. Raw `herdr agent start <name>` bypasses HAM label selection and metadata reporting and is not a substitute.

### Historical Claude skill observations and scope caveats

The following observations are from the **older legacy workflow**, on winmini
with Claude Code **2.1.301** and Herdr **0.9.5**, 2026-10-16
([issue #5](https://github.com/zerodice0/herdr-agent-messenger/issues/5)).
They document skill discovery/installation, not today's mailbox receiving
recipe or native runtime acceptance.

| Check | Observed result |
| --- | --- |
| User install | The user-scope installer (now `python3 -m ham skill-installer install claude` from the plugin root) made `/herdr-agent-messenger` appear as `(user)` outside the checkout. |
| Project install | **HAM Skill** → **Project / Claude** copied the complete bundle; the command appeared as `(project)` in that project before user installation. |
| Checkout bridge | With no user copy installed, Claude followed `.claude/skills/herdr-agent-messenger/SKILL.md` and read the canonical `.agents/skills/herdr-agent-messenger/SKILL.md`. |
| Invocation | User, project, and checkout runs executed the bundled CLI's `list --host local` with exit 0. |
| Historical new session | The older run used separate spawn and request operations and collected a correlated settled reply without resending. That sequence is not the current initial-assignment recipe; use atomic `spawn --message` instead. |
| Natural-language selection | Separate fresh requests mentioning HAM or only a real `local/<label>` address selected the `Skill` tool, both in the checkout before user installation and outside it after installation. |

**Same-name precedence:** this Claude Code version selected the **user** copy
when both user and project/checkout copies existed. Do not assume that the
checkout bridge is being exercised merely because Claude starts in the
checkout. Verify the loaded skill path; test the bridge before installing a
same-named user copy. Restart the client after changing installations.

**Interactive startup:** Claude's folder-trust dialog (and first-run UI
questions) can block a HAM `spawn --kind claude` readiness check. In this
observation, blocked starts returned `agent_start_failed` / `agent_not_ready`
and reported that the created tab was closed. Handle trust interactively in
the intended directory before automated startup; inspect cleanup details
before retrying. Print mode skips the trust dialog, so `claude -p` alone is not
proof that interactive startup works.

**Host authentication observation:** winmini was logged in through `claude.ai`
with a Max subscription. macbook-pro and mac-studio reported `loggedIn: false`
over SSH while their macOS Keychains were unavailable to non-GUI sessions
(`User interaction is not allowed`). That observed host/session condition is
not evidence of a missing skill or a general Claude authentication failure.

## Mailbox commands and identity

Use the mailbox to leave durable messages without injecting a prompt into a busy
agent. Receiving runtimes may admit them at a natural user boundary; eligible
OMP action or FYI mail can cause an automatic turn under the
rules below. Run with cwd set to the plugin root in a registered Herdr agent pane:

```bash
python3 -m ham cli mail send --to local/blue-owl --kind action --body 'Review the boundary.'
python3 -m ham cli inbox read
python3 -m ham cli inbox handle --message MESSAGE_UUID
python3 -m ham cli mail show --thread THREAD_UUID
```

`mail send` requires `--to` and exactly one of `--body` / `--body-file` (UTF-8,
nonblank, 16 KiB maximum). `--kind fyi|action` defaults to `fyi`; `--subject`
sets a new thread's subject (1024 UTF-8 bytes), and `--reply-to UUID` keeps the
thread, increments hop, and atomically handles an addressed queued/delivered
parent. Accepted local mail ordinarily waits queued; remote copies may be pending,
and withdrawal or terminal closure can make mail final without a runtime claim.
Neither kind makes `mail send` itself start a model turn.

Mail can cross repositories on the local host or a registered peer; there is no
repository allowlist. Peer registration remains the trust boundary. Thread
origin (`threads.repo_id` / `messages.repo_id`) never changes. Schema v8 adds
`messages.sender_repo_id` (sender's repo at send time) and
`deliveries.recipient_repo_id` (resolved recipient's repo at send time).
Legacy rows backfill both from the message repo without changing legacy hashes;
new immutable wire payloads include both repo snapshots, with the recipient
snapshot also in the routed delivery. A replier must have sent or received a
message in the thread (`not_participant` otherwise), not share its origin repo.

Cross-repo receipt and wake use the **recipient's** repo settings and own scoped
role. Modes, idle/done readiness, hourly per-recipient limit, coalescing and
max-hop gates are unchanged. Legacy collaboration policy is also unchanged:
`use_mailbox` still applies only to participating same-repo pairs.

Choose `--kind action` when the recipient must act, answer, or continue (for
example, on an answer/decision); use `fyi` for reference information. Eligible
action wakes promptly; FYI is batched for an idle participating OMP wake after
about five to ten minutes, or delivered right after a turn when it arrives mid-turn.
Existing wake safeguards apply.

Successful sends can return advisory warnings without changing the default
`fyi` kind. See the [reference warning list](../.agents/skills/herdr-agent-messenger/reference.md#local-mailbox)
for `recipient_no_receiver` and the advisory contract.

`inbox read` accepts `--message UUID`, `--all`, `--limit N` (default 100,
1–1000), and `--verbose`. Defaults retain IDs/sender/body/state/reply context;
verbose restores full delivery diagnostics. It never changes state/logs/bells, including when a task agent shares
the calling pane. `inbox handle --message UUID` is repeatable and all-or-nothing;
queued→handled does not invent a native delivered timestamp.
`mail withdraw --message UUID` competes atomically with delivery claim and
returns `withdrawn:false` if a claim or another non-withdrawn final result wins.
Repeating a successful withdrawal returns `withdrawn:true` and preserves its
first receipt/time. `mail show --thread UUID` reads the thread, and `repo show`
reads this agent's repository/settings.

`mail dismiss --message UUID [--message UUID ...] --reason TEXT` resolves sender
attention for locally originated `undeliverable` mail only. The reason must be
nonblank; repeated IDs are deduplicated and the batch is atomic. Authorization
requires the verified original terminal in its send-time sender repo (including
a restarted session), or the current active main in the original sender's
host-local anchor role group. Linked worktrees share that role resolver;
same-repo workers or unrelated mains do not qualify, and `off` grants no main
override. Missing sender/group evidence fails closed.
New v11 sends preserve the sender identity and anchor at send time in local
`messages.sender_context`, so the anchor main remains authorized after the
sender agent and linked workspace disappear. It never enters payload hashes
or wire envelopes. Legacy v10 mail has no snapshot: a main override needs
surviving recorded sender/workspace evidence; missing historical scope fails
closed rather than selecting an arbitrary same-repo main.

The first audit's actor/time/reason is immutable on retries, including after
90-day body retention. `dismissal` is null before resolution and an audit object
afterward in compact/verbose inbox reads and thread views. Its stable fields
are `message_id`, `actor_alias`, `actor_terminal_id`, `reason`, `dismissed_at`.
Raw state remains `undeliverable`; failure/native receipt fields, final/update
timestamps and retention deadlines stay unchanged. Dismissal creates no ACK,
handled receipt, wake or remote resolution: it affects only the origin ledger.
Handled threads contain only genuinely handled or explicitly dismissed messages;
unresolved/withdrawn messages and new live replies keep them Active. There is
no TUI dismissal shortcut. See the [full contract](../.agents/skills/herdr-agent-messenger/reference.md#sender-dismissal).

### Repository history and read-only board

```text
mail threads [--repo REPO_ID] [--limit N] [--cursor TOKEN]
mail direct-list [--repo REPO_ID] [--limit N] [--cursor TOKEN]
status board [--repo [ID]] [--host local|CANONICAL|REGISTERED_SSH_ALIAS] [--verbose]
```

Run these after the same `python3 "$HAM_CLI"` prefix. Each accepts `-h` /
`--help` and returns one JSON object; only the board accepts `--verbose`.
All CLI JSON is whitespace-free UTF-8, including verbose. Domain errors use
`{"error":{"code":"CODE","message":"TEXT"}}`, exit 1; usage errors exit 2.
These reads neither acknowledge mail nor change settings, status, last_seen,
display or claims, and expose no user-compose/direct-send/operator ACK bypass.

History lists default to the verified caller's repository. Explicit
`--repo REPO_ID` avoids fetching Herdr caller identity. `--limit` defaults to 100
(1–1000). Results are `{repo_id,threads,next_cursor}` or
`{repo_id,submissions,next_cursor}`; `next_cursor:null` ends traversal.
`mail threads` includes a thread when the selected repo is its origin, any
message's sender repo, or any delivery's recipient repo. Both sides therefore
discover participating cross-repo threads, including retained pending remote
copies on this ledger. `mail direct-list` remains selected-repo `via=direct`
user-submission history, not `spawn_initial` or a cross-repo mail view.
Neither list replicates all-host history.
Pass the HMAC-signed opaque cursor unchanged. It is bound to ledger/query/repo;
tampering or a scope mismatch produces `invalid_cursor`. Pages use
`updated_at DESC` then UUID ascending keyset order, never OFFSET. This is live
pagination, not a frozen snapshot: concurrent updates can move an unseen row
before the boundary. Restart from the first page to see newer updates.

`status board` defaults to all local repositories plus all registered peers.
Bare `--repo` selects the caller's repo; explicit `--repo ID` filters it.
`--host` restricts the board to local or one registered canonical name/SSH alias.
The result `{repo_id,agents,hosts}` defaults to brief address/host/workspace/repo,
role/turn/phase/summary/unread/stale/receiver fields and device/server counts.
Hosts retain errors/unread/stale and resource counts/errors, not duplicate
agent rows. `--verbose` restores full registry/status/resource fields, timestamps,
identity/placement and `hosts[].agents`. `status list --verbose` likewise restores
full local rows. Python/TUI/peer `status-export` retain the full shape.
Compact board/list `repo` is the short repo name for discovering cross-repo targets.
Status-update and registry-observation timestamps differ. Reads do not refresh
or mutate status/display/claims and request peer `refresh=false`. A failed peer has a structured
error and unread `?`. The stateless CLI has no prior rows to invent; a TUI may
retain a prior matching verified-host snapshot as stale. Existing `list` and
local `status list` retain their narrower discovery/status semantics.
Read-only remote behavior requires peers with this read API version; an older
peer may ignore `refresh=false` and perform its legacy registry refresh.
A peer failure still exits with code 0: inspect each host's `error`, `stale` and
unread. An unknown/ambiguous `--host` returns `peer_not_configured` with exit code 1.

### Device claims and resource presence

Use `python3 "$HAM_CLI"` with these commands:

```text
device claim phone|emu DEVICE [--label TEXT] [--force]
device release [phone|emu|all] [DEVICE]
device list
```

- Claim before using a real device (`phone`) or emulator (`emu`), and release
  after use. Emulator digits normalize to `emulator-N`. Without `--label`, a
  phone uses its Android model when available, otherwise its ID; an emulator
  uses its number. An explicit label also supports non-Android devices.
- `release` defaults to `all`, meaning all **your own** claims. Specify a kind,
  then optionally a device to narrow the selection; it never releases another
  agent's claims, and has no force option.
- Claim/release refresh Herdr and prove the caller's stable terminal/session
  generation under the terminal lock. An inherited `HERDR_PANE_ID` alone is
  insufficient. Unresolved identity or failed refresh refuses the mutation.
- A live holder has an active agent row in the current host/terminal generation.
  The same holder can reclaim to update a label. Another live holder returns
  `device_claimed` with holder details; `--force` replaces it **only when the user
  explicitly instructs you to do so**. Inactive or old-generation holders are
  stale and can be replaced without force (`replaced_stale:true`).
  Stale claims are pruned only on mutation paths, never by reading a view.

Commands accept `-h` / `--help`, not `--verbose`, and emit one JSON object with
the same domain/usage error conventions as mailbox commands:

| Command | Result |
| --- | --- |
| `device claim` | `{device,replaced,replaced_stale}`; `replaced` is the previous claim or `null`. |
| `device release` | `{released:[...]}`. |
| `device list` | `{devices:[{device_id,kind,label,claimed_at,holder,stale,attached}]}`. |

`holder` contains `{agent_id,alias,pane_id,terminal_id,generation,active,live}`.
`attached` is adb attachment (`true` only for Android state `device`, otherwise
`false`); it is `null` if adb is unavailable or the ID is not adb-like, such as
an iOS UDID. Attachment is not holder liveness. `device list` is read-only:
no registry refresh, token writes, stale pruning or directory creation.

`status board` requests these fields, projecting lists as counts by default;
`--verbose` restores their full read-only records. Status-export includes
`servers` and host `resources` only when its wire payload sets `resources:true`;
the default export, send/policy checks and recipient lookup do not scan servers.

- Agent `devices`: held nonstale claim rows (`stale:false`).
- Agent `servers`: `{port,bind,pid,process,cwd,started_at,urls,inherited}` rows.
  Discovery uses current-user listeners and Tailscale Serve routes on Linux and
  macOS. Ownership follows the active agent's pane; plugin, adb and agent-runtime
  listeners are excluded. `inherited:true` means the process predates the current
  agent session, not that this session started it.
- Host `resources`: `{servers_unowned:[],dead_serve:[],stale_devices:[],error:null}`.
  `servers_unowned` lists served proxy backends with listeners but no agent owner;
  `dead_serve` lists proxy routes without a backend listener, including listeners
  owned by other users in the liveness check; `stale_devices`
  reports stale claims. A discovery error is reported in `resources.error`.

Each resource field is optional independently. If an older peer omits `devices`,
`servers` or `resources`, only that field is unknown (`?`), never silently empty.
Board/TUI reads do not refresh the registry, prune claims or change tokens.
The TUI shows compact counts plus Devices/Servers details; see the
[UI reference](ui-reference.md#device-and-server-presence).

HAM owns the exact sidebar values `phone=📱 <labels space-joined>` and
`emu=🤖 <labels space-joined>`, clearing the corresponding token key when empty.
Claim/release and status projection keep these values synchronized, including a
live previous holder after force replacement. Herdr tokens are a flat per-pane
map, not isolated by metadata source. Product code does not import the legacy
device JSON; any one-time rollout migration is external. `heavy_slot.py` remains
a separate, unchanged script: HAM neither reads nor displays heavy-work slots.

### Mailbox terminology

- **Mailbox / inbox:** durable recipient-slot mail, not terminal input.
  `inbox read` selects this host/caller terminal and delivery recipient-repo snapshot matching the caller's current repo, normally
  `queued`, `delivering`, `delivered`; `--all` includes its retained final states,
  and `--message UUID` can select one final message. Reading is not an ACK.
- **Thread:** the root message UUID is its thread UUID. `--reply-to` inherits the
  parent's thread/subject and increments its hop. `mail show --thread UUID`
  reads a known retained thread, including sent mail, not just the inbox.
- **TUI Threads:** mixed repo-filtered sent/received threads and direct results,
  plus host-wide pending/failed OUTBOX jobs; not a single inbox/chat or remote
  history replica. **Outbox** is FIFO transport (`message`, `receipt`, `setting`,
  `withdraw`; `pending/sent/failed/cancelled`), not a sent-mail folder.
- **Message states:** `pending` awaits an authoritative recipient result;
  `queued` waits unclaimed; `delivering` is a reserved, possibly uncertain claim;
  `delivered` confirms application with native or audited operator evidence,
  not handling or understanding. `handled`, `withdrawn`, `undeliverable` are
  final. Keep `confirmation_source=native|operator` distinct. Direct
  `submitting/accepted/unknown/failed` is transport acceptance, not mailbox ACK.
- **Unread:** counts `queued` + `delivering` by delivery recipient repo, not
  thread origin or whether anyone viewed the text; delivered-but-unhandled mail
  is excluded. `fyi`/`action` are kinds, not states.

Host identity is a canonical name plus a stable ledger UUID, not the machine's
hostname, `local`, or an SSH alias. `local` maps to this ledger; a registered
canonical name or configured alias maps to its peer. The terminal's stable ID
identifies the recipient slot, while native session identity determines its
generation. A pane move changes location, not the session.

The CLI resolves moved terminals through process ancestry and Herdr's public
`pane process-info` shell PID, without requiring a TTY or trusting an inherited
terminal variable as proof. It refuses an unprovable/stale-pane identity.
Display/status revisions do not create a new generation. Queued mail can move
to a new session in the delivery's send-time recipient repo. A different-repo
or shell occupant holds it as `recipient_changed`; the comparison is against
the recipient snapshot, not the sender or thread-origin repo. Uncertain
old-generation claims are never automatically replayed.

Git HTTPS/SSH/scp origins normalize to a host/path identity. Preserve a planned
origin rename explicitly with `git config ham.repo-id 'git:host/stable/repo'`.
Default storage is `${XDG_STATE_HOME:-~/.local/state}/herdr-agent-messenger/ledger`;
set `HERDR_AGENT_LEDGER_DIR` for tests and `HERDR_AGENT_CANONICAL_HOST` only when
creating a new ledger. Internal `ledger doctor`, `ledger reconcile`, `ledger
event`, `ledger retention`, `ledger agent-session` and `ledger delivery
claim|started|release` share the Python store. See the
[reference](../.agents/skills/herdr-agent-messenger/reference.md#local-mailbox)
for their JSON contracts and recovery/evidence requirements. Mailbox commands
do not install a runtime. Legacy prompt routing and Held Messages remain for
nonparticipating traffic; participating same-repository traffic follows the
mailbox policy below.

### Remote mail and code-only worker

Register stable host identities and both SSH directions before using remote mail:

```bash
# On alpha (on beta use --name beta and alpha's configured SSH alias):
python3 "$HAM_CLI" ledger setup --name alpha
python3 "$HAM_CLI" ledger peer add --ssh-alias beta-ssh --canonical-name beta
python3 "$HAM_CLI" ledger peer list
python3 "$HAM_CLI" mail send --to beta-ssh/blue-owl --body 'Inspect when ready.'
python3 "$HAM_CLI" ledger doctor
python3 "$HAM_CLI" ledger outbox
python3 "$HAM_CLI" ledger worker status
# Explicit retry after fixing a permanent error; retains the message/item IDs:
python3 "$HAM_CLI" ledger retry --item OUTBOX_ITEM_UUID
```

Only existing allowlisted concrete SSH aliases are accepted. Discovery uses
structured `result.plugins[0].plugin_root`, then checks protocol 1 and the
canonical UUID; do not run a new protocol against an old installed checkout.
Canonical host names and SSH aliases both address the same registered peer.
Remote status is queried live, not copied into local AGENTS.

Named targets use all repos on that host: no match gives `agent_not_found`;
multiple matches give `agent_ambiguous` with addresses and repos. Upgrade all
participating hosts together before exchanging v8 mail. Older exact-field
receivers reject new payloads as `invalid_message`; the origin retains failed
outbox mail for manual retry after upgrade, not automatic receiver-side hold.
Keep message/item IDs and use `ledger retry --item OUTBOX_ITEM_UUID` after
upgrading; do not create replacement sends. Existing `recipient_changed`
holds still depend on recipient occupancy, not sender repo.

The detached code-only worker holds a per-ledger flock, retries transient
failures FIFO per peer (up to five-minute backoff), sends receipts, sweeps closed
terminals and expires bodies/logs. It survives the launching CLI and exits when
no pending maintenance remains. Failed Herdr access is not proof that a terminal
closed. A failed item is visible and does not block later items; an offline peer
cannot block independent destinations. Explicit retry retains item/message IDs.
Repeated/lost-ACK accepts use the same immutable message ID and return current
state, including permanent dedupe after body retention. A bell failure after
commit is a successful store with a `notification_failed`, `committed:true`
warning, not permission to resend.

`--to main` resolves on the sender's host at send time against
`(repo_id, canonical host, anchor_workspace_id)`, including linked workspaces
in that role group. The immutable message stores a concrete terminal target.
If the group has no main, sending fails visibly; it never uses another group's
main or the repository home. Explicit `HOST/LABEL` mail crosses both workspaces
and repositories. Receipts and withdrawals follow the saved target.

Use `--to [HOST/]main@REPO` to select another repo's main (HOST defaults local).
For example, `--to main@dxp-api` or `--to beta/main@org/dxp-api`.
An exact repo ID wins; otherwise REPO must uniquely match trailing path
components. Multiple repos give `repo_ambiguous`. On the selected host, exactly
one current main must exist across distinct role groups: none gives
`main_unresolved`, several gives `main_ambiguous` with anchor workspace IDs.
Unknown repos also give `main_unresolved`. Remote selection uses exported
computed roles and optional role-scope metadata. Like plain `main`, this saves a
concrete terminal target; it does not elect a main or fall back to home.
Use a concrete `HOST/LABEL` when multiple groups have mains.
The home is the first enabled canonical host and is deliberately read-only in
the user UI; it does not elect or relay workspace mains. Mode/main/member/threshold
mutations belong to the user UI service, not the agent CLI; there is no `repo set`
or home-changing command. Local auto bootstrap does not wait for all peers.
Observed concurrent initial home proposals converge deterministically.

Isolated verification can pin `peer add --remote-root /ABS/WORK_COPY
--remote-ledger-dir /ABS/PRIVATE/ledger --remote-socket /SHORT/PRIVATE.sock`.
Use private local ledger/socket/HOME/XDG/request directories as well.
`HERDR_AGENT_LEDGER_AUTOSTART=0` disables implicit workers (also for explicit
remote-ledger overrides); `ledger worker once|run|ensure` remains explicit.
See the [wire/setup reference](../.agents/skills/herdr-agent-messenger/reference.md#hosts-fifo-transport-and-worker)
for exact JSON, error and isolation contracts. No runtime/global settings are
installed by these commands.

### Modes, roles, and public status

Repositories first seen by HAM from this version default to **auto**: all same-repo
agents participate, eligible queued action mail may auto-start an OMP turn, and
same-repo legacy `send`/`request`/`batch` must use mail instead. Already-known
repositories retain stored settings; without a stored mode they remain **off**
until changed. Host-local (`local:`) repos follow the same default without
propagation. Reads never seed defaults. Off creates no main/worker roles, automatic
wake, or participating-traffic legacy restriction; explicit reads and natural
user-boundary receiving remain available.

Mode, home and wake thresholds remain repository-wide. Main and members use
`(repo_id, canonical host, anchor_workspace_id)`. A linked worktree workspace
joins a deterministically chosen open nonlinked workspace on the same host with
matching Herdr `worktree.repo_key`. The anchor can have no agents. Missing
metadata or no open anchor leaves the workspace in its own scope; git common
directories do not group ordinary workspaces. Workspace IDs never cross hosts.
Only anchor main/member settings apply while grouped. Linked settings are
retained unchanged, not copied or deleted, and apply again if ungrouped.

- **manual:** an explicit active main in the scope is main; chosen members in
  that scope are workers, excluding main. Nonmembers may receive naturally but
  cannot be auto-woken.
- **auto:** an active explicit main from the anchor's settings wins, anywhere
  in the group. Otherwise an active anchor agent is required: the sole group
  agent becomes main, or, with several agents, the unique active main-checkout
  agent. Without that unique choice there is no main. In particular an open
  anchor without agents gives no auto main, even with one linked agent.
  All other group agents are workers. Ungrouped workspaces elect independently.

A designation that becomes inactive or moves out of the scope is ignored on
read without rewriting the setting; auto falls back to the election above.
Main/member settings are host-local and never replicated. Peers use the computed
roles from the origin host; protocol 1 is unchanged and role-scope export
metadata is optional. Schema v9 adds open-workspace metadata, including empty
anchors, without moving existing settings. All HAM processes sharing a host
ledger must upgrade/restart together: old code cannot open v9 storage, and
downgrade needs a backed-up database. OMP/Claude receiving contracts are unchanged.
See [current migration and rollout](migration.md#worktree-role-grouping-schema-v9);
the v7 section is historical and its independent linked-workspace semantics
are superseded.

Schema v10 adds `deliveries.fyi_turn_end` with default 0. Existing v9 deliveries
stay conservatively unflagged. Upgrade ledger and CLI/copied skills together;
older enqueue code can miss the flag. The extension contract is unchanged and
this schema-only policy needs no extension restart. The [package cutover](migration.md#python-package-layout) separately requires enabled-runtime reinstalls and receiver/hook session plus HAM worker/TUI restarts on all five hosts.
Delayed idle FYI uses the existing local delivery timestamp: queued FYI becomes
wake-eligible 300 seconds after local recipient enqueue, including mail already
queued before the update. No new schema, setting, or data migration is needed.
The 300 seconds is minimum eligibility, not a scheduled delivery guarantee;
idle-only FYI normally wakes on a natural event or the next five-minute safety
check, about five to ten minutes after enqueue if other gates permit.

Schema v11 adds local `mail_dismissals` and nullable `messages.sender_context`,
preserving existing v10 payloads and settings. Upgrade/restart all HAM processes sharing a host ledger together;
read-only opens never migrate, old code cannot open v11, and downgrade requires
the pre-upgrade backup. Protocol 1 and receiving-runtime contracts are unchanged.
See [sender dismissal migration](migration.md#sender-dismissal-schema-v11).

Public status is independent of coordination mode:

```bash
python3 "$HAM_CLI" status set review --summary 'Checking the mailbox boundary'
python3 "$HAM_CLI" status list --repo
python3 "$HAM_CLI" status list --repo 'git:host/stable/repo'
python3 "$HAM_CLI" status clear
python3 "$HAM_CLI" repo show
```

`repo show` exposes the caller's host, anchor `workspace_id`, original
`requested_workspace_id`, scope main and members,
and repository-wide mode. `status board`, sidebar roles and borders use each
agent's host-local anchor role group.
`status set PHASE --summary TEXT` updates the caller's phase/summary; it does not
change Herdr's `turn_state`. Phase is projected to `$recap`. HAM-owned pane
borders show `[메인] alias · summary` or `[워커] alias · summary`, omitting
missing parts. The alias precedes the summary so Herdr's width truncation clips
the summary first. `status clear` removes phase/summary, not alias or active role.
An existing user border is preserved. Agents keeps the role before the
addressable alias; status still works in off mode without a role prefix.
`status list` without a filter lists stored local status; bare `--repo` selects
the caller's repository and `--repo ID` selects that identity. For the rich
local/registered-peer read use `status board`, not a legacy parent `--host` flag
on `status list`. Legacy `status --address HOST/LABEL` remains a recipient read.

### User TUI: quick-send, settings, and uncertain claims

Open **HAM: Mailbox (Right Split)**, **HAM: Mailbox (Tab)** or **HAM: Mailbox
(quick send)** from the command palette (`mailbox-split` / `mailbox-tab` /
`mailbox-popup`, plugin `herdr.agent-messenger`). The quick-send overlay closes after a
successful send result; failed sends keep input open. Actions do not change
global `prefix+m`; optionally bind one only after upgrading all hosts.
Reuse checks stable pane/terminal IDs, not display labels. The split action reuses
the registered mailbox only in the opener's tab; otherwise it opens and registers
a right split, closing the old mailbox only if its visible first line contains
`NAV ·`. The tab action still reuses the workspace's mailbox across tabs.
`q` closes only the owned view, confirming before discarding nonempty drafts.
At top level, Esc closes only the quick-send overlay; in input/dialogs it backs out.
Quick send, messenger, Held Messages, and HAM Skill use Herdr's temporary zoom
overlay, restoring prior focus/zoom on close. HAM sets no width/height or layout
probe; the minimum stays Herdr 0.8.0. Existing `mailbox-popup` IDs are unchanged.
See [placement rationale and upstream sources](ui-reference.md#herdr-overlay-placement).

Responsive **Agents**, **Threads**, and read-only **Detail** regions replace
exclusive screens. Below 80 columns or 18 rows only the focused region appears;
80–139 columns stacks lists beside Detail, and 140+ shows three columns.
Below 32 columns or 10 rows a resize notice appears without losing drafts,
cursor, mode or selections. In NAV, Tab/Shift+Tab, ←/→ or h/l changes focus;
↑/↓ or j/k selects rows; PgUp/PgDn/Home/End pages or jumps. Detail arrows scroll.
Digits never navigate. `s` opens Settings, `?` help, `e` diagnostics in Detail,
and `r` refreshes. Detail Enter does nothing.

Agents groups by host with stale/error headings. Alias, turn, unread and native
receiver readiness share a row with a dim role/phase/summary line beneath.
Stale peers retain their snapshot with unread `?`, not closed agents.
Detail auto-previews the most recently focused list selection, with full agent
fields and distinct status-update/observation timestamps in local time plus age.
Threads contains histories, direct submissions and pending/failed OUTBOX.
**Read-only viewing never ACKs, delivers, handles or resolves mail.**

The Settings overlay has exactly **seven mutable rows**:

| Row | Value / default |
| --- | --- |
| `mode` | `off`, `manual`, or `auto`; new repos default to `auto`; known repos without mode keep `off` |
| `main` | `{"host":"canonical","terminal_id":"term_…"}` or `null` |
| `members` | Unique array of those targets; default empty |
| `idle_minutes` | `3` minutes |
| `coalesce_seconds` | `30` seconds |
| `wakes_per_hour` | `6` wakes per hour |
| `max_hop` | `10` hops |

Mode and the four thresholds apply to the repository. Main and Members rows
identify the Mailbox opener's host-qualified workspace (`Main (workspace …)` /
`Members (workspace …)`), resolved from `HERDR_HAM_OPENER_PANE_ID`; they do not
follow an arbitrarily selected remote agent. In all-repositories view the
existing repository selection still applies; without one repo the editor is
disabled with an explanation.

↑/↓ selects a row, Enter edits, and Esc closes. `Target: host/alias` is the
selected Agents row: `m` sets it as main, Space toggles manual membership, only
when it is active and in the opener's settings scope. Out-of-scope targets are
rejected by the service. Every mutation requires confirmation with Cancel
selected by default.

Each threshold is an integer from 0 to 10000. The four threshold rows are saved
as one versioned, repo-wide `thresholds` field. Home, computed main,
version/origin stamps, conflicts and propagation pending are **read-only**, not
hidden extra editors. Replicated repo-wide fields choose the greatest
`(version, canonical origin)` pair; equal-version competing origins use the
lexically greater canonical origin. Workspace main/member edits stay local.
A new edit allocates a newer observed version. Conflict details wrap without
dropping their contents.

Saving is single-flight and visibly pending. You may open a text editor while
a save is pending, but a second save submission or member/main toggle is
rejected, not silently queued; the edit buffer is retained. Navigation and
closing remain responsive. The authoritative result is matched to the full
repo/host/workspace scope and applied immediately; an older snapshot cannot
overwrite it. Repo-wide propagation can remain pending while a peer is offline;
workspace edits do not propagate. Local saving does not require all peers online.

Agents Enter opens inline mail input; Threads Enter opens a reply to the latest
message with a live, non-stale agent resolved by host/terminal identity.
Stale/unresolvable recipients are blocked; missing native receivers warn but
still allow mail. UI mail is `sender=user`, without a subject. Every new compose,
including a reply or reopened draft, resets to `action`. Ctrl+G toggles `action`
/ `fyi` for that compose; the selected kind is sent explicitly. The CLI default
remains `fyi`. Enter sends immediately without confirmation; blank bodies are rejected.
Shift+Enter adds a newline via the requested kitty keyboard protocol, including
through herdr in compatible terminals. Alt+Enter is the Moshi/mosh fallback
because they cannot negotiate the protocol. Ctrl+J is not a newline key.
`HAM_MAILBOX_NO_KITTY=1` disables the request. Printable keys, including q, ? and
digits, are text. Arrows/Home/End/Backspace/Delete edit, and up/down moves between lines.
Esc keeps the per-recipient/reply text and cursor; Ctrl+R refreshes in input.
F1 opens help while typing and returns to the same input. Success clears only
the unchanged submitted draft and closes input; pending-send edits survive.

Ctrl+D toggles direct input; Enter requires confirmation (default Cancel).
Tab or ←/→ selects a button and Enter executes it. **Direct may interrupt**:
it uses `Message from user (HAM):` and separate accepted/unknown/failed transport
records, never native delivery receipts. Inspect uncertain results before resending.

Threads `w` withdraws eligible locally originated mail; `t` retries the existing
OUTBOX identity. Both require exact-target confirmation. `delivering` is
**UNCERTAIN**; `a` / `n` records operator-confirmed applied / not-applied.
First supply nonempty evidence, then confirm the exact message/claim ID, old
agent, generation and current state, even if the terminal now has a new session.
Cancel is the default; Tab or ←/→ selects, Enter executes and Esc cancels.
Applied preserves that old claim; not-applied releases only that claim without
submitting it again. This is an audited **operator** decision, not native
request/journal proof, model understanding or handling. Never automatically
replay an unknown claim or send a replacement while application is uncertain.

### Receiving clients and evidence limits

**OMP:** opt-in receiving is limited to the root Herdr session and a supported
native session file; the extension delegates ledger work to Python. In a
supported TUI, automatic wake needs an empty editor, quiet input for
`idle_minutes`, Herdr `turn_state` of `idle` or `done`, an idle OMP runtime with no pending message, `willContinue`, or retry
hold, an eligible action or FYI and participating role, plus coalescing/hourly/hop
limits. Eligibility is rechecked in the same tick immediately before enqueue.
It uses agent-attributed `nextTurn` + `triggerTurn`, never steer. Focus itself
does not block this wake; it is not the legacy focused-pane hold.

For OMP registration, `native_session_pending` means Herdr's native-session
publication has not arrived. The receiver shows waiting during its bounded
retry window and clears its own status on success; exhaustion shows unavailable.
HAM never publishes that path itself. Conflicting reported paths remain
`stale_session`.

Eligible action wakes promptly. Queued FYI becomes wake-eligible 300 seconds
after local recipient enqueue, not guaranteed to wake at that instant. Natural
events and the five-minute safety scan normally trigger a batched idle wake
after about five to ten minutes. Existing queued mail uses its local delivery
timestamp, not the sender's message creation time.
FYI arriving during a turn is delivered right after that turn under existing
wake gates: local enqueue records `delivery.fyi_turn_end` only for fresh
`working` state (local reconciliation's `agents.last_seen` within 15 seconds),
bypassing the 300-second delay. Later state changes do not retroactively set
the flag. All wake gates still apply, including participation and idle state.
The flag is local delivery metadata, not a change of mail kind or wire payload.
Natural user turns can receive both kinds even in off mode or for manual
nonmembers. Wakes use the same bounded bundle: at most eight messages / 8 KiB
total, each body bounded to 2 KiB with exact-message-ID read instructions for
truncation. Action wakes can also bundle FYI younger than 300 seconds.
FYI-only bundles ask the recipient to read and continue, replying only if the
information changes its work.
The runtime watches the local bell with `fs.watch` and has a five-minute
code-only safety check. Young ordinary FYI keeps `inspect.has_action=false`
until eligible; it does not arm a deadline or pre-eligibility one-second
draft/status polling. Once eligible, all normal wake gates still apply.
Its ACK proves exact claimed content/hash in the
same-session active-branch journal, **not** provider-request inclusion, model
understanding, or handled work.

**Claude Code:** opt-in receiving uses bounded **SessionStart** and
**UserPromptSubmit** hooks only. There is no Stop hook, idle wake, or worker
that starts a Claude turn. Outside Herdr, the hook returns before reading input,
discovering the plugin, or opening the ledger. Activation environment variables
are not identity: receiving requires verified foreground-root process ancestry,
the native transcript UUID and current generation. An unresolved identity
leaves mail queued; unknown claims stay held.

Hook stdout/exit 0, an attachment, or emitted `additionalContext` alone is not
a delivered receipt. Native confirmation has two evidence paths:

- SDK system-blob evidence requires the exact bundle in the same-session native
  request blob plus fresh `api-request.tail` correlation
  (`claude:api-request:`).
- The typed ordinary-TUI observer requires raw/rendered native hook records
  matching the exact claim bytes/hash and a native causal request witness
  (`claude:accepted-journal:`). This proves **host-context application**, not
  exact provider-wire bytes, provider attestation, model self-report, or
  understanding.

Both paths record `confirmation_source=native`; an operator decision remains
`operator`. The authorized saved run `functional-live-b57ae929e8a7/result.json`
completed in 21.69 seconds with pinned native Claude 2.1.301. Actual production
SessionStart context and the current-generation worker produced a persisted
`delivered`, `via=hook`, native `claude:accepted-journal:` ACK. In the same live
registered process, manual-worker and auto-main windows each lasted 6.02 seconds
with ten samples: the code worker remained active, action + FYI stayed queued,
and no additional primary turn or claim appeared.

This run used one authorized harmless prompt and one primary root request.
Auxiliary `quota_check` / `prompt_suggestion` traffic was tracked separately;
this is not a zero-all-provider-traffic claim. The returned mail-only nonce was
a separate functional response check, never the ACK basis. Herdr already knew
the session UUID: cold-unreported binding CAS has unit evidence only, **not
actual-live proof**. The original closed case remains held, with no retroactive
ACK. The observed host-context application does not attest exact provider-wire
bytes or establish blanket runtime/provider success or deployment.
Provider/session-limit failures are
separate and do not prove successful model processing. Actual OMP and physical
cross-host integration acceptance is also in flight; these mechanics are not
a whole-stage PASS or deployment claim.

**Native Claude smoke safety:** keeping the real HOME/auth while isolating
`XDG_DATA_HOME` does not isolate the native updater: it has repointed the global
`~/.local/bin/claude` alias into disposable work-storage. Launch through a
**private symlink named `claude`** whose target is the pre-proven absolute
versioned executable and original inode (the accepted run used 2.1.301).
Launching the numeric `2.1.301` basename directly failed Herdr client detection;
do not fake metadata or use `exec -a` to hide that failure. Set documented
per-process `DISABLE_AUTOUPDATER=1` before launch. Record the original global
alias's `lstat`, owner, link target and inode baseline, then verify it unchanged
afterward. Keep existing HOME/auth only; never copy credentials. Preserve and
report drift rather than repairing unrelated state. Separately authorized
recovery must compare-and-swap only the exact owned alias target: the observed
updater side effect was repaired atomically to the original 2.1.301 launcher,
private 2.1.302 data was preserved, and the accepted run left the alias unchanged.
Record the binary/version: SDK and TUI 2.1.301 emit different native evidence
formats, and stdout alone never acknowledges a claim.

**Codex:** use the skill at work boundaries: `inbox read`, do the relevant work,
then explicitly `inbox handle --message UUID`. Reads by any client or subagent
are view-only. Handling can move queued → handled without a delivered timestamp;
replying atomically handles an addressed parent. There is no Codex automatic
receiver/wake adapter, and a pull read must never be reported as native delivery.

### Opt-in runtime installation and deployment order

Installing the **skill** copies client instructions. Receiving runtimes require
separate explicit consent, either in the interactive installer, through
`--runtime omp|claude|all`, or through the commands below. Skill installation
does not change coordination mode or global bindings. On each host, select only
the clients you actually use, after checking the read-only summary:

```bash
python3 "$HAM_CLI" runtime status
python3 "$HAM_CLI" runtime install omp
python3 "$HAM_CLI" runtime status omp
python3 "$HAM_CLI" runtime install claude
python3 "$HAM_CLI" runtime status claude
# Later, remove only the selected HAM-owned runtime:
python3 "$HAM_CLI" runtime uninstall omp
python3 "$HAM_CLI" runtime uninstall claude
```

All three client-specific operations accept `--destination DIR`; the no-client
summary does not. OMP defaults to
`~/.omp/agent/extensions` and owns only `ham-mailbox.ts` and
`ham-mailbox.install.json`; it leaves Herdr's extension alone. Claude defaults
to `CLAUDE_CONFIG_DIR`, or `~/.claude`, and owns `hooks/ham-mailbox.py`, its
manifest, and the exact HAM SessionStart/UserPromptSubmit entries in
`settings.json`. Install merges and uninstall removes only those owned entries,
preserving unrelated hooks and configuration. Ownership/checksum validation
refuses foreign, modified, or symlinked managed targets; do not delete another
integration to overcome a conflict. Restart/reload only selected sessions.
An installed-file status is not proof that a receiving session is ready.

Deploy in this order, separately on every participating host:

1. Upgrade the protocol-capable **plugin first**; do not point new peers at an
   old installed endpoint.
2. Install/update the matching skill and opt-in receiving runtime. Confirm
   selected receivers' identity/readiness before enabling participating policy.
   Codex uses the explicit pull workflow rather than an invented runtime.
3. Enable the intended repository mode/main/members in the user TUI, then
   migrate the user-chosen global action binding and status/recap instructions
   last. These are deployment instructions, not a claim they were executed.

Storage uses a private 0700 state directory, 0600 SQLite database and WAL.
Final message bodies expire after 90 days; wake/status logs after 30 days.
Each worker run performs startup cleanup immediately after taking its lock,
regardless of the monotonic clock's epoch, including one-pass/no-work runs.
A continuing worker repeats cleanup hourly.
Dedupe hashes, compact receipts and withdrawal tombstones remain. The UI checks
the local bell every second and remote live status every 30 seconds
independently; these and worker/OMP safety checks are code-only, not model
polling. There is no database replica, ASR router, urgent channel, or ownership
framework.

### Participating policy versus legacy prompt traffic

For same-repository traffic where **both sender and recipient participate** in
manual/auto coordination, legacy `send`, `request`, and `batch` refuse with
`use_mailbox`; use `mail send` instead. A batch resolves and preflights **all**
targets before any submission: one refusal or failed lookup produces zero
submissions. This prevents accidents, not adversarial access.

Off-mode, other-repository and otherwise nonparticipating legacy traffic keeps
the prompt/hold/lifecycle behavior described below. User direct input is a
separate explicit path, not an agent policy bypass. New-session initial
assignment uses atomic spawn, not a legacy request to the new recipient.



## CLI commands and addressing

The bundled skill is split into a short [SKILL.md](../.agents/skills/herdr-agent-messenger/SKILL.md) for common workflows and an on-demand [reference.md](../.agents/skills/herdr-agent-messenger/reference.md#command-and-flag-reference) with exhaustive flags/defaults/units/ranges. Commands include `mail`, `inbox`, `repo`, `ledger`, `runtime`, status operations, and the retained legacy routing commands. Every command supports `-h` / `--help`; the detailed legacy tables below do not replace the mailbox/runtime reference.

The following legacy prompt examples apply only where the participating policy permits them. Run **from the plugin/checkout root**; for another working directory use the absolute path to the bundled script. An installed skill also has `scripts/herdr_agent_messenger.py` relative to its own directory.

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py list --host local
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py list --host macbook-pro
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py status \
  --address macbook-pro/purple-koala --verbose
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py request \
  --address macbook-pro/purple-koala --message 'Inspect the change and report blockers.' \
  --timeout 120000 --output-lines 160 --output-chars 16000
```

Copy `list` → `address` → `--address` directly; it works for `status`, `send`, `read`, and `request`, and as a batch item's `address`. Alternatively use `--host HOST --label LABEL`, or a returned opaque `--route TOKEN` (exactly one selector). `--host` defaults to `local`; a non-default host disagreeing with `--address` produces `conflicting_address`.

Only literal `local` selects the current Herdr server. Every other host must be a concrete configured SSH alias—even a hostname matching this machine still means SSH. Never use a bare label as a global address: labels can repeat across hosts and be mistaken for a client's own subagent names. Every operation resolves the current occupant again; a label does not promise continuity after restart.

The eight original routing commands return compact output by default; `--verbose` restores full diagnostic payloads. `list` returns each agent's `address`, `status`, and `workspace`; legacy recipient `status` returns `address` and `status` (plus `stale: true` when needed). Compact request results omit routes and agent/baseline metadata, and expose cleaned reply text as `response.text`. TUI borders, status footers, and echoed prompts are removed. Use `--verbose` for raw/full response fields such as `response.output`. The `list --legacy` alias still selects verbose output.

| Flag | Commands | Default and meaning |
| --- | --- | --- |
| `--verbose` | The eight original routing commands | Off; show full payloads instead of compact views. |
| `--defer-timeout MS` | `request`, `send`, `batch` | `180000` milliseconds (3 minutes); time to hold a focused recipient before requiring a decision. This is separate from the command's `--timeout` wait budget. |
| `--wait MS` | `request-status` | `0` (one observation); otherwise stops on a state, phase or `error_code` change, a terminal state, or the deadline, not response-text growth. This numeric option differs from the boolean `--wait` on `send` and `batch`. |

### Start a new labeled session

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py spawn \
  --kind omp --cwd /path/to/project --placement tab \
  --message 'Review the project and report blockers.'
```

The optional `--message TEXT` and `--message-file PATH` are mutually exclusive.
The file is UTF-8 and caller-local, including when the new session is remote.
Keep HAM flags before `--`; arguments after it belong to the new agent.
Without either message option, spawn starts a session without an assignment.
With one, readiness and the initial submission are one persisted operation:
the immutable target/body and submitting state are saved before transport.
Accepted input is not native mailbox delivery or a completed reply. An unknown
result may already have submitted; preserve its operation ID and usable
placement for inspection. Never resend, issue a follow-up legacy initial
request, or spawn a replacement merely because acceptance is unknown.

The default placement is a right split from local `HERDR_PANE_ID`. For an SSH split, provide `--from-pane` and `--cwd` explicitly. Local cwd defaults to the invocation directory; SSH cwd is always required and refers to a path on that host. `--placement tab` can use `--workspace`; absent that, HAM infers the source workspace from `--from-pane` or local `HERDR_PANE_ID` when available, otherwise leaves the choice to Herdr. `--placement workspace` creates a separate workspace. New placements are not focused automatically.

`--label` chooses an explicit nonblank name without `/`; otherwise HAM picks a free `color-animal` label. `--workspace-label` controls a new tab/workspace label; its default is the explicit or generated agent label. `--direction right|down` only affects splits. `--timeout` is readiness time in milliseconds (default 90000, range 1–300000), not time to answer the initial prompt. Agent-specific flags must follow `--`:

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py spawn \
  --kind codex --host macbook-pro --cwd /path/on/mac/project \
  --placement workspace --workspace-label Review -- --model MODEL
```

Compact spawn results contain `address`, palette `marker`, `created` (`pane`/`tab`/`workspace`), `pane_id`, `workspace_id`, and `tab_id` when available. Reporting flags `label_metadata_reported` / `placement_label_reported` appear only when false. Use `--verbose` for label/color, host, kind, cwd, route, agent metadata, and both reporting flags. A custom nonpalette name has an empty marker and no palette metadata. A successful session need not have successful optional metadata reporting; inspect false flags. Startup failure includes cleanup information; inspect for surviving resources before trying again.

### GUI routes

The overlay's coordinator prompt supplies an absolute CLI path and host-qualified addresses, so it works even without a globally installed skill. For GUI selections supplied as opaque route tokens, follow the supplied `--route` commands directly; do not decode or modify tokens or replace them with guessed Herdr commands. Compact results use addresses rather than exposing routes; `--verbose` includes routes for diagnostic/GUI-style routing. If `route_refreshed: true`, retain the returned token. Refresh is allowed only when conservative continuity checks identify one safe current occupant; otherwise report `route_expired`. See [route safety](ssh-and-routing.md#route-safety).

## Legacy request lifecycle and exit codes

For policy-permitted existing-agent prompt traffic, prefer `request` to lower-level `send`. Run it from the coordinator's active Herdr agent pane so the sender can be verified. Once delivery is allowed, HAM captures a baseline, submits once without Herdr's ambiguous lower-level `--wait`, observes a fresh requested working→settled cycle, and returns bounded new output. If the recipient was already working, its first settlement is only an old-turn boundary; HAM requires a second working→settled cycle. This lifecycle is not a mailbox native-delivery receipt.

### Focus-based delivery holds

Agent-initiated CLI `request`, `send`, and `batch` deliveries are held when the recipient pane is focused in Herdr. Self-send fails immediately with `recipient_is_sender` before any focus check, even when the sender pane is focused; it is never held. HAM cannot inspect the input box: focus is a safeguard, not typing detection. The request is `deferred`, with `submitted: false`, until focus leaves before the defer deadline. A background worker then delivers it, even if the original CLI wait has ended. A held `send` returns immediately with a `request_id` and exit 3, regardless of `--wait`.

If the pane stays focused for `--defer-timeout` (default `180000` milliseconds, or 3 minutes), the request becomes `awaiting_decision` and HAM sends a Herdr notification. Open **HAM: Held Messages** from the command palette, select a request with Up/Down, and choose **Push** (`p`) or **Cancel** (`c`); `q` or Esc closes the overlay. Push can combine the message with unsent text in that pane. Cancel ends the request as `submission_failed`, with phase and `error_code` `delivery_cancelled` and `submitted: false`. **After the timeout, held messages never auto-push, even when focus later leaves.** You must choose Push or Cancel.

After deferred delivery or Push, the worker observes the submitted request about every 0.5 seconds until it becomes terminal or 30 minutes have passed since submission. Use `request-status` to read the saved result; after that limit, the command can still advance observation. The worker exits only when no deferred, awaiting-decision, or watched requests remain.

HAM overlay direct sends and coordinator delegation are user-initiated and are never held. Known limitation: typing a draft and then switching panes without submitting can still merge that draft with an incoming message.

For SSH recipients, HAM checks focus on the recipient's host. The hold queue, worker, and **HAM: Held Messages** live on the **sender host**. Timeout notifications are sent to both hosts; the recipient-side notification names the sender host so you know where to decide. If the recipient disappears or is replaced before delivery, HAM fails the undelivered request rather than sending to the replacement.

### States and follow-up

| State | Meaning |
| --- | --- |
| `submission_failed` | Resolution failed, or prompt rejected/cancelled before submission; terminal. |
| `deferred` | Recipient pane is focused; phase `deferred_recipient_focused`, nonterminal, `submitted: false`. HAM owns delivery; do not resend. |
| `awaiting_decision` | Hold deadline passed; phase `awaiting_decision`, nonterminal, `submitted: false`. Choose Push or Cancel on the sender host. |
| `submitted_working` | Submitted/possibly submitted, recipient working; completion not proven. |
| `submitted_settled` | Fresh requested cycle observed; terminal. |
| `submitted_unknown` | Matching requested turn cannot be confirmed; usually nonterminal, but occupant change makes it terminal. |

| Exit | Meaning and next action |
| --- | --- |
| `0` | Settled request; all batch items `succeeded`; or successful other-command payload. Review output before trusting claims. Lower-level send success is not lifecycle settlement. |
| `1` | JSON error envelope, `submission_failed`, or batch containing `failed`/`cancelled`/`timeout`. Inspect delivery evidence before retrying; this does not always mean nothing was sent. |
| `2` | Argument usage error on stderr. Correct syntax. |
| `3` | **HAM still owns the request; do not resend.** Request/send is `submitted_working`, `submitted_unknown`, `deferred`, or `awaiting_decision`, or a batch has `submitted`/`deferred` items and no failures. Advance IDs with `request-status`; held requests may require a decision. For no-wait items without IDs, inspect `status`/`read`. |

Compact lifecycle payloads have `request_id`, `state`, `terminal`, `submitted`, `phase`, and `address`, with optional `error_code`, `error`, `defer`, and `response`. Null/absent optional fields are omitted. Held records expose `defer.reason: recipient_focused` and `defer.deadline`. `--verbose` includes full metadata and response fields. Preflight failures instead return `{"error":{"code":"...","message":"..."}}` without `request_id`. Neither all successful CLI payloads nor every batch item has a request ID.

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py request-status \
  --request-id REQUEST_ID --wait 30000
```

Without `--wait`, this command advances one saved nonterminal request with a fresh observation. With `--wait MS`, it stops on a state, phase or `error_code` change, a terminal state, or the deadline, not response-text growth; it never creates a duplicate submission. Refreshing a held request may deliver the saved message once focus leaves before its hold deadline. Changed-only reporting is separate: compact output includes `changed: true` when a state, phase, error code, or response-text change is reported; unchanged output is only `request_id`, `state`, `terminal`, `submitted`, and `changed: false`. `--verbose` always prints the full payload.

Preserve the ID on the same sender host/state location. The shared queue uses `HERDR_AGENT_REQUEST_STATE_DIR` when set, otherwise `${XDG_STATE_HOME:-$HOME/.local/state}/herdr-agent-messenger/requests`; the legacy `herdr-agent-labels/requests` directory is used only if the new directory does not exist. `HERDR_PLUGIN_STATE_DIR` is not used. `request-status` cannot reconstruct a complete working→settled cycle missed between observations. If `phase: recipient_changed` after submission, HAM stops capture and keeps the original route rather than attaching replacement-agent output. This is terminal `submitted_unknown` with `error_code: recipient_changed`; report the uncertainty instead of repeatedly polling or resending. Before submission, a lost/replaced held recipient instead becomes `submission_failed`.

Inspect response fields independently:

- `response.truncated`: true only when reply text itself was cut by output bounds or a failed read, in compact and verbose results. Omitting older history or losing baseline overlap alone does not set it. False does not prove correlation or a reliable complete transcript.
- `response.correlated`: fresh requested cycle observed with reliable baseline and read; false means this is not a proven completed answer for the request.
- Optional `response.anchored: true`: when baseline overlap could not be recovered, capture began at the last matching sender prompt header (`Message from HOST/LABEL:`). This removes preceding startup/history text but is not proof of completion, completeness, or unique correlation among multiple prompts from that sender.

Replies are scraped from the recipient's TUI, not a structured assistant-message API. Narrow panes hard-wrap lines; prefer a tab or workspace placement for long replies. Anchoring does not repair hard wraps.

## Batch coordination

For participating workers use mailbox messages, not legacy batch. For a policy-permitted legacy batch, first list and verify each requested host/label; all targets must pass lookup/policy before any submission. Decompose work into non-overlapping assignments and send only the context each worker needs unless the user explicitly requests direct broadcast. HAM mechanically dispatches the already-tailored messages; it does not interpret, split, or rewrite them.

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py batch \
  --requests-json '[{"address":"local/yellow-falcon","message":"Review API behavior."},{"route":"ROUTE_TOKEN","message":"Review the UI."}]' \
  --wait --timeout 120000 --max-workers 4
```

`--requests-json -` reads stdin; a `{"requests":[...]}` wrapper is also accepted. Supply a nonempty array with exactly one of `address` / `route` and a nonblank string `message` per item. Duplicate resolved targets fail as `duplicate_route`, even if one uses an address and another a route. Results remain in input order. The concurrency limit is 1–8, default 4; timeout is per request, positive milliseconds, default 120000. `--wait` is the default and uses lifecycles; `--no-wait` returns on acceptance without capturing a settled answer.

| Per-item status | Meaning |
| --- | --- |
| `succeeded` | Matching request settled in wait mode. |
| `submitted` | Acceptance confirmed but settlement not verified; never resend. |
| `deferred` | Focus hold or user decision pending; HAM owns delivery. Use the request ID and never resend. |
| `failed` | Invalid item, target resolution failure, or submission rejection. |
| `timeout` | Acceptance unconfirmed or dispatch timed out; possibly delivered. |
| `cancelled` | Dispatch/submission cancelled; inspect acceptance evidence. |

Aggregate `succeeded` means all items were accepted or retained by HAM (`succeeded`, `submitted`, or `deferred`), not necessarily delivered or settled. `partial` means only some reached those statuses; `failed` means none did. The process exit code also checks per-item completion/failure; a batch with `submitted` or `deferred` items and no failures exits 3. Held items have lifecycle IDs even in no-wait mode; preflight failures and immediate no-wait sends may not. Compact items use `address`, `status`, and optional `request_id`, `state`, `error_code`, `error`, and `response` (`text`, `truncated`). Use `--verbose` for full item details and `request-status` for the full lifecycle response, including anchoring metadata.

Wait for every requested worker or clear terminal failure. Review responses against the workspace, follow up on inconsistencies, and synthesize unavailable hosts, unverified claims, uncertainty, and remaining risks. Retry only known-undelivered failed items, never the whole mixed-result batch.

## Error recovery reference

The [complete error code catalog](../.agents/skills/herdr-agent-messenger/reference.md#error-code-catalog-and-retry-policy) lists every category and code. Recovery depends on delivery evidence, not merely exit 1:

| Error codes / category | Recovery / retryability |
| --- | --- |
| `use_mailbox` | Both endpoints participate in same-repository manual/auto coordination. Use `mail send`, not a legacy prompt or bypass. A batch policy/lookup preflight failure submitted no targets. |
| `invalid_address`, `conflicting_address`, `invalid_defer_timeout`, other `invalid_*` input codes, `empty_message`, `empty_batch`, `missing_address`, `duplicate_route` | Fix rejected input; `--defer-timeout` requires positive integer milliseconds. Retry only the undelivered operation/items. Never invent IDs or routes. |
| `agent_not_found`, `agent_ambiguous`, `invalid_route`, `route_expired`, `route_ambiguous`, `resolve_failed`, `recipient_is_sender` | Relist/reselect rather than guess. A post-submission resolution error means resume observation, not resubmit. Create only when asked. |
| `host_not_configured`, `host_unavailable` | Restore authorized SSH/Herdr connectivity. Local sandbox/socket denial requires socket access; failed discovery does not mean missing agent. |
| `sender_unavailable`, `sender_probe_failed` | Use the current Herdr agent pane. Probe failure is before submission; obtain local-socket access for sandbox/socket errors, then retry that exact undelivered request only. |
| `prompt_failed` | Submission rejected; fix cause before retrying known-undelivered work. |
| `prompt_acceptance_unknown`, `prompt_timeout`, `wait_timed_out`, `timeout` | Possibly delivered / completion unknown. Preserve ID and use `request-status`, or inspect recipient if no ID. Never blindly resend. |
| `prompt_cancelled`, `cancelled` | Before submission: may retry; after submission: cancellation only stops waiting, not recipient work. Inspect `submitted`. |
| `delivery_cancelled` | User cancelled a held message before submission. Terminal `submission_failed`, `submitted: false`; respect the cancellation rather than automatically resending. |
| `recipient_changed` | Occupant changed. Before submission, a held request fails undelivered; after submission, the result is terminal uncertainty. Do not scrape replacement output or resend the old request. |
| `request_not_found`, `request_state_invalid`, `request_state_unavailable` | Check ID/state location/permissions; storage failure can follow submission, so inspect recipient before retrying delivery. |
| `cwd_required`, `sender_pane_unavailable`, `label_unavailable` | Fix spawn cwd/source pane/label availability before retrying. |
| `placement_failed`, `agent_start_failed` | Inspect cleanup details and possible surviving session/resource before retrying startup. |
| `cli_not_found`, `internal_error`, `dispatch_failed`, `invalid_sender_result`, defensive `invalid_command` | Repair installation or investigate; unexpected failure is not evidence of non-delivery. |

Local socket access is needed even for a remote request because HAM verifies the sender locally. For a batch `sender_probe_failed`, retry only those failed items after granting access; never replay delivered, submitted, unknown, or timed-out items. Do not bypass SSH host-key verification or alter trust settings to make a request succeed.

## Legacy lower-level send and read

`send` defaults to `--wait` and Herdr's completion signal, unless the recipient is focused: then it returns a deferred lifecycle record immediately, even with `--no-wait`, and HAM owns later delivery. An immediate send returns compact `sent`, `address`, and `waited`, plus nonempty `warnings`; `--verbose` restores full details. A recipient already working produces `recipient_already_working` and, in verbose output, `wait_can_track_submitted_turn: false`; its completion signal may belong to old work. Prefer lifecycle `request`. An immediate `send --no-wait` only confirms acceptance and provides no lifecycle request ID. SSH loss/process interruption after acceptance can produce `prompt_acceptance_unknown`; inspect the recipient before retrying.

`read` defaults to 120 recent lines / 65536 UTF-8 bytes and accepts positive `--lines` / `--max-bytes` limits plus a prior `--cursor` (`--watermark` alias). Compact output contains `address`, cleaned `output`, `delta`, `truncated`, and an opaque new `cursor`; `--verbose` also exposes raw output, `cursor_status`, and routing metadata. Reuse the cursor to suppress unchanged output. Terminal screens may be rewritten, not append-only logs: an unsafe/expired cursor returns a bounded fresh snapshot (`delta: false`), and a malformed cursor produces `invalid_cursor`. Do not infer progress from line numbers or claim full output when `truncated` is true.

## Use HAM without the plugin

HAM can run with Herdr without installing/enabling the plugin. Keep a persistent checkout: the skill wrapper loads router modules from it. Copying only the skill directory is not a self-contained installation.

```bash
git clone https://github.com/zerodice0/herdr-agent-messenger.git \
  "$HOME/.local/share/ham"
mkdir -p "$HOME/.agents/skills" "$HOME/.claude/skills" "$HOME/.omp/agent/skills"
ln -s "$HOME/.local/share/ham/.agents/skills/herdr-agent-messenger" \
  "$HOME/.agents/skills/herdr-agent-messenger"
ln -s "$HOME/.local/share/ham/.claude/skills/herdr-agent-messenger" \
  "$HOME/.claude/skills/herdr-agent-messenger"
ln -s "$HOME/.local/share/ham/.agents/skills/herdr-agent-messenger" \
  "$HOME/.omp/agent/skills/herdr-agent-messenger"
```

Use a free destination for each symlink; do not overwrite an existing skill.
The symlinks let the wrapper resolve the source checkout without a registered
plugin. Copied user-scope installs instead rely on the registered plugin root.
Update the source-backed installation with:

```bash
git -C "$HOME/.local/share/ham" pull --ff-only
```

Plugin-free HAM retains address/label request, wait, read, batch, and `spawn` routing; `spawn` chooses and registers its new session's label. It does not supply the overlays, command-palette installer, automatic labeling of unrelated detected agents, or the agent-detected hook. Existing unnamed agents may be assigned unique names explicitly:

```bash
herdr api snapshot
herdr agent rename <pane-id> yellow-falcon
```

Herdr must be installed and running locally and on every selected SSH host. Remote hosts must be concrete aliases in configured SSH config (normally `~/.ssh/config`).

## Test isolation

Run the local Python and Bun suites with cwd set to the plugin checkout root:

```bash
python3 -m unittest discover -s tests -t .
bun test tests/omp_mailbox_runtime.test.ts
```

Each Python test module imports `tests.ham_test_support as ham_test_support` before product modules. Its
test-only tripwire rejects attempts to bootstrap the runner's default ledger
(including HOME, XDG state, an inherited ledger override, and the account's real
home), before any directory or schema is created. Even a caught tripwire fails
the responsible test. Fixtures must supply a private ledger directory or private
HOME/XDG environment to every code path they exercise; an explicit private
`LedgerStore` alone does not isolate incidental stores opened by other helpers.
The guard is not imported by production commands.
