# HAM agent skill

[한국어](ko/skill-guide.md) · English · [README](../README.md)

HAM lets Codex, Claude Code, and omp message current Herdr agents **and start new labeled interactive sessions** without opening the popup. The canonical skill name is `herdr-agent-messenger`; **HAM** is its shorter user-facing name.

## Install with the plugin

Open **HAM Skill** from Herdr's command palette, or press `Ctrl+G` in Agent Messenger. Select Codex, Claude, or omp at **System** (user-wide) or **Project** (active Herdr workspace) scope. Press `?` for the invocation guide.

| Client | System/user destination | Project destination |
| --- | --- | --- |
| Codex | `~/.agents/skills/herdr-agent-messenger` | `<project>/.agents/skills/herdr-agent-messenger` |
| Claude Code | `~/.claude/skills/herdr-agent-messenger` | `<project>/.claude/skills/herdr-agent-messenger` |
| omp | `~/.omp/agent/skills/herdr-agent-messenger` | `<project>/.omp/skills/herdr-agent-messenger` |

A checkout already supplies the canonical Codex skill and Claude bridge. Install the omp target to make the skill available through omp's skill search. Installer badges mean `✓` current, `↑` update available, `○` not installed, and `!` conflicting files. If a newly installed skill does not appear, start a new client session.

The installer does not overwrite an unrelated skill directory with the same name or follow internal symlinks when replacing managed files. Updates are copied to a temporary directory before replacing the installed skill. A failed copy leaves the previous installation intact; a failed replacement attempts restoration. If restoration also fails, the error identifies the retained backup. Local extra files are preserved; generated bytecode and `.DS_Store` files are omitted.

Open the installer from a shell:

```bash
herdr plugin action invoke agent-skill-guide --plugin herdr.agent-messenger
```

From the plugin/checkout root, the noninteractive installer accepts `codex`, `claude`, `omp`, or `all` and installs the selected user-scope targets:

```bash
python3 agent_skill_installer.py install omp
python3 agent_skill_installer.py install all
python3 agent_messenger.py skill-path
```

The last command prints the packaged canonical skill path. Project installs are selected in the interactive installer and use the active Herdr workspace root.

## Invoke HAM

- **Codex CLI/IDE:** type `$ham`, then select **HAM — Herdr Agent Messenger** from the skill picker. `$ham` is a search term, not a different canonical skill name.
- **Claude Code:** use `/herdr-agent-messenger`, or ask naturally to use HAM. `$ham` is not a Claude command.
- **omp:** ask naturally to use HAM or read `skill://herdr-agent-messenger` after installing the user/project target above.

For an existing recipient, include its exact host-qualified Agent Labels value:

```text
$ham Ask local/yellow-falcon to review the current change. Wait for the reply
and summarize any required follow-up.
```

For a new session, state creation explicitly:

```text
Use HAM to start a new omp agent in a new tab for this project, send it a
focused code-review assignment, and wait for its response.
```

These are different operations: a missing requested label is reported, never guessed or automatically created. When asked to start/open a session and message it, the agent must use HAM `spawn`, then `request --address` with the returned address. Raw `herdr agent start <name>` bypasses HAM label selection and metadata reporting and is not a substitute.

### Claude Code verification and scope caveats

Verified on winmini with Claude Code **2.1.301** and Herdr **0.9.5** on
2026-10-16 ([issue #5](https://github.com/zerodice0/herdr-agent-messenger/issues/5)):

| Check | Observed result |
| --- | --- |
| User install | `python3 agent_skill_installer.py install claude`; `/herdr-agent-messenger` appeared as `(user)` outside the checkout. |
| Project install | **HAM Skill** → **Project / Claude** copied the complete bundle; the command appeared as `(project)` in that project before user installation. |
| Checkout bridge | With no user copy installed, Claude followed `.claude/skills/herdr-agent-messenger/SKILL.md` and read the canonical `.agents/skills/herdr-agent-messenger/SKILL.md`. |
| Invocation | User, project, and checkout runs executed the bundled CLI's `list --host local` with exit 0. |
| New session | Claude used `spawn --kind omp --placement tab`, then `request --address` with the returned address; the correlated, settled reply was collected without a resend. |
| Natural-language selection | Separate fresh requests mentioning HAM or only a real `local/<label>` address selected the `Skill` tool, both in the checkout before user installation and outside it after installation. |

**Same-name precedence:** this Claude Code version selected the **user** copy
when both user and project/checkout copies existed. Do not assume that the
checkout bridge is being exercised merely because Claude starts in the
checkout. Verify the loaded skill path; test the bridge before installing a
same-named user copy. Restart the client after changing installations.

**Interactive startup:** Claude's folder-trust dialog (and first-run UI
questions) can block a HAM `spawn --kind claude` readiness check. In this
verification, blocked starts returned `agent_start_failed` / `agent_not_ready`
and reported that the created tab was closed. Handle trust interactively in
the intended directory before automated startup; inspect cleanup details
before retrying. Print mode skips the trust dialog, so `claude -p` alone is not
proof that interactive startup works.

**Host authentication observation:** winmini was logged in through `claude.ai`
with a Max subscription. macbook-pro and mac-studio reported `loggedIn: false`
over SSH while their macOS Keychains were unavailable to non-GUI sessions
(`User interaction is not allowed`). That observed host/session condition is
not evidence of a missing skill or a general Claude authentication failure.

## Local mailbox

Use the local mailbox when a message must remain available without submitting a
prompt or waking the recipient. Run from a registered Herdr agent pane:

```bash
HAM_CLI="$PWD/.agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py"
python3 "$HAM_CLI" mail send --to local/blue-owl --kind action --body 'Review the boundary.'
python3 "$HAM_CLI" inbox read
python3 "$HAM_CLI" inbox handle --message MESSAGE_UUID
python3 "$HAM_CLI" mail show --thread THREAD_UUID
```

`mail send` requires `--to` and exactly one of `--body` / `--body-file` (UTF-8,
nonblank, 16 KiB maximum). `--kind fyi|action` defaults to `fyi`; `--subject`
sets a new thread's subject (1024 UTF-8 bytes), and `--reply-to UUID` keeps the
thread, increments hop, and atomically handles an addressed queued/delivered
parent. Both kinds remain queued until explicitly handled or claimed by a
runtime receiver. The local command does not wake a model.

`inbox read` accepts `--message UUID`, `--all`, and `--limit N` (default 100,
1–1000). It never changes state/logs/bells, including when a task agent shares
the calling pane. `inbox handle --message UUID` is repeatable and all-or-nothing;
queued→handled does not invent a native delivered timestamp.
`mail withdraw --message UUID` competes atomically with delivery claim and
returns `withdrawn:false` once claimed/final. `mail show --thread UUID` reads the
thread, and `repo show` reads this agent's repository/settings.

The CLI resolves moved terminals through process ancestry and Herdr's public
`pane process-info` shell PID, without requiring a TTY or inherited terminal
variable. It refuses an unprovable/stale-pane identity. Native session references
determine generations; a display/status revision does not create a new session.
Queued mail can move to a new session in the same repository; other-repository
or shell occupants hold it. Uncertain delivering claims are never auto-replayed.

Git HTTPS/SSH/scp origins normalize to a host/path identity. Preserve a planned
origin rename explicitly with `git config ham.repo-id 'git:host/stable/repo'`.
Default storage is `${XDG_STATE_HOME:-~/.local/state}/herdr-agent-messenger/ledger`;
set `HERDR_AGENT_LEDGER_DIR` for tests and `HERDR_AGENT_CANONICAL_HOST` only when
creating a new ledger. Internal `ledger doctor`, `ledger reconcile`, `ledger
event`, `ledger retention`, `ledger agent-session` and `ledger delivery
claim|started|release` share the Python store. See the
[reference](../.agents/skills/herdr-agent-messenger/reference.md#local-mailbox)
for their JSON contracts and recovery/evidence requirements. The local mailbox
does not change legacy prompt routing, Held Messages, or install any runtime.

### Remote mail and code-only worker

Register stable host identities and both SSH directions before using remote mail:

```bash
# On alpha (on beta use --name beta and alpha's configured SSH alias):
python3 "$HAM_CLI" ledger setup --name alpha
python3 "$HAM_CLI" ledger peer add --ssh-alias beta-ssh --canonical-name beta
python3 "$HAM_CLI" ledger peer list
python3 "$HAM_CLI" mail send --to beta-ssh/blue-owl --body 'Inspect when ready.'
python3 "$HAM_CLI" ledger doctor
python3 "$HAM_CLI" ledger outbox
python3 "$HAM_CLI" ledger worker status
# Explicit retry after fixing a permanent error; retains the message/item IDs:
python3 "$HAM_CLI" ledger retry --item OUTBOX_ITEM_UUID
```

Only existing allowlisted concrete SSH aliases are accepted. Discovery uses
structured `result.plugins[0].plugin_root`, then checks protocol 1 and the
canonical UUID; do not run a new protocol against an old installed checkout.
Canonical host names and SSH aliases both address the same registered peer.
Remote status is queried live, not copied into local AGENTS.

The detached worker holds a per-ledger flock, retries transient failures FIFO
per peer (up to five-minute backoff), sends receipts, sweeps closed terminals
and expires bodies/logs. It survives the launching CLI and exits when no work
remains. A failed item is visible and does not block later items; another
offline peer cannot block independent destinations. Repeated/lost-ACK accepts
use the same immutable message ID and return current state, including permanent
dedupe after body retention. A bell failure after commit is a successful store
with a `notification_failed`, `committed:true` warning, not permission to resend.

`--to main` is a symbolic address resolved once by the repository home on
acceptance. An offline home leaves pending mail; an online home without a main
returns a visible `main_unavailable` item for explicit retry. Resolved receipts
and withdrawals follow the saved route, including a main on a third host.
Mode/main/member/threshold mutations are reserved for the user UI service, not
agent CLI. Each setting has its own version/origin; conflicting ties and pending
propagation appear in `repo show`. Local auto bootstrap never waits for all
peers. A stale close or former-home computed publication cannot overwrite a
newer designation/home.

Isolated verification can pin `peer add --remote-root /ABS/WORK_COPY
--remote-ledger-dir /ABS/PRIVATE/ledger --remote-socket /SHORT/PRIVATE.sock`.
Use private local ledger/socket/HOME/XDG/request directories as well.
`HERDR_AGENT_LEDGER_AUTOSTART=0` disables implicit workers (also for explicit
remote-ledger overrides); `ledger worker once|run|ensure` remains explicit.
See the [wire/setup reference](../.agents/skills/herdr-agent-messenger/reference.md#hosts-fifo-transport-and-worker)
for exact JSON, error and isolation contracts. No runtime/global settings are
installed by these commands.


## CLI commands and addressing

The bundled skill is split into a short [SKILL.md](../.agents/skills/herdr-agent-messenger/SKILL.md) for common workflows and an on-demand [reference.md](../.agents/skills/herdr-agent-messenger/reference.md#command-and-flag-reference) with complete flag/default/unit/range tables for all eight commands: `list`, `status`, `send`, `batch`, `read`, `request`, `request-status`, and `spawn`. Every command supports `-h` / `--help`.

The following examples run **from the plugin/checkout root**; for another working directory use the absolute path to the bundled script. An installed skill also has `scripts/herdr_agent_messenger.py` relative to its own directory.

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py list --host local
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py list --host macbook-pro
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py status \
  --address macbook-pro/purple-koala --verbose
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py request \
  --address macbook-pro/purple-koala --message 'Inspect the change and report blockers.' \
  --timeout 120000 --output-lines 160 --output-chars 16000
```

Copy `list` → `address` → `--address` directly; it works for `status`, `send`, `read`, and `request`, and as a batch item's `address`. Alternatively use `--host HOST --label LABEL`, or a returned opaque `--route TOKEN` (exactly one selector). `--host` defaults to `local`; a non-default host disagreeing with `--address` produces `conflicting_address`.

Only literal `local` selects the current Herdr server. Every other host must be a concrete configured SSH alias—even a hostname matching this machine still means SSH. Never use a bare label as a global address: labels can repeat across hosts and be mistaken for a client's own subagent names. Every operation resolves the current occupant again; a label does not promise continuity after restart.

All eight commands return compact output by default; `--verbose` restores full diagnostic payloads. `list` returns each agent's `address`, `status`, and `workspace`; `status` returns `address` and `status` (plus `stale: true` when needed). Compact request results omit routes and agent/baseline metadata, and expose cleaned reply text as `response.text`. TUI borders, status footers, and echoed prompts are removed. Use `--verbose` for raw/full response fields such as `response.output`. The `list --legacy` alias still selects verbose output.

| Flag | Commands | Default and meaning |
| --- | --- | --- |
| `--verbose` | All eight commands | Off; show full payloads instead of compact views. |
| `--defer-timeout MS` | `request`, `send`, `batch` | `180000` milliseconds (3 minutes); time to hold a focused recipient before requiring a decision. This is separate from the command's `--timeout` wait budget. |
| `--wait MS` | `request-status` | `0` (one observation); otherwise stops on a state, phase or `error_code` change, a terminal state, or the deadline, not response-text growth. This numeric option differs from the boolean `--wait` on `send` and `batch`. |

### Start a new labeled session

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py spawn \
  --kind omp --cwd /path/to/project --placement tab
# Use the address returned above, not an invented color-animal name:
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py request \
  --address RETURNED_HOST/RETURNED_LABEL --message 'Review the project and report blockers.'
```

The default placement is a right split from local `HERDR_PANE_ID`. For an SSH split, provide `--from-pane` and `--cwd` explicitly. Local cwd defaults to the invocation directory; SSH cwd is always required and refers to a path on that host. `--placement tab` can use `--workspace`; absent that, HAM infers the source workspace from `--from-pane` or local `HERDR_PANE_ID` when available, otherwise leaves the choice to Herdr. `--placement workspace` creates a separate workspace. New placements are not focused automatically.

`--label` chooses an explicit nonblank name without `/`; otherwise HAM picks a free `color-animal` label. `--workspace-label` controls a new tab/workspace label; its default is the explicit or generated agent label. `--direction right|down` only affects splits. `--timeout` is readiness time in milliseconds (default 90000, range 1–300000), not time to answer the future prompt. Agent-specific flags must follow `--`:

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py spawn \
  --kind codex --host macbook-pro --cwd /path/on/mac/project \
  --placement workspace --workspace-label Review -- --model MODEL
```

Compact spawn results contain `address`, palette `marker`, `created` (`pane`/`tab`/`workspace`), `pane_id`, `workspace_id`, and `tab_id` when available. Reporting flags `label_metadata_reported` / `placement_label_reported` appear only when false. Use `--verbose` for label/color, host, kind, cwd, route, agent metadata, and both reporting flags. A custom nonpalette name has an empty marker and no palette metadata. A successful session need not have successful optional metadata reporting; inspect false flags. Startup failure includes cleanup information; inspect for surviving resources before trying again.

### GUI routes

The popup's coordinator prompt supplies an absolute CLI path and host-qualified addresses, so it works even without a globally installed skill. For GUI selections supplied as opaque route tokens, follow the supplied `--route` commands directly; do not decode or modify tokens or replace them with guessed Herdr commands. Compact results use addresses rather than exposing routes; `--verbose` includes routes for diagnostic/GUI-style routing. If `route_refreshed: true`, retain the returned token. Refresh is allowed only when conservative continuity checks identify one safe current occupant; otherwise report `route_expired`. See [route safety](ssh-and-routing.md#route-safety).

## Request lifecycle and exit codes

Prefer `request` for ordinary messaging. Run it from the coordinator's active Herdr agent pane so the sender can be verified. Once delivery is allowed, HAM captures a baseline, submits once without Herdr's ambiguous lower-level `--wait`, observes a fresh requested working→settled cycle, and returns bounded new output. If the recipient was already working, its first settlement is only an old-turn boundary; HAM requires a second working→settled cycle.

### Focus-based delivery holds

Agent-initiated CLI `request`, `send`, and `batch` deliveries are held when the recipient pane is focused in Herdr. Self-send fails immediately with `recipient_is_sender` before any focus check, even when the sender pane is focused; it is never held. HAM cannot inspect the input box: focus is a safeguard, not typing detection. The request is `deferred`, with `submitted: false`, until focus leaves before the defer deadline. A background worker then delivers it, even if the original CLI wait has ended. A held `send` returns immediately with a `request_id` and exit 3, regardless of `--wait`.

If the pane stays focused for `--defer-timeout` (default `180000` milliseconds, or 3 minutes), the request becomes `awaiting_decision` and HAM sends a Herdr notification. Open **HAM: Held Messages** from the command palette, select a request with Up/Down, and choose **Push** (`p`) or **Cancel** (`c`); `q` or Esc closes the popup. Push can combine the message with unsent text in that pane. Cancel ends the request as `submission_failed`, with phase and `error_code` `delivery_cancelled` and `submitted: false`. **After the timeout, held messages never auto-push, even when focus later leaves.** You must choose Push or Cancel.

After deferred delivery or Push, the worker observes the submitted request about every 0.5 seconds until it becomes terminal or 30 minutes have passed since submission. Use `request-status` to read the saved result; after that limit, the command can still advance observation. The worker exits only when no deferred, awaiting-decision, or watched requests remain.

HAM popup direct sends and coordinator delegation are user-initiated and are never held. Known limitation: typing a draft and then switching panes without submitting can still merge that draft with an incoming message.

For SSH recipients, HAM checks focus on the recipient's host. The hold queue, worker, and **HAM: Held Messages** live on the **sender host**. Timeout notifications are sent to both hosts; the recipient-side notification names the sender host so you know where to decide. If the recipient disappears or is replaced before delivery, HAM fails the undelivered request rather than sending to the replacement.

### States and follow-up

| State | Meaning |
| --- | --- |
| `submission_failed` | Resolution failed, or prompt rejected/cancelled before submission; terminal. |
| `deferred` | Recipient pane is focused; phase `deferred_recipient_focused`, nonterminal, `submitted: false`. HAM owns delivery; do not resend. |
| `awaiting_decision` | Hold deadline passed; phase `awaiting_decision`, nonterminal, `submitted: false`. Choose Push or Cancel on the sender host. |
| `submitted_working` | Submitted/possibly submitted, recipient working; completion not proven. |
| `submitted_settled` | Fresh requested cycle observed; terminal. |
| `submitted_unknown` | Matching requested turn cannot be confirmed; usually nonterminal, but occupant change makes it terminal. |

| Exit | Meaning and next action |
| --- | --- |
| `0` | Settled request; all batch items `succeeded`; or successful other-command payload. Review output before trusting claims. Lower-level send success is not lifecycle settlement. |
| `1` | JSON error envelope, `submission_failed`, or batch containing `failed`/`cancelled`/`timeout`. Inspect delivery evidence before retrying; this does not always mean nothing was sent. |
| `2` | Argument usage error on stderr. Correct syntax. |
| `3` | **HAM still owns the request; do not resend.** Request/send is `submitted_working`, `submitted_unknown`, `deferred`, or `awaiting_decision`, or a batch has `submitted`/`deferred` items and no failures. Advance IDs with `request-status`; held requests may require a decision. For no-wait items without IDs, inspect `status`/`read`. |

Compact lifecycle payloads have `request_id`, `state`, `terminal`, `submitted`, `phase`, and `address`, with optional `error_code`, `error`, `defer`, and `response`. Null/absent optional fields are omitted. Held records expose `defer.reason: recipient_focused` and `defer.deadline`. `--verbose` includes full metadata and response fields. Preflight failures instead return `{"error":{"code":"...","message":"..."}}` without `request_id`. Neither all successful CLI payloads nor every batch item has a request ID.

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py request-status \
  --request-id REQUEST_ID --wait 30000
```

Without `--wait`, this command advances one saved nonterminal request with a fresh observation. With `--wait MS`, it stops on a state, phase or `error_code` change, a terminal state, or the deadline, not response-text growth; it never creates a duplicate submission. Refreshing a held request may deliver the saved message once focus leaves before its hold deadline. Changed-only reporting is separate: compact output includes `changed: true` when a state, phase, error code, or response-text change is reported; unchanged output is only `request_id`, `state`, `terminal`, `submitted`, and `changed: false`. `--verbose` always prints the full payload.

Preserve the ID on the same sender host/state location. The shared queue uses `HERDR_AGENT_REQUEST_STATE_DIR` when set, otherwise `${XDG_STATE_HOME:-$HOME/.local/state}/herdr-agent-messenger/requests`; the legacy `herdr-agent-labels/requests` directory is used only if the new directory does not exist. `HERDR_PLUGIN_STATE_DIR` is not used. `request-status` cannot reconstruct a complete working→settled cycle missed between observations. If `phase: recipient_changed` after submission, HAM stops capture and keeps the original route rather than attaching replacement-agent output. This is terminal `submitted_unknown` with `error_code: recipient_changed`; report the uncertainty instead of repeatedly polling or resending. Before submission, a lost/replaced held recipient instead becomes `submission_failed`.

Inspect response fields independently:

- `response.truncated`: true only when reply text itself was cut by output bounds or a failed read, in compact and verbose results. Omitting older history or losing baseline overlap alone does not set it. False does not prove correlation or a reliable complete transcript.
- `response.correlated`: fresh requested cycle observed with reliable baseline and read; false means this is not a proven completed answer for the request.
- Optional `response.anchored: true`: when baseline overlap could not be recovered, capture began at the last matching sender prompt header (`Message from HOST/LABEL:`). This removes preceding startup/history text but is not proof of completion, completeness, or unique correlation among multiple prompts from that sender.

Replies are scraped from the recipient's TUI, not a structured assistant-message API. Narrow panes hard-wrap lines; prefer a tab or workspace placement for long replies. Anchoring does not repair hard wraps.

## Batch coordination

First list and verify each requested host/label. Decompose work into non-overlapping assignments and send only the context each worker needs unless the user explicitly requests direct broadcast. HAM mechanically dispatches the already-tailored messages; it does not interpret, split, or rewrite them.

```bash
python3 .agents/skills/herdr-agent-messenger/scripts/herdr_agent_messenger.py batch \
  --requests-json '[{"address":"local/yellow-falcon","message":"Review API behavior."},{"route":"ROUTE_TOKEN","message":"Review the UI."}]' \
  --wait --timeout 120000 --max-workers 4
```

`--requests-json -` reads stdin; a `{"requests":[...]}` wrapper is also accepted. Supply a nonempty array with exactly one of `address` / `route` and a nonblank string `message` per item. Duplicate resolved targets fail as `duplicate_route`, even if one uses an address and another a route. Results remain in input order. The concurrency limit is 1–8, default 4; timeout is per request, positive milliseconds, default 120000. `--wait` is the default and uses lifecycles; `--no-wait` returns on acceptance without capturing a settled answer.

| Per-item status | Meaning |
| --- | --- |
| `succeeded` | Matching request settled in wait mode. |
| `submitted` | Acceptance confirmed but settlement not verified; never resend. |
| `deferred` | Focus hold or user decision pending; HAM owns delivery. Use the request ID and never resend. |
| `failed` | Invalid item, target resolution failure, or submission rejection. |
| `timeout` | Acceptance unconfirmed or dispatch timed out; possibly delivered. |
| `cancelled` | Dispatch/submission cancelled; inspect acceptance evidence. |

Aggregate `succeeded` means all items were accepted or retained by HAM (`succeeded`, `submitted`, or `deferred`), not necessarily delivered or settled. `partial` means only some reached those statuses; `failed` means none did. The process exit code also checks per-item completion/failure; a batch with `submitted` or `deferred` items and no failures exits 3. Held items have lifecycle IDs even in no-wait mode; preflight failures and immediate no-wait sends may not. Compact items use `address`, `status`, and optional `request_id`, `state`, `error_code`, `error`, and `response` (`text`, `truncated`). Use `--verbose` for full item details and `request-status` for the full lifecycle response, including anchoring metadata.

Wait for every requested worker or clear terminal failure. Review responses against the workspace, follow up on inconsistencies, and synthesize unavailable hosts, unverified claims, uncertainty, and remaining risks. Retry only known-undelivered failed items, never the whole mixed-result batch.

## Error recovery reference

The [complete error code catalog](../.agents/skills/herdr-agent-messenger/reference.md#error-code-catalog-and-retry-policy) lists every category and code. Recovery depends on delivery evidence, not merely exit 1:

| Error codes / category | Recovery / retryability |
| --- | --- |
| `invalid_address`, `conflicting_address`, `invalid_defer_timeout`, other `invalid_*` input codes, `empty_message`, `empty_batch`, `missing_address`, `duplicate_route` | Fix rejected input; `--defer-timeout` requires positive integer milliseconds. Retry only the undelivered operation/items. Never invent IDs or routes. |
| `agent_not_found`, `agent_ambiguous`, `invalid_route`, `route_expired`, `route_ambiguous`, `resolve_failed`, `recipient_is_sender` | Relist/reselect rather than guess. A post-submission resolution error means resume observation, not resubmit. Create only when asked. |
| `host_not_configured`, `host_unavailable` | Restore authorized SSH/Herdr connectivity. Local sandbox/socket denial requires socket access; failed discovery does not mean missing agent. |
| `sender_unavailable`, `sender_probe_failed` | Use the current Herdr agent pane. Probe failure is before submission; obtain local-socket access for sandbox/socket errors, then retry that exact undelivered request only. |
| `prompt_failed` | Submission rejected; fix cause before retrying known-undelivered work. |
| `prompt_acceptance_unknown`, `prompt_timeout`, `wait_timed_out`, `timeout` | Possibly delivered / completion unknown. Preserve ID and use `request-status`, or inspect recipient if no ID. Never blindly resend. |
| `prompt_cancelled`, `cancelled` | Before submission: may retry; after submission: cancellation only stops waiting, not recipient work. Inspect `submitted`. |
| `delivery_cancelled` | User cancelled a held message before submission. Terminal `submission_failed`, `submitted: false`; respect the cancellation rather than automatically resending. |
| `recipient_changed` | Occupant changed. Before submission, a held request fails undelivered; after submission, the result is terminal uncertainty. Do not scrape replacement output or resend the old request. |
| `request_not_found`, `request_state_invalid`, `request_state_unavailable` | Check ID/state location/permissions; storage failure can follow submission, so inspect recipient before retrying delivery. |
| `cwd_required`, `sender_pane_unavailable`, `label_unavailable` | Fix spawn cwd/source pane/label availability before retrying. |
| `placement_failed`, `agent_start_failed` | Inspect cleanup details and possible surviving session/resource before retrying startup. |
| `cli_not_found`, `internal_error`, `dispatch_failed`, `invalid_sender_result`, defensive `invalid_command` | Repair installation or investigate; unexpected failure is not evidence of non-delivery. |

Local socket access is needed even for a remote request because HAM verifies the sender locally. For a batch `sender_probe_failed`, retry only those failed items after granting access; never replay delivered, submitted, unknown, or timed-out items. Do not bypass SSH host-key verification or alter trust settings to make a request succeed.

## Lower-level send and read

`send` defaults to `--wait` and Herdr's completion signal, unless the recipient is focused: then it returns a deferred lifecycle record immediately, even with `--no-wait`, and HAM owns later delivery. An immediate send returns compact `sent`, `address`, and `waited`, plus nonempty `warnings`; `--verbose` restores full details. A recipient already working produces `recipient_already_working` and, in verbose output, `wait_can_track_submitted_turn: false`; its completion signal may belong to old work. Prefer lifecycle `request`. An immediate `send --no-wait` only confirms acceptance and provides no lifecycle request ID. SSH loss/process interruption after acceptance can produce `prompt_acceptance_unknown`; inspect the recipient before retrying.

`read` defaults to 120 recent lines / 65536 UTF-8 bytes and accepts positive `--lines` / `--max-bytes` limits plus a prior `--cursor` (`--watermark` alias). Compact output contains `address`, cleaned `output`, `delta`, `truncated`, and an opaque new `cursor`; `--verbose` also exposes raw output, `cursor_status`, and routing metadata. Reuse the cursor to suppress unchanged output. Terminal screens may be rewritten, not append-only logs: an unsafe/expired cursor returns a bounded fresh snapshot (`delta: false`), and a malformed cursor produces `invalid_cursor`. Do not infer progress from line numbers or claim full output when `truncated` is true.

## Use HAM without the plugin

HAM can run with Herdr without installing/enabling the plugin. Keep a persistent checkout: the skill wrapper loads router modules from it. Copying only the skill directory is not a self-contained installation.

```bash
git clone https://github.com/zerodice0/herdr-agent-messenger.git \
  "$HOME/.local/share/ham"
mkdir -p "$HOME/.agents/skills" "$HOME/.claude/skills" "$HOME/.omp/agent/skills"
ln -s "$HOME/.local/share/ham/.agents/skills/herdr-agent-messenger" \
  "$HOME/.agents/skills/herdr-agent-messenger"
ln -s "$HOME/.local/share/ham/.claude/skills/herdr-agent-messenger" \
  "$HOME/.claude/skills/herdr-agent-messenger"
ln -s "$HOME/.local/share/ham/.agents/skills/herdr-agent-messenger" \
  "$HOME/.omp/agent/skills/herdr-agent-messenger"
```

Use a free destination for each symlink; do not overwrite an existing skill.
The symlinks let the wrapper resolve the source checkout without a registered
plugin. Copied user-scope installs instead rely on the registered plugin root.
Update the source-backed installation with:

```bash
git -C "$HOME/.local/share/ham" pull --ff-only
```

Plugin-free HAM retains address/label request, wait, read, batch, and `spawn` routing; `spawn` chooses and registers its new session's label. It does not supply the popup, command-palette installer, automatic labeling of unrelated detected agents, or the agent-detected hook. Existing unnamed agents may be assigned unique names explicitly:

```bash
herdr api snapshot
herdr agent rename <pane-id> yellow-falcon
```

Herdr must be installed and running locally and on every selected SSH host. Remote hosts must be concrete aliases in configured SSH config (normally `~/.ssh/config`).
